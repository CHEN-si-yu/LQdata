## 1. 为什么要这张表：把「有没有用」拆成两半

一个因子"没用"有两种完全不同的原因，而它们由**不同的会话**负责：

| 半边 | 问题形态 | 谁负责 | 证据形态 |
|:--|:--|:--|:--|
| **PIT / 覆盖** | 值算错了、用到了当时拿不到的信息、某段历史整块空、覆盖率随时间断崖 | **因子会话** | 截断复算、覆盖台账、`audit-pit` 报告 |
| **经济增量** | 值算得对，但对**含费净收益**没有增量（IC 升、钱不升也算没有） | **模型会话** | 多种子配对的最差情形，不是单点峰值 |

**"因子有没有用"不是因子会话能单独回答的问题**，但"这个因子在含费口径下有没有增量"
也不是因子会话该背的锅。所以：

- 进入本表的需求**必须写明收益假设**（它该在什么机制上赚钱）；
- 因子侧只承诺 **PIT 正确 + 覆盖达标**，不承诺收益；
- **晋级（纳入 `trainingdata`）由模型会话决定**，且必须走多种子配对。

## 2. 提需求：照抄这个模板

```markdown
### REQ-<YYYYMMDD>-<序号> · <一句话标题>
- 提出方：            <会话名>
- 上游依赖：          <datadownload/data/ 下的数据集名>
- 输入 / 公式：        <具体到可以照着实现；含窗口、复权口径、缺失处理>
- 可用时点：          <T 日收盘后可得 / T+1 / 需要 delay；说明与现有 delay 表的关系>
- 收益假设（机制）：    <为什么它应该有增量；写不出机制就不要提>
- 覆盖要求：          <预计起点、预计日均截面只数、是否全池>
- 需求紧迫度：        P0 / P1 / P2
- 状态：              open / in-progress / delivered / rejected
- 交付证据：          <因子会话回填：产物路径 + 覆盖体检 + 局限>
```

**硬要求**（缺一条会被退回）：

1. **不许提"再试一个参数"** —— 平台已系统性做过参数扫描，没有机制的方向不接。
2. **不许提平台拿不到的数据** —— 只能用 `datadownload/data/` 里已落地的表
   （清单见 `datadownload/README.md` 的"已删除 / 从未下载"表；**指数成分、概念板块、
   大宗交易都没有可用历史**，提了也是死路）。
3. **不许要求改既有因子的历史分区** —— 新增因子用新名字；既有因子一旦重算，
   下游所有结论作废（`QUANT_PLATFORM.md` §3.3 第 4 条）。
4. **涉及 delay>0 的表必须在"可用时点"里说明** —— 因子侧会在 `spec` 注册时用
   `lagged_ok` 卡住它；说不清就别提。

## 3. 因子侧回执：交付时同时给三样

1. **产物路径**：`data/factors/<名字>/year=YYYY/data.parquet`（4 列契约）；
2. **覆盖体检**：起点、逐年日均截面、结构性稀疏（哪些年份/哪些行业整块空）；
3. **局限声明**：已知的 PIT 近似、口径断点、与既有列的秩相关（若有）。

★ 交付**不等于**模型侧会纳入。模型侧纳入时自行决定时机，
并遵守 `AGENTS.md` 的「**不要在训练中途改变输入**」—— 换快照要等训练停。

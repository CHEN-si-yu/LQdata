# 因子工程维护约定

适用本目录及子目录。当前授权为 2026-09-24 的全因子审核、修复、历史重建及 30 个市场因子接入；替代旧版“仅开发新因子、禁止重算现有因子”的本次工作限制。后续任务按用户当次授权执行。

## 边界

- `/root/autodl-fs` 与 `/autodl-fs/data` 指向同一共享盘；不同端口不是独立文件副本。
- 可维护本项目脚本和文档；原始上游数据只读。不改模型工程、训练快照、上游工程脚本、共享环境。
- **本单元自成一体**：只运行入口 `python main.py`，只读上游 `../datadownload/data`，**全部产物写在项目目录内**（`data/`、`state/`、`logs/`、`artifacts/`）。不读、不写、不依赖 `CodeX` 或任何项目外的位置 —— 包括缓存、日志、运行账本、因子字典、审计输出。新增路径一律先加到 `conf/config.yaml` 的 `paths:` 或用 `cfg.root` 拼接，禁止 `cfg.root.parent`。
- 项目内目录约定：`data/derived/` 派生层预聚合缓存、`state/runs/` 运行账本、`state/input_hashes/` 上游输入身份缓存、`artifacts/{catalog,checks,pit,dayhash,audits}/` 产物与审计。
- 上游运行期间不启动生产因子写入；因子写入持有共享文件锁。不得终止其他任务。
- 单次因子任务总内存小于 90 GB。默认串行；`--jobs` 上限由 `FEA_MAX_JOBS` 控制（默认 2）。提高并行度前先用 `scripts/mem_trace.py` 实测内存峰值。多年份分开进程，避免长期累积缓存。

## 数据契约

现行范围、输出与操作见 [README.md](README.md)。固定池 2115 只，输出下界 2018-01-01。不得为了让台账一致而修改股票池、清洗源数据或用未来值填补缺失。

股票因子返回 `(T,C)` 数组，市场因子返回 `(T,)` 数组。统一使用 FactorSpec、Context、Engine、Store；市场因子声明 `is_market=True` 并保存到独立市场目录。不把市场值复制成股票行。

- **★ 时间轴必须对齐（硬约定）**：每个因子的年分区都从 `default_start`（2018-01-01）起，
  一年不缺 —— 下游按因子拼 `[T,C]` 矩阵时列必须是齐的。`FactorSpec.start` 只表示
  「从哪天起有**真实值**」，其前的年份是对齐区间，值由 `align_fill` 决定
  （`nan`=上游没有这段数据／`0.0`=上游以 0 表达未披露／`None`=关掉对齐）。
  对齐区间的 **rank 恒 NaN**。
  ⚠️ **优先放开起点真算，不要轻易填 0**：填 0 会断言不存在的观测。判据必须是**实测**
  （读上游那一年那一列的精确 0 占比），不能靠注释或推断 —— 2026-09-25 实测发现
  `fin_exp_int_exp`/`rd_exp`/`fin_exp_int_inc` 在 2018 年分别有 44%/49%/50% 真实值，
  原先按注释「早年恒为 0」截断是错的。
  ⚠️ **每引入一个新契约字段，要把「会删/会改/会重建数据」的旁路工具全部过一遍**
  —— `fea/history.py`（裁剪）、`scripts/rebuild_manifest.py`（台账重建）就因此各出过一个缺陷。
- 声明全部直接输入和父因子依赖；引擎拒绝写入读取了未声明依赖的结果，父因子先完成再读。公式、单位、有效分母、缺失、交易状态和可用时点应写清。
- 日线收益使用当时累计复权因子；停牌不得伪造成成交。标签明确未来窗口及成熟条件。
- 财报按公告可得日对齐，采用当时已知版本；TTM/单季/同比必须按报告期计算。禁止全样本标准化、负位移、向后填充进入普通因子。
- 滞后源使用统一可得日延迟；缓存必须纳入输入内容和股票池身份。实际返回值应与声明公式一致。
- warmup_days 是日历天；嵌套窗口按最长完整依赖链计算。计算锚点固定到输出年，禁止用本次增量起点改变递推初始化。
- 改变数值逻辑须提升版本或公共逻辑指纹，重建受影响历史。修订父因子时修复全部受影响后续日期。
- **数值环境也是输入**：入口钉死共享解释器，环境指纹（numpy 版本 + 固定算例位模式哈希）拼进 `recipe`；换环境会强制全量重建。数学一律在 float64 上做，只在落盘处压 float32；**禁止把 float32 数组/Series 送进超越函数**（`arcsinh`/`log`/`log1p`/`exp`/`expm1`/`power`/三角/`arctanh` —— numpy 的 float32 SIMD 核与正确舍入有 24.76% 的输入不一致，float64 下与 libm 逐位相同）。见 README「数值环境与可复现性」。

## 验证

使用 `/autodl-fs/data/miniconda3/bin/python`。测试入口 `scripts/run_tests.py`。数值可复现性回归见 `tests/test_numeric_reproducibility.py`；审计工具 `scripts/mem_trace.py`（内存采样）、`scripts/env_invariance_test.py`（环境不变性）；审计工作区写 `artifacts/audits/<日期>/`。

交付至少检查：全部注册对象可运行；年度日期/股票轴完整且主键唯一；市场每天一行；状态行数及逻辑指纹与文件相符；没有无穷值；有效值起点和覆盖率有记录；同输入全量与增量逐日 MD5 一致。删除重建测试先备份，恢复后核对 value/rank、行数、覆盖范围及历史非测试区间；运行时间和文件修改时间可变化。

动态因果抽查应截断可用输入并与生产值比对。不要把静态扫描、格式检查、哈希一致当作收益有效性或完整历史可得性证明。

## 审核执行顺序与停止条件

技术路线、真实案例和复用技巧统一维护在 README 的“审核方法与本次经验”，不另建项目 Markdown。

- 先确认上游已完成及验收截止日，再固定输入、备份和股票池；任何因子结论都要有明确的有效日期范围。
- 先复现边界和批次/窗口独立性，再重建受影响历史；修改公共数值逻辑后，旧的相关通过结论不能直接沿用。
- 真实数值、依赖声明、因果可得性、全量/增量一致性、缺口恢复分别验收。全空相等、仅格式正确、仅退出码为零，都不等于数值通过。
- 对账同时保留修复前后的变化说明与同源重复更新证据。破坏测试必须备份、实际删除、恢复、核对全历史及语义台账，不能覆盖原始基线来隐藏失败。
- 日常入口、数据与语义台账一致，必要检查全部通过，下一次计划合理后结束工作。已有有效证据应复用；用户要求收尾时不再探索无关问题。

更新时间：2026-09-21。依据用户本次明确分工，适用于本目录及子目录。

## 工作边界

- **因子开发会话**：通过 `connect.westc.seetacloud.com:56292` 连接容器，负责 `featureengineering/` 内的新因子、因子测试、因子产物及对应文档；只读 `datadownload/data/`。
- **模型与策略会话**：`codex://threads/01a0c1f7-4e1d-7e52-b5e9-deda2583e211`，负责 `model/` 内的模型开发、交易策略与收益稳定性研究。请不要并行修改本目录的因子实现、注册、配置或重算现有因子。
- 需要新因子或发现因子问题时，请写入本目录 `FACTOR_REQUESTS.md`，描述输入、公式、可用时点与使用需求，由因子会话实现；模型侧可读取已交付的因子 parquet，但不要跨工程 import 因子代码。
- 因子会话不修改 `model/`、模型训练快照、上游下载数据、全局 Python 环境或共享配置；不启动模型训练及策略回测。

## 共享存储与数据纪律

- `/root/autodl-fs` 指向 `/autodl-fs/data`；不同容器访问的是相同文件，SSH 端口不同并不隔离这些文件。
- 新增因子使用独立名称；开发与验证使用本工程独立的 artifacts 子目录。既有因子的历史分区和状态不因新增开发而重算或覆盖。
- 新因子交付清单、可用日期、局限与检查结果记录在本目录开发报告中。模型侧是否纳入新因子、何时更新训练快照由模型会话决定，避免在训练中途改变输入。
- 不主动运行全库 `main.py run`、跨因子相关性/IC 分析或清理他人的产物。重计算采用受限线程，遵守平台资源纪律。

## 开发框架

先读 `README.md` 的现行约定、因子开发契约、运维手册，以及上一级 `QUANT_PLATFORM.md`。
沿用 `FactorSpec` 注册、`Context` 数据读取、引擎增量/断点续跑及统一 Store 输出，不另造生产流程。
使用 `/autodl-fs/data/miniconda3/bin/python`；代码与说明使用中文，显式处理可用时点、缺失值、停牌与除权。

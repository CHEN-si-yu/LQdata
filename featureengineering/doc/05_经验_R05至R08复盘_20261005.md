## 一、本轮结果与复盘的主要结论

R5–R8 共实际启动 22 个冻结候选，包含 19 个股票因子、3 个市场因子。**1 项通过并完成正式发布，21 项淘汰退休，没有待审候选。** 通过项为 R7 E 收益醒目性，准入依据限定在 5 日收益期限。R8 E 营运资本现金实现噪声完成完整样本与全部既定补充控制后未通过增量门，按冻结条件顺序结束审核。

正式库从 124 股票＋47 市场＋5 标签，变为 **125 股票＋47 市场＋5 标签**。新增因子的 2018–2026 九年数据与研究完整封存结果精确一致；原有 176 个对象的定义、元数据和分区哈希保持一致。最终发布 ID：`5e820717a51eaa9b43fb3dc7a771cc3d0147f4729b266831f9a03483373b4c86`，截止 2026-09-30。

约 4.32 小时的完整留存监督窗口内，32 核 cgroup 平均 CPU 利用率 **12.72%**，没有达到用户希望的 50%；观察到的计费内存峰值 **43.18GB**，OOM/OOM-kill 为 0/0。264 个中央任务均完成，队列清空，监督器及本次工作进程退出。任务数包含计算、控制生成、审核、验证和发布，**不等于 264 个因子，也不等于 264 次独立假设检验**。

最值得保留的研究判断是：经济机制、数据代理、原始方向信号、相对现库的独立增量以及可交易利润，必须分别成立、分别表述。本轮保住了评审纪律和证据链；资源利用率、长任务编排效率以及交接文档的及时整合仍有明显改进空间。入库少本身不是应该放宽门槛的理由，也不能被包装成研究效率已经很高。

## 三、接手、派单和主裁判职责

### 1. 接手时先恢复事实

接手者先核对工程说明、`doc/AGENTS.md`、最近交付、当前发布指针、生产批准集合和仍在途任务，再决定下一步。必须分清“文档草稿说 pending”“真实任务仍运行”“任务已成功封存但尚未评审”三种情况。

模型切换或上下文压缩后，至少恢复：项目根和解释器、授权范围与停止要求、当前 release/registry 身份、候选及源码哈希、实际 run/evaluate/verify ID、排队与运行任务、监督器身份、资源阈值、已完成工作及下一项必要动作。连接信息按安全方式接续，交接单只写连接用途，不写凭据。

已有成功封存的结果先核对身份后复用；已有进程先识别归属和状态，不能再启动一份同名任务。只有 `begin.json` 或目录存在时，不能将其视为完成，也不能盲目删除目录后重跑。

### 2. 主裁判与执行者分工

| 角色 | 责任 | 必须守住的边界 |
|---|---|---|
| 主裁判 | 研究方向、差异性判断、设计冻结、公共评估口径、资源分配、独立复算、最终裁决、生产发布 | 不能只转述子 Agent 的显著性数字；不能把通过工程测试等同于有效信号。 |
| 因子执行者 | 源字段核对、机制与公式、候选实现、针对性边界检查、固定实验、事实交接 | 不自行反号、增变体、改公共内核、绕过中央队列或自行准入生产。 |
| 评估/工程支持 | 复用冻结统计内核，构造所需控制与审计适配器，绑定实际源和输出 | 不能借工具改写样本、放宽门槛、删除不利控制列，或把年度来源重标为完整来源。 |

派单要写清：唯一任务编号、机制、股票/市场类型、允许写入的文件、共享只读文件、冻结定义与版本、控制和评估范围、交付位置、资源申请、依赖任务、完成条件。每项任务有一个明确负责者，避免多个 Agent 同时覆盖同一文件。

Agent 数量、服务器计算进程数、数值库线程数是三层不同的并发。增加执行 Agent 不会自动提升服务器利用率；执行 Agent 也不能私自开多层进程池。服务器重计算统一排队，主裁判集中掌握全局预算。

## 四、从研究方向到正式发布的标准流程

| 阶段 | 核心动作 | 进入下一阶段的依据 |
|---|---|---|
| 0. 恢复工位 | 读合同、现库、清理记录、实际任务与资源 | 边界明确，无重复任务，状态可追溯。 |
| 1. 源与近邻预查 | 查字段含义、历史覆盖、公告可得性、重复机制和代数关系 | 能说明“测量什么、何时知道、与谁不同”；不成立则 HOLD。 |
| 2. 事前冻结 | 固定 Idea→Family→Candidate、唯一主表达、方向、窗口、试验预算和对照 | 冻结定义及引用身份落盘，收益未被用于挑选定义。 |
| 3. 实现与小样本资源测量 | 接入 Context/Engine/Store，检查关键边界；测实际时间和峰值 | 主要数学与时点逻辑正确，资源预约有依据。 |
| 4. 年度预筛 | 对完整固定年度轴做质量、G4 和 base8 双口径增量检验 | 同一主期限的方向、显著性和年份要求满足；失败即裁决。 |
| 5. 完整统计审核 | 单一完整运行、全库 G5、全部冻结近邻控制、共同样本对照、年度与 LOYO 检查 | 必要统计门全部满足；不能以局部通过替代全套要求。 |

这是本轮沉淀的执行顺序，不要求对已在前门失败的候选无条件做完所有昂贵准入核验。**条件顺序必须事前明确。** R8 E 的完整统计审核失败后不再运行官方准入评价/G1，是按照已冻结顺序终止，不是漏检后假称通过。新增真实发现如确需另一种设计，应另行获得对应研究范围、事前登记；本次已停止，不执行这种后续探索。

## 五、研究设计：先说明差异，再花算力

一个可执行的设计至少回答以下问题：

1. **经济现象和主导机制是什么？** 用一句话说明预期关联，区分风险补偿、行为修正、经营质量和市场背景，不以“复杂”代替机制。
2. **本地字段是否真的测到了它？** 列出字段、源表、单位、频率、历史缺口、报告类型和当时可得日。原论文构念与本地代理分别命名。
3. **与现库及已清理方向有什么区别？** 同时查现有正式定义、已失败候选、`06_清理_股票因子剔除_20261003.md` 和 `06_清理_市场因子剔除_20261004.md`，不能重新包装已经否决的旧构念。
4. **是否存在排序或代数同构？** 拆开分子、分母、差分与乘积；识别正反写法和隐含风格暴露。统计相关低不能代替这一步。
5. **唯一主定义是什么？** 事先写公式、方向、窗口、预热、有效样本、季节项、异常值、缺失与零处理，列出允许变体及预算。不能看收益后补定义。
6. **怎样证伪和怎样停止？** 固定主期限、准入门、必需控制和分阶段终止条件。辅助期限与解释性检验不能替代主期限。

网络调研用于理解机制和忠实核对文献设定，优先原论文及原始方法来源。应记录链接/版本与本地改写，不从文献中的长期结果直接推断本项目 A 股 1/5 日收益必然成立。此次文档完善没有发起新调研或新假设。

本轮典型边界：完整外部净融资缺少独立回购、股利/利息拆分，故本金净募集只能按明确的本金代理表述；净经营资产和受限现金不能用方便的差额冒充；研发早期大量零值存在口径断点；15:00 五分钟柱不能分离集合竞价。HOLD 说明源或差异性条件不成立，**不计作已经回测失败**。

## 六、实现与数据时点的关键细节

固定池为 2115 股票；输出从 2018-01-02 起完整对齐本地交易日历。本轮截止 2026-09-30，共 2123 个交易日。股票因子保留全部日期×股票键，缺失用 NaN，不少写行；内部计算用 float64，正式落盘 value/rank 为 float32。`warmup_days` 按日历天解释，并保持跨年及增量初始化一致。

收益标签从 T+1 开盘到 T+1+h 开盘，h=1/3/5/10/20，使用后复权和真实成交端点；未成熟标签为 NaN。评价时使用未来端点成交条件，不意味着信号日可以提前使用未来成交资格筛股票。价格状态和真实可交易状态分开，停牌不能压缩交易日槽位后再滚动。

财务构造须遵守以下做法：

- 单季、TTM、同比按报告期处理；YTD 差分使用同财年紧邻累计，不能压缩缺季或拿不同季度混合凑 TTM。
- 按当时可见的整行版本选择记录，明确公告可得日和下一交易日生效。后续修订只在修订可得之后生效。
- 先确定当前共同报告前沿，再检查资格。新前沿缺字段或不合资格时清空旧信号，不能回退旧报告保住覆盖率。
- 真实零、缺失、负的合理净流量和异常负的 gross 项目分别处理。高非空率不证明早年大量零值可靠。
- 报龄按规定基准逐日推进，过期清空；供应商没有保留的历史版本不能声称已恢复。
- 回归中的历史 lead 项要明确输出时点。例如 R8 E 回看 t≤q−1，CFO(t+1) 最晚为当前已披露的 CFO(q)，拟合值只在当前 q 的可得日之后输出，不回填历史 t。
- 显式声明 `fin_fields` 和依赖，只预建需要的字段，避免每个候选默认装载全部财报字段。

数学近似可以使用，但必须有明确代理名称、假设和限制。用户在其他工程研究中允许等效简化的偏好，不意味着可以修改金融原始观测、伪造历史可得性或挑选好看的收益年份。

## 七、评估标准与不能混淆的统计口径

下表归纳本轮实际冻结规则，原始定义以 R5 冻结文件及 R6/R7 继承记录为准；它不是对任何未来任务自动通用的“万能阈值”。

| 门槛 | 本轮要求 | 常见误读 |
|---|---|---|
| G1 工程 | 真实输入截断与两阶段增量重放，float32 value/rank、NaN 和键精确一致，完整轴、无 Inf，非全空 | 静态扫描、退出码 0、目录存在或年度拼接，不等于 G1。 |
| G2 覆盖 | 至少 60% 交易日有至少 100 只有限值股票 | 不是要求平均股票覆盖率≥60%；不能改成只看活跃日。 |
| G3 非常数 | 有效交易日中至少 95% 截面标准差>0 | 大量零/离散阶梯即使非恒定，仍须解释混淆风险。 |
| G4 方向信号 | h=1 或 h=5 至少一个期限的 declared RankIC HAC95% 下界>0，且至少 7/9 年同向为正 | 条件回归强不能替代原始信号门；辅助期限不能替代主期限。 |
| G5 与现库差异 | 全部现有股票因子逐一比较，abs(平均日度 Spearman)≤0.95；>0.90 需具体解释 | 不是平均绝对日度相关；不能只查几个有利近邻。 |
| G6 稳定性 | 报分年和逐年剔除结果，主裁判排除由一两个年份主导 | 全期 t 强不等于多年稳定；本轮没有事后增设一个统一 LOYO t 门槛。 |
| G7 独立增量 | 主裁判复算；在 G4 支持的同一期限，秩/模型两种口径的 declared t 均≥2，正向年份均≥7/9；完成规定近邻控制，解释主期限间异常符号冲突 | 不能在 h1 借 G4、h5 借 G7；不能只报显著内核或只报 base8。 |

基础八控制固定为：`momentum_120, short_term_reversal_5, vol_120, idio_vol_60, log_mv, turnover_std_20, bp, roe_ttm`。各机制规定的补充控制也必须事前冻结。例如本轮波动近邻组使用 `idt_rv_daily, id2_parkinson_vol, atr_14_ratio`；旧文件中的其他组名不能无声替换本轮冻结组。

秩口径在逐日共同有限样本上进行截面秩变换与回归；模型口径先按现有消费变换处理完整截面，再在共同样本上回归。两者都使用既定标签秩及 HAC19，不能把两种变换的系数互相替代。保留日历缺口，不通过压缩日期使 HAC 结果变好。

`higher_is_better=true` 时 declared=raw，false 时 declared=−raw。raw 与 declared 均保存，结论用 declared；原始因子 value/rank 保持定义本身。官方评价中已标为登记方向的数字不能再翻一次。本次文稿最终核对曾纠正一个用词：R8 E 的 +0.004548 是**登记方向 IC**，原始噪声数值对应的 raw IC 为负；数值和裁决未改变。后续表格应始终显式标方向。

补充控制至少并报三组：原 base8、补充控制共同样本上的 base8、共同样本上的 base8＋全部补充控制。这样才能区分样本减少和控制加入带来的变化。保留不足样本和秩不足记录，不按结果删列救秩；对存在代数恒等关系的变量组，采用事前设计的可识别比较，而不是临时消掉不利项。

G5 每天对共同有限值且至少 100 股票的配对重新计算含并列的秩相关，再等权平均有定义的日度相关、最后取绝对值。比较库固定到 release；同批若有多项拟准入，还要做相互比较。R8 E 已淘汰，最终仅一项准入，因此准备好的 R7E/R8E 双新因子比较没有执行，不能计作完成结果。

市场因子每天只有一个值，必须按冻结市场合同走 M0–M7，不能把同一市场值复制成股票截面制造 IC。本轮市场信号使用日期维度的固定检验，所有三项均未通过主信号门；没有以“市场背景变量”名义绕过信号与工程证据要求。保守滞后一日是源可得性的假设，不等于证明了历史真实到达时间。

## 八、资源管理：守住内存，也要承认算力利用不足

### 1. 适用上限与监测口径

用户明确的 60GB 上限和 55GB 建议线，优先于旧文档中的 90GiB 预算、85/100GiB anon 阈值等历史配置。不能把 GB 与 GiB 混用；不能因为页缓存可回收就完全忽略 cgroup 计费内存。charged、anon、进程组 RSS/HWM 和 PSS 各有含义，分别记录。

本轮中央监督器 v4 的主要运行设置如下，属于**本次实配记录**，以后先核对环境与用户最新限额再沿用：

| 设置 | 本轮执行值/作用 |
|---|---|
| 新作业启动基础条件 | charged<45GB 且 anon<38GB。 |
| 启动预测约束 | 新鲜 charged＋最近 30 秒启动预约＋本次新增预约≤50GB，防止多任务同时起步。 |
| 预约依据 | 参考同阶段实测进程组峰值，留约 1.5 倍余量；未测的大窗口先用保守估计并标明。 |
| 调度总预约上限 | 56GB；这是预约账面和，不等于实际内存，也不代表允许目标用量到 56GB。 |
| 独立内存保护 | 约 0.25 秒检查；54GB 先终止本研究的大占用任务，56GB 紧急终止本研究任务，必要时约 1 秒后升级处理。54/56 是保护动作点，不是日常目标。 |
| 记录频率 | 约 15 秒保存资源序列；作业另存开始、结束、返回码、峰值和异常原因。 |
| 正式发布 | 本次采用 4 计算 worker、8 的进程上限配置，项目预算按 55GB 换算，原生 charged 护栏约 49.5GB，并保留外层保护。 |

上述设置不是“每个任务可以用 55GB”。所有研究者共用一个预算；保护动作只针对确证属于本研究的进程。独立保护线程不得被慢日志、文件遍历或状态写盘阻塞。进程组预约适合研究作业；正式入口若创建嵌套协调进程，还须结合原生台账和 cgroup 计数，不能用外层主进程很小的 RSS 冒充整条流水线峰值。

### 2. 本轮没有做好的地方

全程平均 CPU 仅 12.72%，是明确未达标项。年度并行阶段有所改善，但设计与工具准备、等待依赖、单核财务计算、完整核验及顺序发布使服务器存在明显空闲。这里是执行记录支持的瓶颈判断，没有做精确的耗时归因，不能给各原因编造百分比。

后续应在获得继续研究授权后改善编排：提前准备已经批准的独立年度任务与必要控制；把准备、源预建、因子计算、评价、验证分别计时；在同阶段实测内存允许时补充独立工作；减少不必要的重复预建和复读。不要固定套用“核越多越好”，也不要用空转、新开未经批准的研究、删验证或突破内存线换取漂亮利用率。

年度 pilot 不能无条件外推到完整窗口或 verify。不能在长任务已运行时为了塞进更多作业，临时把未经同跨度测量的预约调低。反过来，历史峰值保守叠加也会低估可用并发，应把“保守预约”和“实时计费”分别观察，只有拿到相应证据后再调整。

磁盘和 inode 也是资源。大批任务前检查剩余容量；出现压力先盘点归属和引用，不递归删除共享交付目录，不删除生产数据或正在被审核引用的证据。旧文档中将中间产物外写 `/tmp/` 的建议不适用于本次仅工程内写入的边界。

### 3. 怎么汇报才诚实

CPU 分母使用实际 cgroup 配额/可用核数，明确整个监督窗口的起止。全程指标与分阶段指标分别报，不用最忙的十分钟冒充平均达标。cgroup 计数包含同组其他进程，不能声称全部来自本 Agent。

本轮中央采样峰值为 43.121GB，正式发布原生采样观察到 43.184GB；最终取较大的已观察值 43.18GB，**不能将二者相加**。最终平均值在监督器退出后按完整留存计数重算，含发布后短暂整理期。采样峰值不保证每个未采样瞬间，报告应保留这种事实边界。

一份最小交接单应能让下一位直接接手：候选 ID、当前状态、定义/源码/源截止和 release 身份、实际 run/eval/verify ID、已完成及失败事项、当前任务与资源、下一项必需动作、所写文件及其哈希。不要只写“基本完成”“效果不错”或给一个没有来源说明的数字。

证据强度必须分层：字段探查证明可得性线索；合成检查证明边界逻辑；年度预筛证明该年度真实源的结果；单一封存 full 证明完整计算身份；真实输入截断与增量重放证明 G1；正式发布后的逐值比较证明生产落地一致性。**不同层不能相互冒充。**

实际 `run.json` 存在也仍要核对候选、日期、股票轴、输入/实现身份和输出内容哈希。控制生成必须绑定具体年度或 full 来源，精确复算原因子后才输出控制，不能换个标签就复用不同截止或预热上下文。对 JSON 语义身份和文件字节 SHA256 分开命名：用于哪一种验证就按哪一种核对，不为绕过失败临时切换。

结果、原始观测、代理假设、未执行计划在文字中显式区分。阶段草稿可保留当时的 pending 描述，但必须有终稿索引指向最后裁决。后续按用户要求编辑总结时应记录文档修订和新的交付哈希，不修改旧统计证据或据此重发生产数据。

## 十一、正式入库与发布的完成条件

研究期固定比较基线，不能在别的候选还用旧库做 G5/G7 时先把新因子放进去。全部既定基线审核结束后，主裁判才生成明确批准集合，核对每个候选的最终 verdict、完整 run、evaluate、verify 和支持期限。

按官方顺序执行 `candidate → qualified → shadow → production`。评价的 `calculation_run_id` 必须与验证的 `reference_run` 一致；同时检查定义、源、协议和计算身份。通过门槛不等于执行者可自行发布，改生产批准清单由主裁判统一安排。

`production` 状态只代表获准进入生产，**不代表数据已完整发布**。随后运行项目无参数 `main.py`，让现有入口完成年度补齐、质量监控、字典和完整发布。不能直接复制研究 Parquet 到正式目录、手填 manifest、改哈希、删除 dirty/inflight 标记或手写 release 来冒充成功。

发布后独立验收至少核对：新批准集合与实际集合相同；正式对象总数/类型/方向正确；新因子的全部年度日期与股票键、value、rank、NaN、类型和非空值与同一研究 full 一致；原有对象无未解释的定义、元数据或分区内容变化；官方读取验证通过且无未完成标记。本轮旧 176 项不变，是该次任务的验收要求；未来若用户另外授权修改旧项，须对变更单独说明和审批，不能套用“旧项永远不能变”。

下游只获得清楚的交付接口信息：因子 ID、方向、支持期限、可用起点、字段格式、数据位置、发布 ID 和局限。不修改其训练配置、样本或模型；也不因文档提到“通知下游”就自动向外部人员发送消息。

## 十二、停止指令、收尾顺序与下一次接续

收到“完成已设计实验后停止”时，先保存范围快照，明确已冻结单元、在途任务、必要审核和不再启动事项。不再扩新方向、改参数救援、补市场配额或安排持续唤醒。最后一轮不完整是允许的，必须解释而不是补跑凑齐。

收尾顺序为：完成范围内必要实验 → 主裁判逐项终判 → 失败项退休并保留证据 → 固定基线审核全部结束 → 通过项正式准入与完整发布 → 发布后验收 → 汇总结论、讨论、资源和未试验提案 → 清空本次队列并停止自有监督器/工作进程 → 核对文档镜像哈希并关闭连接。

检查“停止”不能只看主进程退出，应核对自有进程组和原生嵌套作业；不要终止其他会话或服务器上不属于本次任务的进程。本次没有创建后续自动研究任务。**现在仅处于文档维护状态，继续因子探索须等待用户新的明确指令。**

若以后用户明确要求继续，先沿用本轮接口、固定池和审核纪律，读取新近生产状态后再建立下一轮冻结；不得把本次终稿中的建议当作自动执行的新任务，也不得把旧 release ID 当成永久不变的当前版本。

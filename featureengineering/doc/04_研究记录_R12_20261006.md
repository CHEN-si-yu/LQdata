### 经验教训凝练（本轮）
1. **自动跳过的正确形态 = 台账自愈而非重算**：coverage 从"已校验分区"回填 + rebuild 不再清台账，
   实测代价从"全量重生成"降到 26 任务分钟/29 因子×9 年；每日发布内对账亦证"已覆盖历史零重排"
   （207 分区同内容跳过写盘、51 分区仅空→满补写、unexplained=0、changed=0）。
2. **可编辑窗口由哈希口径决定**：晋升(现场重算)只绑定 fea/*.py、research 顶层 *.py、候选自身模块；
   批冻结绑定递归 **/*.py。**加**新模块文件到 research/families/ 在跑批/晋升期间也安全；
   **改**任何 .py 必须安排在两次窗口之间的发布后时段（详见 memory: fe-hash-scope-and-freeze-windows）。
3. **conf/field_expansion.json 是自动注册源**：加条目 = 凭空多出库因子（annual_field_expansion 逐条 @register）。
   年度缺别名时正确做法 = `r12gc_common.annual_value` 年度网格（roa_y 先例，零 conf 变更）。
4. **转述必须对权威结构复核**：枚举代理"别名已声明"经 `ANNUAL_ALIASES` 复核为真
   （17 条覆盖 gcD 全部 11 个年度分子字段）；反例是批 B 的 G7 误植（文档 1.44 实为 U2-A 数字），
   靠四变体逐位复现才定位——**裁决级数字一律回源**。
5. **门检必须同源证据**：晋升强制 eval/verify 同 reference run；run_gates.sh 的 --eval 自动查找
   消灭过 NOT_PROVIDED。
6. **内存护栏口径 = 计费内存（含页缓存）**：刚做完大批读盘的任务后紧接新任务会踩线
   （本次每日任务触发 55.1GiB → 自动降档 1×6 重跑成功）。大批量读的作业要错峰、降并发。
7. **批断点迁移法**（plan.json 不可变 ⇒ 换 out 目录 + 迁移 candidates/attempts 树 + 重新 freeze）：
   内存击杀后无损续跑，实测两次。
8. **GC 通道 = 扩容引擎**：三项门槛+verify+注册去重，不主张 G4–G7；|ρ| 硬线 0.98、
   软带 0.95–0.98 留主裁判复核（本批 2 例 <0.98 且有 0.9681 在库先例 → 判过，留痕）。
9. **批窗口内禁一切 mark-dirty 操作**（promote / main.py run / 发布）；register-only 不受限，
   可在任意时刻补注册。

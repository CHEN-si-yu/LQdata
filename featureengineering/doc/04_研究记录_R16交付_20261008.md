## 缓存缺陷、工程修复与真实回放

旧 v1 的全期、截断和增量数值精确通过，但独立收尾发现 NumPy object 数组 raw bytes 包含进程指针，使股票代码轴哈希跨进程变化，阻塞真实模型缓存恢复。因此旧候选在准入前退役，原证据与失败记录保留。

v2 只将两处代码轴校验改为确定性 Unicode 字节；数学、训练和参数完全不变，统计试验仍只有一次。它登记了新的不可变工程身份并重新执行真实正式链；没有把旧 v1 的工程结果改名冒作新版本通过。

新候选：`r16c_ml1_price_volume_monthly_h5_mlp_replay_v2_d9ac78cf139d8d43`。实现 [r16_ml1_official_v2.py](../research/families/r16_ml1_official_v2.py) 的 SHA-256 为 `947b1c1598ac5abe9ad01eb57eccdf54cea6353bdf73d875062653e554babbff`。

同 namespace 两个真实进程的缓存恢复已通过，第二个进程在禁止训练 guard 下 fit_once_calls=0；105 月模型的权重、scaler、训练日期/端点/计数、X/Y 与代码轴哈希独立核验全通过。新全期正式值和 NaN 与冻结参考逐位一致，h1/h5 标签也精确相同，4,288,881 有限单元；见 [全期对拍](../artifacts/research/round16_20261008/seat_ml/ml1_v2_official_full_compare_v1.json) 和 [105 月独立模型审计](../artifacts/research/round16_20261008/seat_ml/official_105_model_identity_review_v2.md)。

为加快用户要求的收尾，实际截断、增量及实际生产仅预热同 v2 全量运行的成熟模型 NPZ 权重，不复制预测、manifest、父因子、标签或原始输入。目标仍按其实际源截止重建 X/Y、日期、端点、scaler、计数和完整 lineage，任何差异都会拒绝复用，随后重新 GPU 推理与输出对拍。模型复制的源、目标和 SHA 逐项留存；这是缓存优化，不替代正式工程和生产验证。

## 2026-10-09 环境政策变更（用户指示：任何机器都要能算）

用户当日明确要求「任何机器都要能正确生成」，与模型侧 2026-09-22「指纹守卫全部改告警」的既有政策一致，
对 `research/families/r16_ml1_official_v2.py` 做如下修改（仅该文件；数值算法、配方与种子未动）：

- **硬件与解释器版本不再硬拦**：GPU 型号 / 驱动 / Python / NumPy / Torch / CUDA 版本与封存环境
  （vGPU-32GB / 570.124.04）不一致时只发告警（warnings + stderr），计算继续；无 CUDA 时自动退回 CPU。
- **数值设置仍强制**：SEED、float64、threads=1、deterministic algorithms、CUBLAS_WORKSPACE_CONFIG、
  BLAS 单线程——与机器无关，仍为硬校验（设置失败即报错）。
- **缓存复用改为「训练身份」比较**：lineage 除 `environment` 与 `adapter_sha256` 外逐字段严格比较
  （训练日/输入/目标/端点摘要、codes、universe、父模块哈希、设计哈希等）；环境不同只告警并注明。
  `adapter_sha256` 与生产系统总体设计一致地只做记录，公式变更仍走显式重建。
- **预测缓存**：训练身份一致但本机重算末位不同时，告警并用本次结果覆盖缓存（不再 raise）。
- 模型/预测归档的 `environment_json` 记录实际计算环境，新增 `sealed_environment_match` 字段。

## 二、方法学经验（每条都有实证）

1. **G7（控制后增量）是不可省略的最终关卡**。本轮两例"美丽陷阱"：
   `goodwill_to_equity`（IC 9/9 年、G5 干净）与 `price_granularity`（declared 8/9 年、非规模代理）——
   在 8 个标准控制下 FM t 分别只有 −0.44 / −0.86。**原始 IC 漂亮 ≠ 增量信息**，这是第 N 次实证。
   **要求：任何准入决定前，Lead 必须独立复算 G7；执行者的数字（尤其其自建 FM 工具）不能直接采信。**
2. **FM 口径要双列留档**：AGENTS.md 的 G7 = 秩回归内核（Lead 复算口径，与 R2/R3 锚点可比）；
   执行者自建工具常用"模型消费变换"（winsor-z-clip）口径，两者 t 可差 2 倍（如 idio_max 13.4 vs 4.9）——
   **结论一致方向、数值不可混记**。任务书应明确"两口径并报"。
3. **G5 拦截仍有独门案例**：`pre_ann_runup_20` 与 `momentum_20` **ρ=0.998 结构性同构**
   （池内相对收益减去的截面均值不改变排序）——**构造新因子时要先想"这个变换会不会在排序意义上恒等于现有因子"**。
4. **G2（覆盖）是结构性硬约束**：`pre_ann_turnover_shock` 除 G2 外全门全过（含 FM +8.4/+5.8），
   但事件窗口因子覆盖 49.3%<60% 被拦。**不按"活跃日口径"重新解释 G2**（=事后放宽门槛）；
   复活唯一合法路径是重新设计覆盖结构后**新预登记**。
5. **半离散变量的主动排除义务**（D.2）：`same_month_consistency` 是 13 格点 k/n 变量 →
   除"FM 不归零"外，Lead 追加了**上市年龄混淆检验**（加 `listing_age` 第 9 控制，t 基本不变）才放行。
   **遇到 SPARSE_OR_DISCRETE 旗标：先做混淆检验再谈准入。**
6. **镜像对设计是好模式**：`log_price_level ↔ price_granularity` 同注册方向让数据裁决符号——省一次方向猜测。
7. **重蹈检查必须强制执行**：本轮抓到 3 个机制撞已删因子（`forecast_implied_surprise`、`close30_volume_share_20`、
   `close_location_value_20`）。**实现前必 grep 两代失败档案**（374 股票 + 27 市场删除记录）。
8. **防重蹈即省预算**：V1 执行者按检查主动停掉 `goodwill_to_assets`（已删同名构念）——好实践。

## 三、工程与运维经验

1. **RLIMIT_AS=24GiB/进程 是框架级天花板**（`fea/resources.py`，不可环境覆盖）：5min 族长跑会在
   `upstream._audit_dates` 的 47.8M 元素中间拷贝处累积触顶（upbar 三次失败实证；单年可跑）。
   绕行：malloc 收紧（`MALLOC_TRIM_THRESHOLD_=0 MALLOC_TOP_PAD_=0 MALLOC_MMAP_THRESHOLD_=65536`）后成功（VmPeak 23.74GiB）。
   **正式修法待办：让 RLIMIT_AS 可按进程/按族声明。**
2. **内存护栏**：cgroup charged 会在密集 verify 潮时冲高（本轮实测峰值 61.9GB / 上限 64.4GB，无 OOM 但回收触顶 3.1 万次）。
   纪律：启动前 **anon>42GB 或 charged>52GB 等待**（双闸门）；不把「memory.current 高」当恐慌信号（多为页缓存）。
3. **inode 是硬资源**：本轮从余 11.1 万降到最低 7.7 万（runs 产物），清理后回到 10.8 万。
   每个 research run 约 100–140 inode；**大批量研究前查 `df -i`**。
4. **完成判定只认 `run.json`**：被杀的 run 只有 `begin.json`——按目录存在判定完成会拿半成品去 evaluate（R2 血泪，已复用）。
5. **子 Agent 操作的坑**（本轮新增）：
   - 子代理会在「等后台任务」时结束回合 → 父会话需按通知唤醒（SendMessage），并在任务书里要求 `sleep` 轮询而非停回合；
   - 子代理环境可能**无法写 report.md**（工具层限制）→ 父会话（Lead）须把返回的全文**原样落盘**（本轮 2 例：r4m、r4t）；
   - 唤醒/监控映射用 `lead/dispatch_registry.md` 登记表管理。
6. **promote 生命周期细节**：candidate→qualified→shadow→production 三级逐级；
   **eval 与 verify 必须同源 run**（配错会报 "must share the same run"——从 evaluation 的 `calculation_run_id` 反查配对）；
   市场绿卡也要跑三段 verify 才能过生命周期（工具不豁免）。
7. **前件 freeze 的引用方式**：批间 freeze 绑定应对前件用**内容哈希锚定**而非文件字节相等，否则前件合法推进（重写时间戳）会触发再绑定链。
8. **共享源码纪律有效**：本轮 12+6 个并发 Agent 零共享源码改动（`fea/`、`research/` 顶层 mtime 全程核查）；发现"疑似改动"先查 mtime 自证。

## 四、流程与裁判机制经验

1. **裁判机制（Lead 出题/审核 + 员工独立执行）在本轮充分验证**：执行者不是"手"，是独立验证者——
   两处由执行者发现并纠正的用户级问题（子代理环境限制、mtime 碰撞）与三处 Lead 拦截并存。
2. **预登记与冻结**：方向/机制/预算在看结果前冻结，本轮 60 候选中**零事后改向**；失败与撤销全部留档（含"重蹈对照"记录）。
3. **资源协调**：`ops/usage.log` 每分钟采样 + 每小时巡检播报（用户要求 1h 节奏）+ 双闸门启动等待；间歇性 verify 潮需提前错峰。
4. **每轮收口的固定动作**（本轮定型）：全库 G5 穷尽扫描 → promote → 无参数日更发布 → 发布验收 →（按当时用户口径）下游对齐/通知 → 证据链处置（见 §六）→ 经验回写。

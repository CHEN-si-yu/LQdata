# 因子工程维护约定

本文件说明本项目的维护边界。后续用户明确指令优先。当前生产要求来自 2026-10-07 的重构任务：保持入口与因子落盘合同，优化全量、增量、自动跳过、并行和生产进度。文档导航见 [README](README.md)，操作以[项目手册](01_生产_项目手册.md)和[入口命令说明](01_生产_命令接口.md)为准。

## 工作边界

- 维护范围为本因子工程。配置声明的上游原始数据只读，不修改上游抓取工程、下游模型或其他工程。
- 所有数据、缓存、状态、日志、临时文件与验证产物在项目内。使用 `cfg.root`、`cfg.project_path(...)` 或相应配置属性解析路径。
- 隔离验证使用 `Config.sandbox(...)` 或入口 `--sandbox`，同时隔离数据、派生缓存、状态和日志；不得在正式输出中删除或裁切分区模拟故障。
- 2026-10-08 用户明确启动 R16 因子研究，确认子 Agent 使用 gpt-6-luna/high，并允许机器学习与 GPU；本轮范围见 [R16记录](04_研究记录_R16_20261008.md)。历史数量目标和分工不自动继承，新候选遵循现行研究流程与 v4/v4.1 准入。
- 用户随后要求完成本轮已设计和规划任务并收尾交付，暂停新的研究方向；继续冻结候选的工程验证及通过后的实际生产对拍，不再新增方向、模型变体或统计试验。
- 2026-10-18 用户重新明确授权 R17 因子挖掘：主 Agent 主审、子 Agent 研究，目标正式股票因子 >500 或用户停止；沿用 v4/v4.1、研究流程与全部工程/PIT/结构去重纪律。R16 的暂停指令自此被 R17 授权取代；R15 冻结方向仍需单独授权。

## 当前生产路径

- 无参数 `python main.py` 直接增量生产；首次运行或新注册对象补齐请求范围的历史。入口只保留 `run/incremental`、`rebuild/full`、`list/status`。
- 注册包含 `factors/` 启用规格和此前研究转正的实现。保持这些实现及其定义依赖完整。
- 生产路径不运行指纹、历史内容哈希、审核、评估、监控、字典生成和发布。不把 `current_release.json` 或旧字典作为新入口的完成标志。
- 根据覆盖和实际年分区计划任务。已对齐结果跳过；缺失或不可读分区补算；状态丢失可按日期列恢复覆盖。公式修改由显式 `rebuild` 处理，历史源修订由明确日期的 `--refresh` 处理。
- `rebuild` 强制重算选定范围；中断后默认入口或 `rebuild --resume` 补剩余任务。不能把旧版“rebuild 自动跳过全部已有结果”的规则带回当前入口。
- 主进程持有 `state/daily.lock`。计算进程写互不冲突的因子年分区；主进程逐成功任务保存覆盖。失败任务及其依赖节点不得标记完成，不手改台账伪造成功。

## 固定数据合同

- 股票轴读取 `conf/universe_frozen.tsv`，不通过删股票改变覆盖。默认从 `default_start=2018-01-01` 对齐本地交易日历；更早输入用于预热。
- 股票因子与标签保存四列 `trade_date:string, stock_code:string, value:float32, rank:float32`；市场保存 `trade_date:string, value:float32`。年度 Parquet 路径、列序、排序、压缩和完整键轴沿用 Store 合同。
- 缺值保留 NaN 与完整行。`FactorSpec.start` 是真实值起点，对齐前缀按原规格保留；不能凭空零填充。默认对齐 NaN 前缀的 rank 为空。
- 计算使用 float64，落盘转换 float32。普通因子不能使用未来位移、向后填充、全样本标准化或最新前复权基准。收益类使用原始价格及当时累计复权信息。
- 标签为 T+1 开盘买、T+1+h 开盘卖的后复权收益，h 为 1/3/5/10/20；两端须真实成交，未成熟保留 NaN，标签 rank 始终为空。
- 财务以公告可得日和保留版本构造 PIT，报告期用于 TTM/单季/同比。源频率及滞后按项目输入合同处理，不能把供应商缺失的历史版本说成已重建。
- 声明全部直接数据输入及父因子依赖，通过 Context/Engine/Store 计算与保存。`warmup_days` 是日历天，锚点固定于输出年；增量起点不得改变递推初始化。

## 并行、展示与验证

- 当前使用 `fea/production.py` 的持久进程池。默认 12，配置上限 20，受 CPU 配额约束；单进程数值线程为 1，默认地址空间上限 24 GiB。
- 项目内存预算配置上限 90 GiB，容器更小则取更小值。在途任务按 cgroup 内存余量与 `worker_memory_gib` 预留动态限制。不能把旧年份流基准或旧资源台账当作当前测量。
- 终端采用名称对齐的总进度和逐因子进度条；文本采用时间戳、阶段摘要、序号、已有覆盖、写入/新增行数及耗时。主进程统一展示。
- 数值或调度修改在项目隔离目录验证日更、全量、新注册、跨年、标签成熟、依赖预热、断点、缺失/损坏分区、状态丢失、写入互斥和计算进程异常。
- 与原 Engine 做逐值与 Parquet 字节对拍；需要有非空有效值，不能把全 NaN 相等当作数值正确证明。测试入口和已跑结果见[验证记录](01_生产_重构验证_20261007.md)。
- 根据变更执行相关检查。文档整理只校对命令、链接、索引和历史保留，不启动正式全库计算。

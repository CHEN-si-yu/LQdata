# 运行与恢复

在项目根目录执行。上游 `../datadownload/data` 只读；默认起点为2018-01-01，默认截止为上游 `stock_daily` 最新交易日。

## 常用命令

```bash
python main.py                              # 日更；首次运行也补历史
python main.py list                         # 注册类别与台账覆盖
python main.py run momentum_20 roe_ttm       # 指定对象，自动包含父依赖
python main.py run --group market           # 按规格类别选择
python main.py run --dry-run                 # 只查看生产计划
python main.py rebuild --jobs 1             # 强制重算全部启用对象
python main.py rebuild --resume --jobs 1    # 全量中断后补剩余部分
python main.py run momentum_20 --start 2026-09-01 --end 2026-09-30 --refresh
```

`run/incremental` 表示增量，`rebuild/full` 表示强制重算，`status` 与 `list` 相同。无参数或只传生产选项时自动采用 `run`。全局 `-v/--verbose` 放在命令前。完整帮助使用 `python main.py run --help`。

**当前完整结果（2026-11-10）**：500项（445股票/50市场/5标签）、2018–2026共4500年度分区／2,042,562,800行至2026-11-09，正式全量及恢复全部完成，完整键/格式/state/coverage和12,015截面rank通过；重算前后4500文件SHA相同，全500实际pending为空。两轮原生11-06→11-09增量均500任务成功且与全量对拍差0，CLI分别4097.044秒与1983.062秒；全量含正式补跑累计16415.6851秒。缓存条件、失败及计量边界见[关键结果顶部](03_关键结果.md)。质押源停更仍独立披露。

本次32核/60GiB、无可用CUDA的环境使用下列自动模式。保留已有派生缓存与月度模型；这不是清空缓存后的训练成本。配置默认12/上限20未改，本次未完成12进程实测，不据8进程成绩推断更高并发收益。

```bash
FEA_DEFAULT_JOBS=8 FEA_MAX_JOBS=8 FEA_MEMORY_BUDGET_GIB=60 python main.py run --jobs 0 --progress plain
FEA_DEFAULT_JOBS=8 FEA_MAX_JOBS=8 FEA_MEMORY_BUDGET_GIB=60 python main.py rebuild --jobs 0 --progress plain
```

使用正整数`--jobs 8`会豁免项目资源保护，与上述测试条件不同。

## 参数

| 参数 | 作用 |
|---|---|
| 位置名称或 `--factors NAME ...` | 选择因子；后者优先；缺省为全部启用对象 |
| `--group GROUP ...` | 未点名时按实际 `group` 选择；父依赖自动补入 |
| `--start/--end YYYY-MM-DD` | 请求日期范围；终点不超过源截止 |
| `--from-year/--to-year YYYY` | 取对应年首/年末，覆盖同侧日期参数 |
| `--refresh` | 重算请求范围，保留范围外结果 |
| `--resume` | 按覆盖恢复，通常用于 `rebuild` 中断后；恢复时不加 `--refresh` |
| `--jobs N` | 0为自动；正整数直接指定进程数并豁免项目资源限制 |
| `--progress auto/bars/plain/off` | 自动检测终端、强制进度条、文本、仅阶段摘要 |
| `--sandbox DIR` | 数据、派生缓存、状态、日志均写入项目内独立子目录 |
| `--dry-run` | 只规划，不生成分区或提交覆盖；仍创建日志和锁文件 |

`list/status` 仅支持 `--sandbox`。父依赖计算范围可能因年度预热扩大；更新父对象不会自动选择所有未点名子对象，公式修改应明确选择受影响对象。

## 跳过与恢复

生产路径为 `main.py → fea/production.py → Engine → Store`。按日期覆盖和物理年分区规划任务：已对齐跳过，缺失或不可读分区补算，状态丢失可从日期列及每天行数恢复覆盖。该恢复不等同于逐键逐值审核。新因子补历史，标签随源推进回算未成熟尾部，包括跨年尾部。

每个成功年分区立即保存断点。强制重算派发前撤销相应旧覆盖，避免中断后把旧文件误认成完成。中断后运行默认入口，或对相同对象和范围执行 `rebuild --resume`；不带 `--resume` 的 `rebuild` 会重新强制计算。失败对象及其被阻塞依赖不标记完成。

当前入口不执行内容指纹、审核、评估或发布。公式和同尺寸历史内容变化不会自动失效旧覆盖：公式修改显式重建；上游历史修订用明确日期的 `--refresh`。不要手改台账制造成功。

历史2026-10-27工程核验曾发现：当时六项留有2025待完成标记，但普通规划会因coverage/行数齐全而跳过；两项质押因子因上游快照只到09-11，从10-13起有效期过期而全空。`--dry-run`待算0只说明当前规划无任务，不证明所有遗留状态已闭合或源仍新鲜。2026-11-10正式全量重算后这些历史pending已自然清除；质押源停更与过期缺值保持。对象名单、实测增量/恢复结果与处理边界见[关键结果顶部](03_关键结果.md)。

生产写入受 `state/daily.lock` 独占保护。锁文件存在不等于进程存活，不通过删除锁文件绕过互斥。

## 资源与设备

配置位于 [config.yaml](../conf/config.yaml)。自动模式默认12个计算进程、上限20，受CPU配额和内存余量约束；项目内存预算上限90GiB、单进程地址空间默认24GiB、每任务预留3GiB，数值库单线程。可用上面的环境变量将本次预算固定到实际60GiB。显式正整数`--jobs`豁免项目的并行度、地址空间与调度内存限制，操作系统和容器限制仍有效。共享筹码摘要按月有界构建，多个变体复用；旧完整大表每worker约20GB的估计不适用于新版。

自动模式在成功写入后达到既有内存门时释放可重载任务缓存；任务异常会清理部分初始化缓存，协调器排空并回收进程池后接续。R16ML1依赖齐备后自动排空普通池，使用全新单进程池运行该模型阶段，完成后恢复常规并行，避免混合任务worker累计地址空间妨碍Torch映射。父依赖、失败阻塞、成功逐年断点与全局锁保持。

R16ML1有CUDA时使用全局非阻塞GPU锁；无CUDA回退CPU，按派生缓存路径、任务年份和截止日加锁。本次容器没有GPU设备，Torch的CUDA构建版本不代表设备可用。不要通过提高地址上限或删除设备/CPU锁处理进程污染；使用正式入口及新的进程阶段即可。

硬件与Python/NumPy/Torch等环境版本漂移只告警。种子、float64、确定性和线程设置仍强制；模型训练身份严格比较，跨设备浮点末位不承诺逐位一致。模型月度训练、缓存和2016/17私有父历史属于正式因子计算，不能当研究垃圾删除。

## 日志与退出码

日志为 `logs/run_factors_*.log`；正常调度结束写 `state/production_last_run.json`，异常退出不保证刷新摘要，恢复以逐因子断点为准。后台执行：

```bash
python main.py --progress plain > logs/console.log 2>&1
```

终端默认显示总进度与逐因子条，重定向自动采用文本；进度按成功年任务推进。退出码：`0`成功/跳过/计划完成，`1`计算或配置错误及失败阻塞，`2`参数错误或写锁冲突，`130`用户中断。

新增筹码生产聚合依赖Numba；本轮正式解释器Python3.14.7、Numba0.68.1、llvmlite0.50.0。`data/derived/chip_distribution_v1`及其年度锁/身份文件是生产缓存；不随work清理。首次九年预建可点名 `python main.py run cg_log_iqr_v1 --jobs 3`，再用上述三个group补全部新增对象。已有覆盖自动跳过，源修订仍按原合同显式refresh。

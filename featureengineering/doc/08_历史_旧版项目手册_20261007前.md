## 每天怎样运行

上游更新后执行同一个入口，从任意工作目录运行均可：

```bash
python /root/autodl-fs/featureengineering/main.py
```

无参数等价于 `main.py run`，计算进程数按当前配置、CPU 配额和内存护栏确定；实际用量以该次资源台账为准。入口使用现有共享解释器 `/autodl-fs/data/miniconda3/bin/python`，不安装或改写共享环境。

一次完整日更依次执行：等待已识别的上游写入进程退出；获取项目独占写锁；读取正式批准对象与项目内源可得性合同；固定本轮输入身份与截止交易日；恢复未完成批次；按依赖顺序、年度独立进程计算；原子替换年分区并核对输入与逐日内容；执行质量监控；刷新因子字典；发布完整对象清单。

截止日来自上游 `stock_daily` 实际水位，不把未来日历日期当作已有行情。默认上游等待时间 21600 秒，遇到其它因子写入者立即拒绝并发。退出码 0 表示本次请求完成；对无参数完整日更，应同时出现“发布完成”并更新 `state/current_release.json`。指定少数因子、限定日期或沙箱运行只完成维护/研究请求，不能当作全库已经发布。

日更失败后查看 `state/runs/<run_id>/report.json`、同目录的失败记录、年块日志及 `quality.json`。保留的 `state/daily_inflight.json` 表示批次未完成；解决原因后再次运行无参数入口，由程序恢复，不要手改 coverage 或删除运行日记来绕过失败。

新因子正式批准后，同一入口自动补齐其缺失历史；已有对象按源水位和覆盖做增量规划，完好的历史分区自动跳过。研究候选须先完成正式准入，候选登记和主审建议不自动等于生产登记。详见 [因子侧一键更新交付说明](08_历史_一键更新交付_20261006.md)。`status` 与 `check` 的 legacy 规格遍历不覆盖所有研究转正对象；全库验收以真实完整 release、对应质量报告及字典为准。

本轮R13已完成默认无参数入口的全历史补齐、同源增量、质量核验及两次完整发布审计，股票227/市场47/标签5；实际回执与经验见 [收尾交付总结](04_研究记录_R13交付_20261006.md)。

## 项目边界与目录

业务输入只允许访问 `conf/config.yaml` 中声明的上游原始数据目录，当前为 `../datadownload/data`。源频率、延迟、股票池、研究定义与生产批准清单由本项目自己维护；不读取上游工程或其它项目的配置、状态、训练数据。操作系统资源监测和现有解释器是运行基础设施。

缓存、日志、状态、临时文件、沙箱、研究证据及最终数据全部写在本项目内。不要使用项目外路径或硬链接建立第二份产物目录。

## 固定任务网格与保存合同

股票池是名单冻结时仍存续、2016-08-09 起未出现 ST、上市不晚于 2018-01-01 的 2115 只主板股票。筛选包含幸存者偏差与事后 ST 判据，研究结论针对这个固定池，不能解释为历史可投资全 A 股结果。股票代码保留交易所后缀及前导零。

输出下界固定为 2018-01-01，首个本地交易日是 2018-01-02。上游更早数据可用于预热，不扩大评价股票或输出时间范围。所有新候选沿用这条日期轴；读取数据晚起时保持明确的缺失前缀。

| 对象 | 年分区路径 | 列与类型 |
|---|---|---|
| 股票因子、正式标签 | `data/factors/<name>/year=YYYY/data.parquet` | `trade_date:string, stock_code:string, value:float32, rank:float32` |
| 市场状态因子 | `data/market_factors/<name>/year=YYYY/data.parquet` | `trade_date:string, value:float32` |

股票分区每个本地交易日保留 2115 个股票键，缺失值为 NaN，不能用少写股票行代替缺失。市场分区每天一行，不复制为股票行。主键唯一，列序与类型统一，无无穷值。股票因子的 `value` 为原始公式值；`rank` 为当日有效截面经统一缩尾后的百分位，方向合同通过元数据 `higher_is_better` 保存。正式标签的 `rank` 恒为 NaN。存储使用 Parquet，而非 Feather。

`FactorSpec.start` 是真实值起点；默认 `align_fill=NaN` 的分区仍从 2018 起对齐，前缀 rank 恒为空。只有原始表明确用零表达“无”并保存了实际字段证据，才能使用零填充。缺表、缺字段、未披露和无事件必须按各自声明区分。新候选不允许用 `align_fill=None` 关闭任务日期轴。

## 价格、时点可得性与正式标签

普通因子只使用信号日收盘及以前已知输入。状态价格可以前向沿用；成交量、成交额及真实成交状态不能用前向填充伪造成成交。收益使用原始价格乘截至当日累计复权因子的后复权口径，禁止用最新复权基准回改历史价格。数值运算采用 float64，仅存储时转换 float32。

财报按公告可得时点及已保留版本构造当时最新状态；TTM、单季和同比按报告期计算。源延迟读取项目内合同和观测，融资融券等已声明滞后源必须正确移位。无法还原供应商未保存的历史修订版本，不能把普通截断测试写成完整供应商 vintage 证明。

正式标签 `label_ret_1d/3d/5d/10d/20d` 的统一定义是：

```text
y_h(t) = open_hfq(t + 1 + h) / open_hfq(t + 1) - 1
```

T 日收盘产生信号，T+1 开盘买入，持有 h 个交易日后开盘卖出。个股买、卖两个端点都必须真实成交，价格有限且分母有效；未来行情不足的尾部保持 NaN，后续行情到齐才成熟。未来成交掩码只用于定义离线目标，不能提前用它筛选信号日输入。标签期限 1/5 日为主要评价期限，3/10/20 日用于辅助衰减诊断。

生产标签保留在 `factors/labels.py`，共享数组合同位于 `fea/targets.py`。生产 `eval` 优先读取正式落盘标签，缺少某年度正式标签时采用同等端点/成熟合同计算，报告明确记录来源。市场标量没有同一天股票间排序，不计算虚构的日横截面 IC；若研究交互，应明确构造对应股票候选。

部分市场输入为供应商全市场聚合，部分为固定池统计，名称/元数据应保留范围区别。历史收益形成的行业代理不等于官方历史行业归属。上午行情指标的截面时点即使是 11:30，当前日终供数的实际可用时点仍为收盘后。

## 正式生产清单与完整发布

`conf/production.json` 明确决定无参数日更计算哪些对象。已有对象首次接入登记为 `legacy`、研究复核待完成；这保留既有生产集合，不声称已有盈利性验收。新文件被导入或新函数注册，不会自动成为正式输出。

```bash
cd /root/autodl-fs/featureengineering
python main.py library list
python main.py list
python main.py status
```

`library bootstrap` 是缺少正式清单时的一次性接纳已有定义动作；首次无参数生产入口也会自动执行，不要删除正式清单来重新接纳未审核实现。已有定义的数值逻辑修改需要提升版本并审查身份变化：

```bash
python main.py library accept EXISTING_NAME --reason '写明实际公式修订及验证依据'
python main.py rebuild --factors EXISTING_NAME --jobs 8
python main.py
```

上面的 `EXISTING_NAME` 替换为实际名称。`accept` 记录批准身份，不能代替正确性验证；同文件中其它正式定义身份若也改变，应逐项审查。暂停/退出已有对象使用 `library status NAME paused|retired --reason ...`；仍被正式父依赖引用时拒绝移除。研究来源的生命周期统一走 `research promote`。

共享计算内核另有审批合同。修改 `fea/context.py`、`mathx.py`、`prices.py`、`deriv.py`、`panel.py`、`dates.py`、`universe.py`、`store.py`、`spec.py`、`targets.py`，或 `_COMMON_KERNELS` 列出的日内/派生内核后，需要核对实际数值影响，递增 `conf/config.yaml` 的 `compute.kernel_version`，再显式接受公共版本：

```bash
# 先在配置中递增 compute.kernel_version，再记录实际审核理由。
python main.py library accept-common --reason '写明公共计算修订、受影响范围及实际验证依据'
python main.py
```

公共版本进入 recipe，下一次完整日更据此重建受影响输出，再通过监控和完整发布。基线版本 1 保留既有 recipe；不能跳过版本递增，不能直接编辑批准哈希绕过审核。单因子 `library accept` 与公共内核 `library accept-common` 是不同变更通道。

公共版本也进入派生缓存身份；版本 1 沿用既有类版本，大于 1 后重建所需年度缓存，包含新算法从非空变为空的情况，避免新因子口径继续读取旧聚合值。

完整批次通过质量闸门后写入 `artifacts/releases/<release_id>.json` 并更新 `state/current_release.json`。清单包含对象版本、定义/recipe 身份、股票池、年度路径和文件哈希。年文件按原路径原子覆盖，这不是为每批复制一份不可变数据。

消费方使用项目内 `fea.release.read_release(cfg)`，并在读取年度数据期间保持其共享读锁。接口拒绝未完成日记、发布后维护改动、被改变的清单及分区文件；需要完整文件校验时传入 `verify_hashes=True`。单独读取旧发布指针无法保证完整批次一致。消费者随后按自己的模型需求对齐，本项目不主动改其输入工程。

## 以后如何开发新因子

新候选全部在本项目实现，优先在 `research/` 增加构造器，复用 `FactorSpec`、`Context`、价格/PIT 层、Engine 和 Store。构造器引用形式为 `research.<module>:<builder>`，返回一个普通因子的上下文计算函数；股票结果为 `(T,C)`，市场结果为 `(T,)`。声明全部原始输入和父依赖，不直接在公式里读取任意文件。

每个新 Family/版本采用独立实现模块，例如 `research/families/example_v1.py`。已登记的候选封存整份实现文件的身份，在旧文件中追加代码也会使该身份失效；保留原文件，用新模块登记下一版本。

研发对象分为三层：Idea 记录工程/经济假设、方向、期限、原始字段与可证伪条件；Family 预登记变体集合、比较基线和试验预算；Candidate 固定实现、参数、单位、缺失/成交/可用时点及 FactorSpec 元数据。定义不可变，修改实现或参数需要新的版本/候选身份，失败与放弃的试验保留在账本中。

登记定义文件必须位于项目内，YAML/JSON 均可；最小字段可参考 `conf/research/examples/`。命令依次为：

```bash
python main.py research idea --file conf/research/examples/pv_idea.yaml
python main.py research family --file conf/research/examples/pv_family.yaml
python main.py research candidate --file conf/research/examples/pv_candidate.yaml
python main.py research list
```

也可运行 `python main.py research init-example` 一次登记预设六个量价候选；这只登记，不计算、不准入，不表示六个候选已经验证有效。

将下面的 `CANDIDATE_ID`、`RUN_ID`、`EVALUATION_ID`、`VERIFICATION_ID` 替换为前一步输出的实际身份。开发时先选合理的短窗口核对接口，再扩展到完整证据区间；示例日期用于说明参数，并不宣称试验已经执行：

```bash
python main.py research run CANDIDATE_ID --start 2025-01-01 --end 2026-09-30 --jobs 4
python main.py research evaluate RUN_ID
python main.py research verify RUN_ID --jobs 4
```

隔离运行写入 `artifacts/research/runs/<run_id>/`，同时计算声明的父依赖与正式标签，生产 `data/` 和 `state/` 不被借作候选工作区。运行封存定义、协议、输入与计算代码身份。每个试验/增量阶段把原始表可见行限制到该阶段末日，窄列读取也会临时加入可得日期；派生缓存和可见 ST 基线按阶段隔离，同一阶段内 ST 内容变化仍明确报错；完整 ST 原始文件也纳入同源身份核对。财报取公告日、实际公告日和报告期的最大值，预测公告按本次公告日；缺少可得日期的表不能宣称通过截断审计。基本日历和股票名单保留冻结任务轴，任意 Python 绕过项目接口直接读取文件不属于本审计保证。评价写入 `artifacts/research/evaluations/<evaluation_id>/daily_metrics.parquet` 和 `evaluation.json`；验证另保存实际全量、截断、分两阶段增量结果，并核对参考结果的值、rank 和缺失位置。

候选可以把另一个不可变候选的完整 `candidate_id` 声明为父依赖，父子一并在同一隔离区复算。代码拒绝同名冲突、循环、未声明的源和未来标签输入；证据身份包含全部父版本及实现。进入生产前，研究父因子必须先独立通过准入，批准子因子不会自动批准父因子。

生命周期按显式决策推进：`candidate → qualified → shadow → production`；允许按实际状态进入 `paused` 或 `retired`，退休不可逆，恢复应建立新的研究记录。每次决策必须说明理由并链接实际证据：

```bash
python main.py research promote CANDIDATE_ID --to qualified --reason '工程证据与历史评价复核通过' --evaluation EVALUATION_ID --verification VERIFICATION_ID
python main.py research promote CANDIDATE_ID --to shadow --reason '进入影子观察' --evaluation EVALUATION_ID --verification VERIFICATION_ID
python main.py research promote CANDIDATE_ID --to production --reason '批准纳入正式计算集合' --evaluation EVALUATION_ID --verification VERIFICATION_ID
python main.py
```

`qualified/shadow/production` 均重新检查证据归属，以及保存证据与当前协议、完整依赖及计算代码的身份；共享逻辑或配置改变后不能沿用旧证据。股票候选主要两个期限需要至少 60 个有限逐日评价观察，并要求实际工程验证通过。这是样本与证据门槛，没有统一 RankIC 盈利阈值。正式批准后由同一个日更入口在正常年度目录补齐输出，再发布新集合。准入决定是因子工程计算资格，不能写成未来收益有效或模型增量已经证明。可选 `--external-evidence` 只附加项目内已提供材料，本工程不把外部结论冒充自己执行的模型实验。

## 评价与持续监控

正式单因子评价与冗余复查示例：

```bash
python main.py eval FACTOR_NAME --years 2025 2026 --horizons 1,3,5,10,20
python main.py dedup FACTOR_A FACTOR_B --years 2025 2026 --threshold 0.95
python main.py monitor
```

`eval` 每日期限使用成对有限股票：IC 为 Pearson，RankIC 为平均秩 Spearman，常数或样本不足记缺失。保留真实箱数与人数，不拆并列值来硬凑十组；单调性也是 Spearman。逐日记录包括覆盖、样本数、分层、ac1、未成熟/无效原因，汇总包含年度结果和日期 HAC 区间。ICIR 使用未年化日相关序列，兼容年化列明确采用 `sqrt(244)`；它不等于可执行收益或独立样本显著性。

生产 `eval` 的股票门槛来自 `rank.min_cross_section`，当前为 100；研究候选门槛来自封存的 `conf/research/protocol.yaml`，当前 `min_pairs=30`。比较时必须统一协议与共同有效网格，不能直接混用这两张表的评分。研究候选评价先按 1%/99% 缩尾、日截面 zscore、±10 截幅与声明方向变换，NaN 保留；生产 `eval` 报告的是落盘原始 value，报告明示两种表示。

生产评价保存 `state/eval/runs/<run_id>/daily.parquet`、`summary.json`、`run.json`，`state/eval/latest.json` 指向最新完整报告，原有运行不会覆盖。冗余复查先使用年块秩余弦快速召回，再精判共同覆盖、逐日秩相关及标准化 value 相关；同秩不代表同一非线性信息。相关阈值用于召回，不自动删除目录或退出对象；默认精判最多 2000 对，报告记录截断情况。

正式因子字典仅列批准的生产对象，并保存 `origin`、`research_review`、`candidate_id`、`recipe`、`input_watermark` 与 `coverage`。检查这些身份与当前发布范围，再使用质量统计；不要拿旧目录的最后日期或旧评价 JSON 当作本次状态。

完整日更自动执行 monitor。`monitor.jobs` 当前设为 4，在 CPU 配额和项目资源预算内并行检查独立对象；设为 1 可串行运行，结果口径相同。`monitor.tail_days` 当前设为 10：全部年度页脚核对 schema/行数/可见无穷极值，尾部逐键核对股票/日期轴、数值、rank、合法对齐前缀及未成熟标签，并核对 manifest 的 recipe/分区/已有文件身份。数据结构、无穷值和不正确标签属于硬错误，阻止新发布；常数、低覆盖、稀疏或覆盖突变是诊断，不据此自动反号或退休。页脚加尾部检查不能代替全历史唯一键和 PIT 检验。

默认不执行全部对象滚动收益评价。若需要对明确对象启用有限窗口，代码支持以下实际配置键；不要把无效别名当作已经启用：

```yaml
monitor:
  jobs: 4
  tail_days: 10
  rolling_enabled: true
  rolling_factors: [FACTOR_NAME]
  rolling_windows: [60, 120]
```

窗口上限 504 个交易日，只读本项目正式标签，未成熟样本不填零。监控报告保存到 `artifacts/monitor/runs/<run_id>/report.json`，`latest.json` 仅是最新指针。

`research splits` 生成完整日期轴的 purged walk-forward 划分计划，按最大 20 日标签保留 21 个交易日边界，默认 2018—2021 为初始历史、2022 起按季度前推。它没有执行模型训练。已有历史窗口已经用于研究，不能重新称作未触碰留出集；未来确认应冻结候选与协议后另记访问历史。

## 增量、缺口恢复与显式历史修改

正常新增交易日的 ST 记录只有在旧日期前缀的记录数和内容均未变化、并且所有新增事件都晚于已发布及已写覆盖边界时，才自动接受，股票键仍固定为 2115 个。旧日期补录、删除、修订或不可读来源不会被这条规则放行；接受证据保存在项目 ST 基线中。

普通日更回刷最近 10 个日历日；标签的回刷边界还按未来端点向前扩展。预热是日历天，计算锚点固定到输出年份；不能随增量起点重新初始化滚动或递推状态。父依赖先完成，失败子节点不标记完成。

已覆盖且早于冻结回刷边界的日期不会因新增未来输入自动重算。上游旧日期修订记入 `frozen_input_changes/history_recompute` 等报告；这保障日常输出的稳定使用，不等于证明供应商历史版本完整。缺失/损坏分区是输出修复，允许恢复冻结区内的实际缺口，并单独记录 `output_repairs`；不能把旧 coverage 当作文件仍然存在的证据。

当文件大小/mtime 改变时，已有内容基线用于确认是否只是同值重写；缺少足够内容基线不会仅凭页脚行数断言值未变。写盘前逐格相同则跳过覆盖。数值公式、共享数值逻辑、任务轴、延迟或环境身份变化需要显式历史处理，不能长期把旧新语义混在一个年分区。

维护命令示例，日期范围和对象名应替换为实际审核范围：

```bash
python main.py run FACTOR_NAME --start 2026-01-01 --end 2026-09-30 --refresh --jobs 8
python main.py rebuild --from-year 2018 --to-year 2026 --jobs 8 --dry-run
python main.py rebuild --from-year 2018 --to-year 2026 --jobs 8
python main.py rebuild --from-year 2018 --to-year 2026 --jobs 8 --resume
python main.py
```

重建默认强制重算；`--resume` 跳过已经验收完成的年块。完整重建成功后会执行项目历史裁剪规则和完整日更核验/发布。`--start/--refresh/--rebuild` 是有意历史操作，应提前确定范围、定义版本与验证依据；它们不是每日运行所需参数。不要用生产目录实际删除文件做研发验证；缺口、修订、跨年、串并行及 full/incremental 对拍在项目内隔离工作区完成。本次用户已完成备份，不再创建重复备份。

旧 `prune_factors.py --apply`、`prune_derived.py --apply`、`rebuild_manifest.py` 的写入模式以及 `test_incremental.py prepare/run/all` 已停用，保留只读预览/复核。正式对象退出走 `library status` 或研究生命周期；增量对拍走隔离的 `research verify`，不再通过裁切生产文件或手改 manifest 认证产物。

## 资源策略

配置从 12 进程起步、上限 20（`resources.max_jobs`），实际并行度不超过 cgroup CPU 配额。项目总预算是 90 GiB，容器若更小则采用更小限制；每计算进程地址空间默认 24 GiB，BLAS/数值线程默认 1，避免进程与线程乘法放大。项目总预算不是每个 Agent 或每个作业各 90 GiB。

**多路年份流执行器（2026-10-03）**：`main.py run/rebuild` 由 `fea/executor.py` 调度 —— driver 持 `state/daily.lock` 且是台账唯一写者；一个 `run_bounded` 包住 coordinator（单一内存护栏，全部年块同组）；年块 worker 一律 `--slice-worker --no-state-writes`（只算数、只写数据分区），台账由 coordinator 逐块提交；派生层与闸门在派发前由 driver 单点完成；耦合因子（deps 是别的因子）在所有年块后跑「尾批」，保证父因子历史先就位。车道逐块自适应（起点 `--jobs`、上限 `max_jobs`；加档前提：峰值 <38GB 且 CPU ≥0.65×车道，>0.85×护栏减半）。每次运行写资源台账：`state/runs/<stamp>/resources.json`（墙钟/CPU 利用率/峰值/逐块明细）与滚动 `state/resource_ledger.jsonl`，`python main.py resources` 查看。实测（20 因子 × 9 年）：12 车道 381s → 20 车道 243s（利用率 19%→34%）；24 车道因内存触发减半反而变慢——**当前硬件下利用率的上限由内存决定（约 1 GiB anon/车道）**。

生产按年度独立子进程释放缓存；候选研究在同一个研究进程中按年重新构造 Engine 并回收缓存。研究 `--jobs` 主要控制派生层预聚合并行，候选、父依赖和标签顺序计算，默认 1。大规模研究与生产验收统一安排资源。

按年度独立子进程释放历史缓存；派生预聚合与因子 worker 阶段不同时扩张。监测真实 cgroup 计费用量与共享页的 PSS，进程 RSS 合计只作诊断。计费护栏在有效上限的 90% 提前触发：有效上限 90 GiB 时为 81 GiB；因页缓存等也计费，不能仅看 NumPy 数组占用或主机总内存。达到护栏会停止本批子进程并保留失败/恢复状态。

降低资源可调整 `resources` 配置或 `FEA_DEFAULT_JOBS`、`FEA_MAX_JOBS`、`FEA_MEMORY_BUDGET_GIB`；单次预算不能超过 90 GiB。提高并发需要实际核对峰值与墙钟收益，不把旧版基准或主机 48 个逻辑线程当作当前可用核数。大型因子和候选验证可显式使用 `--jobs 4` 或 `--jobs 1`；多 Agent 修改代码可以并行，重计算应统一调度预算。

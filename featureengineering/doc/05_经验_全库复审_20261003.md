## 二、复审口径上的教训（会直接影响结论可信度）

1. **门槛数字必须事前冻结、看到结果不翻号**。G4（登记方向 IC）与 G7（风格增量）都按
   原 `higher_is_better` 判；本次没有因为"IC 只是弱"去翻号或调窗口——低 IC 量级只作背景，
   设统一 IC 淘汰阈值会误杀干净的基础因子。
2. **双期限规则要一次说清**：G4/G7 的"稳定"在本次被定义为「1/5 日两期限都满足正向且
   年度 ≥7/9」；只有单期限显著的对象进 Revise（11 个）而不是直接过。规则含糊会导致
   同一批数据得出两种结论。
3. **"工程通过"与"有效性"分开记账**：G1（复算一致）通过 ≠ alpha 合格；
   库里很多对象数据管道健康但信号不达标。文档里必须分开写，不能把补数据说成审批通过。
4. **基准/控制用途不豁免**：作为风格控制项入库的对象，复审时同样要过线；本次
   `benchmark_control_review` 逐项标注，控制用途与独立 alpha 资格分开记录。
5. **绿卡通道的边界**：用户新增的"基本因子绿卡"只要求经济含义清晰的十四类基础因子
   通过**基础门槛**（非空/非常数/无泄露），跳过 G4–G7。执行中坚持了"不为凑数降格"：
   411 个池对象里机械派生族（科目结构占比/年度同期差/复合交互）一律不计入，
   最终 37 个并入保留集；**文档必须逐项标注通道，绿卡 ≠ 严格通过**。

## 三、工程层的教训（踩过的坑，全部真实发生过）

1. **`definition()` 的哈希粒度是"整模块 AST"**。删掉模块里任何一个函数，
   该模块里**每一个**留存对象的定义哈希都会变 → 必须逐个 `version++` 再 `accept_existing`，
   否则 `production_specs` 直接拒载（`Approved definition changed`）。
   本次一次性对 94 个留存对象做版本自增 + accept 记账。
2. **AST 的 `col_offset` 是 UTF-8 字节偏移，不是字符偏移**。在含中文的源码行上做
   偏移替换时，不换算会在错误位置落刀：曾把 `_rsi_close(ctx,14)` 改成 `(ctx,314)`
   （幸好 apply 的 AST 等价检查当场拦下）。所有文本外科工具都要共享一个
   `_char_col()` 字节→字符换算函数（本次已统一）。
3. **共享盘上的运行期写盘 = 漂移事故**。全量复算 parity 跑到一半，另一个进程往
   `research/families/` 落文件（被 parity 的文件快照覆盖），整轮复算被判 `drift` 作废。
   规矩：**任何全量/复算运行期间，不写任何被跟踪路径**。
4. **页缓存会把 60GB 机器打爆**。7 路并发读 5 分钟 RAW 数据后，cgroup charged 冲到
   50.5GB（其中 30GB 是页缓存）触发护栏杀进程组。缓解手段已验证有效：
   ① 0.25s 独立护栏（charged≥50.5GB / anon≥48GB 停自己的进程组）；
   ② 对已完成的 derived 缓存做 `posix_fadvise(DONTNEED)` 定期回收；
   ③ 弹性阶梯：+2 路需 10 分钟窗口实测 + 峰值<38GB + CPU≥0.65×档位。
5. **`pkill -f` 会自杀**：模式串匹配到了自己的命令行，把本会话 shell 一起杀掉（exit 144）。
   杀进程用 `/proc` 遍历按 PID 杀，不要用宽匹配的 pkill。
6. **heredoc 里写 Python 多行字符串会被转义打坏**（`'\n'.join` 变成真实换行）。
   生成脚本一律写到文件再执行，不在 heredoc 里拼代码。
7. **动态工厂的四种形态**要分别处理：模块级 for 循环注册（momentum）、
   注册器函数风格（field_events 的 `add()`/`ll()`）、共享 FactorSpec 的工厂函数
   （quarterly_quality/financial_detail 的 `_spec`、tradability 的 `_register`）、
   conf 数据驱动（annual_field_expansion）。整厂删除和部分删除的版本策略不同：
   部分保留时版本站位要改在**共享站点**上（一次改全部剩余对象）。
8. **`__all__` 也是代码**：只清 `import` 行不剪 `__all__` 会留下死名字
   （本次已补齐处理器）。
9. **测试适配要跟着删除集走**：被删模块的测试文件删掉；部分删除的模块测试
   只删对应用例（如 field_markets 全删但 field_events 的助手测试保留）；
   读取删除集的测试（test_batch_factors 从 final_mechanism_review 动态读）最稳。

## 四、流程与协作教训

1. **先封存工具、再执行动作**：每个改动过的执行器都带源码哈希封存
   （`engineering_parallel_amendment_v13…v19.json`），出问题能回放到"哪一版干的"。
2. **计划-应用分离**：剪枝计划（候选源码 + sha 基线 + 版本表）先落盘、dry-run 校验
   基线一致，再 `--apply`；回滚点 `/tmp/cleanup_rollback_v15/` 全程可用。
3. **资源护栏写进每个执行器**，而不是靠人盯：0.25s 采样、双阈值、按进程组杀。
4. **用户催交付时的"缩短路径"要如实标注**：本次最终按用户指令跳过了
   沙箱 parity 复算、研究锚迁移与重发布（重量级计算），accept 无重算核验；
   交付文档逐项写清"执行了什么/什么没执行/为什么"，不把未做的步骤写成已做。
5. **偏差如实报，用户会接受**：绿卡目标 100–150、实际合格 37；如实报告口径与原因后
   用户明确回复"低于预期也没问题"。**凑数降格才是真错误**。

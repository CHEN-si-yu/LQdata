# 财务因子工程经验与检查模板（R13，2026-10-06）

本文面向后续财务候选设计、实现和结构审核，记录本轮固定的数据时钟与缺失合同，以及实际初审留下的边界。它总结的是工程和会计描述经验，不宣称任何候选具有 alpha，也不把 H7 结构检查当成收益检验。政策口径以[准入政策 v3](03_准入_政策_v3_20261006.md)和对应冻结件为准。

## 1. 财务信号同时有三个时钟

财报因子要分别处理报告期、披露版本时点和日频生效日，不能把三者混成一个“最新值”。

1. **报告期时钟**：`end_date` 决定报告期及季度。收入、费用、现金流通常是财年累计 YTD；资产负债表通常是期末时点值。
2. **披露版本时钟**：本轮模块将 PIT 定为有效 `max(ann_date, f_ann_date, end_date)`；至少一个公告字段有效，PIT 不早于报告期。日 T 只可见 PIT≤T 的版本。后续修订从自己的 PIT 起影响状态，不能改写此前历史。
3. **日频生效时钟**：把 PIT 映射到项目交易日历中的下一交易日一次。节假日、周末公告聚到同一个交易日时，保留该日 PIT 较晚的事件；不要在候选公式或下游再加第二次 next-session 延迟。

这套语义可对照[financial-quality 实现](../research/families/r13gc_financial_quality_v2.py)和[financial-composition 实现](../research/families/r13gc_financial_composition_v1.py)中的 `_report_table`、`_map_daily`。项目上游只保留当前可读的历史版本时，哈希能证明本次读了哪些字节，却不能证明供应商保存了每一次历史修订；缺版本时不要自行造版本。

## 2. 先限定标准报告，再选版本

对本轮财务 GC 源，先过滤 `comp_type=1`、`report_type=1`，然后才对 `(股票, 报告期, PIT)` 做整行版本选择。先去重再过滤，会让另一报告类型在相同键和 PIT 下覆盖标准报告。这个过滤次序已写入两套实现和[冻结的 H7 源合同](../artifacts/research/round13_20261006/financial_rescreen/financial_gc_next7/h7_source_operand_contract_v1.json)。

同一标准键、同一 PIT 有多行时，按源物理顺序保留最后一整行。金额 NaN 或无穷也留在这条最新行里：它表示最新可见披露的金额无效，应清空旧金额。不能先删掉坏金额，再退回较早版本。不同 PIT 的修订各自保留，不能只取文件当前最大 PIT 并回填整段历史。

在每个单表内单独形成“最新报告期前沿”：按股票和 PIT 顺序维护已见报告期的前缀最大值。需要两张表的公式必须有各自明确的同钟规则；不得拿 A 表旧报告去搭配 B 表新报告。当前前沿所需字段缺失或非有限时输出 NaN，不回退到更旧报告期。若公式是同表 ratio，分子、分母必须来自该表同一报告期前沿和同一 PIT 可见版本。

## 3. YTD 差分和严格 TTM

累计 YTD 源不能把四季记录直接相加。对报告期季度 q：

- 单季流量：Q1=`YTD(Q1)`；Q2/Q3/Q4=`YTD(当前季度)-YTD(同财年精确前一季)`。
- TTM：Q4=`YTD(当前财年 Q4)`；Q1/Q2/Q3=`YTD(当前季度)+YTD(前财年 Q4)-YTD(前财年同季度)`。

公式中的每个槽位都必须是报告期精确匹配、在当前 PIT 已披露且有限的金额。缺 Q2 不能把 Q3 当成第二季，缺前财年 Q4 不能用更早年度替代，也不能用部分和、0 填补或把其他季度压缩进窗口。Q4 的特例只用本财年 Q4 YTD；非 Q4 则需要当前 YTD、前财年 Q4 YTD 和前财年同季度 YTD 三项。实现细节见上述两个 module 的 `_strict_ttm`。

建议实现前用逐季度 literal rows 手算 Q1–Q4，至少验证 Q4、非 Q4、缺任一精确季度、晚到修订和 NaN 清空；只比对某个聚合结果或窗口尾数不足以发现错季。

## 4. 报告陈旧、分母和符号边界

本轮财务候选报告期年龄超过 550 个自然日时输出 NaN；恰好 550 天仍有效。年龄从当前前沿报告期末日计算，不是从最后公告 PIT 计算。warmup 负责让序列在 2018 输出起点前取得完整历史窗口，它不能许可放宽季度完整性。

不要把不同冻结式子的分母边界合并成一个“项目默认值”：

| 本轮构造 | 分母条件 | 恰好 1,000,000 元 |
|---|---|---|
| Financial-quality v2 比率 | 有限且 `>=1e6` | 接受 |
| Financial-composition v1 比率 | 有限且 `>1e6` | 拒绝 |
| FI06 FY revenue 分母 | 有限、正且 `>1e6` | 拒绝 |

Quality 实现在 `_safe_positive_ratio` 使用 `>=`；composition 使用 `_safe_ratio` 的 `>`；FI06 冻结定义也写的是严格大于。这个差异是冻结定义的一部分，不得为方便复用 helper 而改变。分子为真 0 或负值时按候选合同保留；有限 0 与缺失 NaN 不同。不要把费用、退款、亏损或现金流反转自动截成 `[0,1]`。

## 5. GC 与 C 的职责不同

按 v3，**GC 是透明描述量**：有明确的会计、价格或物理含义，不主张 G4/G7 预测方向；其用途和缺失规则需事先冻结，并仍须过真实工程、覆盖、非常数、结构查重等对应审核。**C 是预测候选通道**：需要事前方向并按冻结的较宽统计路径提供初步预测证据；它仍不等于长期有效或独立样本外确认。GC 不可被用来改名接纳一个方向型候选的统计失败；C 也不能因为名字像会计项目就自动免除 alpha 审核。详见[政策 v3 的 GC/C 条款](03_准入_政策_v3_20261006.md)。

财务量的数值公式恒能由自身分子、分母重构。例如 `A/B` 可用 A 与 B 自身解释；这属于定义身份，不自动证明它与库内其它因子重复。v3 的结构审核同时覆盖现库、历史删除和已研究近邻；逐项比较单位、报告期、分母、PIT、掩码、变换及生命周期。既有未晋级研究也要查，但不能将其虚称为生产因子或正式退休。仅注册未运行的同式构造与已实际研究的构造应分别记录。对 GC，不要把结构审核报告为回报回归或方向性 alpha 检验。

H7 是冻结控制下的 accounting-overlap 描述检查，不是回报回归、因果测试或 G4/G7。目标、base8 和预注册的现有会计控制用同一日期的共同有限样本；原值标准化 OLS 与 average-tie-rank 检验都保留所有冻结列。遇到秩亏应报告并将该日排除出可解释日计数，不能删控、换样本或改阈值救结果。

**目标自己的原始操作数不放入 H7 控制列。** 原始操作数的有限/缺失、0、正负和 unique 计数是独立数据诊断；它们不是“现有库近邻”。例如目标 `X/Y`，把 X、Y 或 X/Y 的任意代数分解临时塞成 H7 控制，只会把恒等式冒充增量检验。应把两包证据分开：冻结的现有库控制检验结构混淆；source-component 诊断解释值域、零值和可重构关系。

## 6. 少数股东权益与 R12 权益字段不能互换

R12 的 `total_hldr_eqy_inc_min_int` 是含少数股东权益的合并所有者权益合计；`total_hldr_eqy_exc_min_int` 是不含少数股东权益的归母/母公司股东权益。R12 `r12gc_equity_turnover` 用含少数股东权益的合计作分母，`r12gc_de` 也用该字段；`r10gc_yoy_net_asset` 用排除少数股东后的权益序列。三者经济口径不同，不能只因字段名字都带 equity 就替换。

财报中的 `minority_int` 还与两种 equity 字段存在分解关系：在字段口径一致时，含少数股东权益减去不含少数股东权益可重构少数股东权益。这个恒等关系要求明确报告表、PIT 和原字段是否同源；不应把单独的代数重构诊断当成 H7 现有库重复证据。

本轮少数股东/资产候选与旧 R12GD 精确公式相同，但旧记录是注册未运行候选，不是 production/published 因子。应分别写出注册状态、运行、批准、发布；“catalog 有同式”并不等于“生产已有该因子”。候选定义和旧记录分别见[当前 R13 定义](../artifacts/research/round13_20261006/definitions/gc_financial_quality_v2/candidate_minority_interest_assets_point_v2.json)、[R12GD 候选](../artifacts/research/catalog/candidates/r12gd_minority_int_ta_v1_75612fd636c2d892.json)，R12 两个 equity 字段的具体分母可参阅[equity turnover 定义](../artifacts/research/catalog/candidates/r12gc_equity_turnover_v1_4cba36560ca472e5.json)、[D/E 定义](../artifacts/research/catalog/candidates/r12gc_de_v1_d4cd33b978d63b0a.json)和[净资产同比定义](../artifacts/research/catalog/candidates/r10gc_yoy_net_asset_v1_2a57af1e5c40492f.json)。

- **FC02** `TTM(c_paid_invest)/TTM(stot_out_inv_act)`：该目标实际 H7 作业 `returncode=0`；主审初审文件称，在冻结现有库控制下未见近线性重构。这是有界结构证据，不代表一般独立性或 alpha。run `r_f5224febfe6b4207a7472265edea33fe` 的目标重建逐格匹配 float32 值与 NaN；2123 个可估日期全部满秩，最小/中位共同样本 N 为 1204/1706。见[FC02 H7 作业资源/退出码](../artifacts/research/round13_20261006/jobs/h7_fc02_frozen_actual_v1/result.json)及[FC02 H7 主审初审](../artifacts/research/round13_20261006/verdicts/fc02_chief_H7_preliminary_v1.json)。仍需 same-run trueG1、baseline208 hardG5、冻结候选互相重叠和主审终裁；该文件明确 `final_admission=false`。
- **FB06** `point(lt_eqt_invest)/point(total_nca)`：该目标实际 H7 作业 `returncode=0`；主审初审称在冻结控制下未见近线性重构，属于结构检查范围内的有限结论。run `r_66afec8cc9144bc48d33818443b38d3f` 重建匹配 4,490,145 个目标单元（含 NaN），2123 个可估日期全部满秩，最小/中位共同样本 N 为 1201/1526。见[FB06 H7 作业资源/退出码](../artifacts/research/round13_20261006/jobs/h7_fb06_frozen_actual_v1/result.json)及[FB06 H7 主审初审](../artifacts/research/round13_20261006/verdicts/fb06_chief_H7_preliminary_v1.json)。文件同样保留 trueG1、hardG5、冻结候选重叠和终裁等后续项；`final_admission=false`。
- **Minority interest / assets**：实际 H7 作业已 `returncode=0`，主审已重算 NPZ 和 sidecar 哈希；目标全部 4,490,145 个 float32/NaN 单元重构一致。2123 日原值及排名模型全部满秩，共同样本最小/中位 N 为 1405/1967，平均 R²分别约 0.0752/0.1520。在固定现有库控制下未见近线性重构；含/不含少数股东权益的原始操作数仍单独诊断，不能混入控制列。见[实际退出码](../artifacts/research/round13_20261006/jobs/h7_minority_frozen_actual_v1/result.json)、[主审 H7 初审](../artifacts/research/round13_20261006/verdicts/minority_chief_H7_preliminary_v1.json)和[冻结控制计划](../artifacts/research/round13_20261006/financial_rescreen/financial_gc_next7/h7_control_plan_precalc_v2.json)。这项结构初审尚不等于准入。
- **Total profit / revenue**：这是 GC 结构去重的反例。该候选与已发布 `r12gc_opm_ttm` 的平均日度绝对 Spearman 为 `0.9916102045`，超过 v3 GC 重复阈值 `0.98`，故经正式生命周期记录退休。见[total-profit 重复裁决初审](../artifacts/research/round13_20261006/verdicts/total_profit_chief_duplicate_preliminary_v1.json)和[官方退休记录](../artifacts/research/round13_20261006/closeout/total_profit_official_retirement_v1.log)。理由是新增信息重复，不是方向反转、alpha 失败或可事后改式的许可。

三项冻结 H7 已各自实际完成，结束的是这项联合重构流程；不能从 H7 结构结果推导 1/5 日收益。源重构通过、数值相关性低或模型 R²不高，都不替代 G1、G5、候选间查重和最终生命周期裁决。原始交付时只有 FC02、FB06 完成的历史说明保留在阶段证据中，此处已更新实际进展。

## 8. 后续研究者检查模板

每个财务候选在冻结前逐项填写并保存源和定义哈希：

```text
[ ] 候选属于 GC 描述量还是 C 预测量？若是 C，方向/期限是否事前锁定？
[ ] 列出原始表、原始字段、单位、源频率、报表类型定义和所需依赖。
[ ] 说明报告期时钟、披露 PIT、日频生效时钟；PIT 需要哪些有效公告列？
[ ] 先筛 comp_type/report_type，再以整行做 code/period/PIT 版本选择。
[ ] 同 PIT 物理最后行若金额 NaN/Inf，会不会保留并清旧值？有无 synthetic collision test？
[ ] 说明同表最新 union frontier 的定义；缺/坏当前前沿是否输出 NaN 且不回退？
[ ] 对 YTD 源逐季写出单季和 TTM 公式；证明槽位精确、有限、无缺季压缩或零填充。
[ ] 多表、多字段是否同报告期、同 PIT、同钟？如不能证明，标 HOLD。
[ ] 固定 next trading session 一次、报告年龄阈值（>550 天失效）和 warmup。
[ ] 按该版本的冻结定义声明分母边界：>=1e6 还是 >1e6，并测恰好等于边界。
[ ] 分开处理 0、负数、NaN、Inf；不要无证据截断或把 NaN 当 0。
[ ] 检查 active/published 与 historical/deleted/registered-unrun 近邻；逐个比较公式、分子、分母、时钟、类型、样本与生命周期。
[ ] 把恒等分解/原始 source operands 放在源解释诊断，不塞进 H7 作为库控制或重复证据。
[ ] 事前冻结现有库 H7 控制列表、共同有限样本、raw/rank 计算、最小 N 和秩亏解释规则。
[ ] 记录“工程通过”“结构不重复”“统计证据”“批准”“发布”为不同状态。
[ ] 文献只支持机制/描述定义；不得把海外长期回报结论写成 A 股短期限 alpha 保证。
```

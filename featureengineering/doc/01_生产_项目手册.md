# 项目手册

对齐 2026-10-07 的直接生产入口。首次阅读从[根 README](../README.md)开始；完整参数见[入口命令说明](01_生产_命令接口.md)，历史材料见[分类索引](README.md)。


含 R16ML1 GPU 候选的首次补历史、跨年指定运行和全量重算使用 `--jobs 1`。其全局 nonblocking GPU 锁只允许一个候选 worker；实际冻结环境与数值合同见 [R16交付记录](04_研究记录_R16交付_20261008.md)。


## 每日运行与全量重算

```bash
python /root/autodl-fs/featureengineering/main.py
```

无参数执行增量。启动后加载启用注册对象，读取上游 `stock_daily` 最新交易日，按本地交易日历规划缺口，然后计算。首次运行没有覆盖时会补历史；增加注册因子后只补新增对象及必要依赖。重复执行且源截止未推进时，已对齐对象跳过。

在项目根目录执行以下操作：

| 场景 | 命令 | 行为 |
|---|---|---|
| 每日更新 | `python main.py` | 补新日期、缺口、标签未成熟尾部 |
| 强制全量 | `python main.py rebuild --jobs 1` | 重算全部启用对象的默认历史范围 |
| 指定对象 | `python main.py run momentum_20 roe_ttm` | 选择对象并自动包含父依赖 |
| 指定年份重算 | `python main.py rebuild --from-year 2025 --to-year 2026 --jobs 1` | 重算指定年份，不删除其他年份 |
| 历史源修订 | `python main.py run momentum_20 --start 2026-09-01 --end 2026-09-30 --refresh` | 重算明确日期，保留范围外结果 |
| 中断恢复 | `python main.py` 或 `python main.py rebuild --resume --jobs 1` | 按断点补剩余部分 |
| 查看计划 | `python main.py run --dry-run` | 规划但不生成因子、不提交覆盖 |
| 查看注册与覆盖 | `python main.py list` / `python main.py status` | 显示规格类别及台账摘要 |

默认起点读取配置 `default_start`，现为 2018-01-01；默认终点为源最新交易日，显式终点也不超过源截止。年参数会覆盖同侧的日期参数。输出轴按交易日取交集。请求子因子时，父因子范围可能扩到输出年锚点及预热所需日期。

`--dry-run` 仍会初始化日志、状态目录与锁文件；它不会生成因子分区或提交因子覆盖。`list/status` 读取台账，不扫描输出数据，不等于分区完整性检查。

## 生产执行与跳过

当前路径为 `main.py → fea/production.py → 原 Engine 数值计算 → Store 年度落盘`。`fea/progress.py` 统一展示进度。公式、截面 rank、PIT 和年份锚点沿用原实现。

规划依据是 `state/<name>.json` 的日期覆盖与实际年分区。正常跳过只读取必要页脚；覆盖丢失或分区元信息不匹配时读取日期列检查每天行数。缺失或页脚不可读的分区加入补算。没有代码、输入或输出内容指纹，也不进行全历史值扫描，因此不会自动发现公式改变或同尺寸的历史内容修订；这些修改使用显式重算命令。

新源日期到来时，标签按 `forward_days` 对应的未来端点回算尾部，能更新上一年尚未成熟的日期。普通因子不会每天自动回刷 10 天。配置里的 `compute.revision_days`、`kernel_version` 等历史工具字段不代表当前入口启用了对应旧流程。

父依赖完成后才派发子因子。父分区补算或刷新时，请求范围内对应子因子会进入更新计划。公式修改须明确选择重算对象和受影响的下游对象，不能依靠 `version` 自增触发自动历史重建。

分钟、筹码等派生层按需构建，同一层用独占构建锁；已有缓存按源文件修改时间判断更新，不计算内容哈希。财务层仅在相应依赖需要时加载，按请求规格的字段并集复用。

## 断点、失败与恢复

年分区原子写入，主进程收到成功结果后立即提交对应覆盖。强制重算派发前会撤销待算日期的旧覆盖，并记录 `pending_years`，避免中断后把旧文件误认成新结果。

- 日更或全量中断：保留已完成分区，再运行默认入口；恢复全量也可用同一选择范围的 `rebuild --resume`。
- 某因子失败：日志显示失败，该因子及被阻塞的依赖节点不标记完成；其他成功任务照常保存。修复原因后再次运行。
- 计算进程异常退出：程序及时结束并保留已提交断点，再次运行补齐。Ctrl-C/SIGTERM 会清理本批计算进程。
- 因子分区缺失或不可读：实际运行发现后补算；无需手改台账。不要在正式输出里人为制造故障做测试。
- 台账丢失：可以从已有输出的日期列和每天行数恢复覆盖；这不等于逐键、逐值审核。保留状态可减少后续规划开销。
- 第二个入口写同一输出：独占锁失败并返回退出码 2。判断是否运行以 `flock` 为准，锁文件存在不代表有活进程，不删除锁文件绕过互斥。

再次执行不带 `--resume` 的 `rebuild` 会重新强制重算，不能用它恢复已完成的大批全量。普通任务失败返回 1；成功或全部跳过返回 0；用户中断返回 130。详情与异常栈查看启动时打印的日志。

## 日期、股票与落盘合同

固定股票轴读取 [universe_frozen.tsv](../conf/universe_frozen.tsv)，当前冻结样本为 2115 只股票；这不是动态全市场股票名单。日期轴从配置起点按交易日完整对齐。`FactorSpec.start` 是真实值起点，之前的对齐前缀沿用规格填充，通常为 NaN；完整轴不能通过省略空行替代。

| 对象 | 相对路径 | 列与类型 |
|---|---|---|
| 股票因子 | `data/factors/<name>/year=YYYY/data.parquet` | `trade_date:string, stock_code:string, value:float32, rank:float32` |
| 收益标签 | 与股票因子相同 | 四列相同，`rank` 恒为 NaN |
| 市场因子 | `data/market_factors/<name>/year=YYYY/data.parquet` | `trade_date:string, value:float32` |

股票/标签按日期与股票键排序，市场按日期排序。计算 float64，落盘 float32，当前压缩为 zstd。股票因子 rank 沿用原 Engine 的 winsor 与截面排名口径；`higher_is_better` 是方向元数据，不在生产中自动反号。限日期更新按交易日替换并一次合并旧年分区，保留范围外数据；完整年分区可直接原子写入。

股票轴、列序、数据类型、缺值语义、排序、目录及年度分区不能因优化而改变。[因子注册与落盘](01_生产_因子注册与存储.md)说明新增规格与生产来源。

## PIT、标签与预热

价格水平使用未复权价及当期已披露信息；收益类使用未复权价格与当时累计复权因子，不用最新前复权基准改写历史。停牌价格状态与真实成交掩码分开。普通因子不能读取未来、向后填充或使用全样本定标。

财务按公告可得日与源保留版本构造 PIT；TTM、单季和同比按报告期计算。日频来源按项目频率及延迟合同处理。供应商未保存的历史版本无法由代码保证重建，保留既有来源限制。

正式标签为 T+1 开盘买、T+1+h 开盘卖的后复权收益，h 为 1、3、5、10、20 个交易日；两端需真实成交，尚未成熟的值和标签 rank 为 NaN。标签允许未来信息，仅用于离线目标；不能拿未来成交条件筛选普通因子的信号日。

`warmup_days` 单位为日历天。预热沿依赖链展开，锚点固定到输出年份，不能让本次增量起点改变滚动或递推初始状态。

## 并行与进度

配置默认 12 个持久计算进程，上限 20，实际不超过 CPU 配额。任务按因子×年份领取，优先同年较长预热对象，连续任务复用输入；跨年或连续 16 个任务后释放缓存。数值库每进程单线程。单进程地址空间默认 24 GiB，项目内存预算上限 90 GiB，容器更小则采用更小限制。在途任务根据 cgroup 计费/匿名内存和每任务预留限制派发，当前 `worker_memory_gib=3`。

这些值在 [config.yaml](../conf/config.yaml) 的 `resources` 中配置；`--jobs` 选择并行上限，内存不足时实际在途任务会减少。当前没有旧年份流执行器、`resources` 命令或旧式逐次资源台账。

`--progress auto` 在标准错误为终端时显示总进度与逐因子 tqdm 条，因子名对齐，状态包含等待、计算、完成、跳过、失败及阻塞，单位为目标交易日。已有日期计入初始完成数，刷新日期会重新进入待算。年任务完成后进度推进；大任务内部不是逐行刷新，预计时间仅按已完成任务估算。

`--progress plain` 显示时间戳、①—④阶段摘要、对齐序号/名称、已有行数与覆盖、本次日期数、写入/新增行数和耗时，每 10 秒报告在途任务。`--progress off` 保留阶段摘要。长名在窄终端可能截断，`list` 显示完整名称。后台运行建议：

```bash
python main.py --progress plain > logs/console.log 2>&1
```

该重定向示例要求 `logs/` 已存在。仅重定向标准输出而保留终端标准错误时，自动模式仍可显示进度条。详细计算日志写入 `logs/run_factors_*.log`。

## 目录、状态与验证

| 路径 | 职责 |
|---|---|
| `main.py` | 唯一生产 CLI |
| `factors/`、`research/` | 内置公式及历史研究转正实现 |
| `conf/`、`artifacts/research/catalog/candidates/` | 配置、冻结股票池、生产清单及转正定义 |
| `fea/production.py`、`fea/progress.py` | 规划、并行、断点与展示 |
| `fea/engine.py`、`fea/store.py` | 原有数值执行与存储合同 |
| `data/` | 正式输出和按需派生缓存 |
| `state/<name>.json` | 因子覆盖、分区和未完成年份 |
| `state/production_last_run.json` | 正常调度结束后的本次摘要；不能假设异常退出也会更新 |
| `logs/`、`artifacts/tests/` | 计算日志和隔离验证产物 |
| `doc/` | 当前说明与历史分类导航 |

历史研究、审核、评价与发布模块仍在，但当前 `main.py` 不暴露旧命令、不更新旧发布指针或生成旧字典。下游直接使用原年度文件合同；如下游依赖旧发布指针，须明确对接该需求，不能把陈旧指针视为本次生产完成。

验证在项目内沙箱进行，上游只读。相关命令、20 个小样本场景、5 个真实因子逐值/字节一致结果，以及未执行全库生产的边界，统一见[生产重构验证记录](01_生产_重构验证_20261007.md)。维护边界见 [AGENTS](AGENTS.md)；本手册替代[旧版手册](08_历史_旧版项目手册_20261007前.md)的日常运行规则。

## 固定数据合同

- 固定股票池为 `conf/universe_frozen.tsv` 中 2115 只主板股票，不改变名单来提高覆盖率或评价表现。固定池包含既有幸存者/事后 ST 筛选，报告准确限定结论范围。
- 输出日期轴从 `default_start=2018-01-01` 起按本地交易日历完整对齐，首个交易日 2018-01-02；更早原始数据只用于预热。
- 股票/标签保存四列 `trade_date:string,stock_code:string,value:float32,rank:float32`；市场保存 `trade_date:string,value:float32`，每天一行。统一年度 Parquet，股票每日完整股票键，NaN 不能通过少写行替代。
- `FactorSpec.start` 表示真实值起点，默认 NaN 对齐前缀保留完整日期轴且 rank 恒为空。新候选不能关闭时间轴对齐。仅有真实源字段证据支持时才可零填充，不靠注释推断“早年无值”。
- 数学使用 float64，只在 Store 转换 float32。普通因子禁止未来位移、向后填充、全样本标准化或最新前复权基准；价格状态与真实成交分开。
- 正式标签为 T+1 开盘买、T+1+h 开盘卖的后复权收益，h=1/3/5/10/20；两端真实成交，未成熟保持 NaN，rank 恒为空。未来成交掩码仅供离线评价，不能用作信号日筛选。
- 财务按公告可得日与保留版本构造 PIT，TTM/单季/同比按报告期；源频率/延迟读取项目内合同和观测。不能把供应商未保存的历史版本当作已重建。
- 声明全部直接输入和父依赖；读 Context，走 Engine/Store，不在公式中任意访问文件。父节点先计算，失败节点不标记完成。
- `warmup_days` 是日历天，按完整依赖链取值；锚定输出年，不能让本次增量起点改变滚动/递推初始化。

## 资源与多 Agent

- 默认 12 计算进程起，上限 20（`resources.max_jobs`），受 cgroup CPU 配额限制；单次项目预算不超过 90 GiB，容器更小时取更小限制。
- 执行器（2026-10-03）：`main.py run/rebuild` 走 `fea/executor.py` 的多路年份流 —— K 路年份块并行、单一内存护栏、车道按实测自适应（加档前提：峰值 <38GB 且 CPU ≥0.65×车道；峰值 >0.85×护栏则减半）。实测（20 因子 × 9 年，60 GiB 容器、另有 I/O 竞争）：12 车道 381s/19% → **20 车道 243s/34%** → 24 车道触发减半反而 372s；**瓶颈是内存（约 1 GiB anon/车道），不是核数**。每次运行落资源台账（`state/resource_ledger.jsonl` + `runs/<stamp>/resources.json`，`main.py resources` 可查）。
- 每计算进程地址空间默认 24 GiB，数值线程默认 1。生产按年度独立进程释放缓存；候选研究在同一进程中按年重新构造引擎并回收缓存。派生层与 worker 并发阶段分开，避免股票/日期拆分破坏窗口与完整截面。
- cgroup 计费内存与 PSS 是主要证据，RSS 合计仅诊断。有效预算留 10% 计费余量；90 GiB 的计费护栏为 81 GiB，页缓存也计入。
- 多 Agent 可分文件开发，运行大型生产/候选/验证作业时统一分配资源；每个 Agent 不能各领 90 GiB。调高并发要有实际墙钟/峰值证据，不能把旧基准直接当作本次测量。

## 因子研究方法学与硬规则（R2/R3 沉淀，2026-10-02）

本节是两轮研究（10 个事前 Idea、56 个候选、2 个因子入库）沉淀下来的**强制规则**。
新增/审核因子时按本节执行；与其它章节冲突时以本节为准。

### A. 准入门槛：G1–G7，缺一不可

| 门 | 内容 |
|---|---|
| G1 工程 | `research verify` 的截断复算与两阶段增量重放**逐值一致**（float32 精确、NaN 相等）；无 Inf；每日 2115 键完整 |
| G2 覆盖 | ≥60% 交易日有 ≥100 只有效票；真实值起点与声明一致 |
| G3 非常数 | 有效交易日中 ≥95% 的截面 std > 0 |
| G4 信号 | **declared** RankIC 在 h=1 或 h=5 落在 HAC 95% 区间之外，且分年一致**为正** ≥7/9 |
| G5 新增信息 | 与任一现有正式因子 \|rho\| ≤ 0.95；>0.9 必须论证 |
| G6 稳定 | 无单一年份主导；不出现"只有 1–2 年有效" |
| **G7 增量** | 见 B 节 —— 控制通用风格因子后的 Fama-MacBeth 系数显著且**符号与登记方向一致** |

**通过 G1–G7 只是进入审核的最低底线，不等于"有效因子"，更不等于盈利性证据。**

### B. G7 增量检验（R3 确立）

逐日截面回归 `label_rank ~ [控制因子秩] + 候选秩`，取候选系数的跨日 HAC t 值。

通用控制集：`momentum_120, short_term_reversal_5, vol_120, idio_vol_60, log_mv, turnover_std_20, bp, roe_ttm`；
波动率族候选额外加入 `idt_rv_daily, id2_parkinson_vol, var_95_20`。

**必须用已入库因子定标**（否则无从判断门槛松紧）。当前参照系：
`s26_structure_side_hhi_v1` t=+12.21/+7.29；`s26_liq_up_fragility_v1` t=−9.02/−8.28；
`r2own_v2_trend_persistence_v1` t=+4.74/+4.53；`r3b_intraday_rv_skewness_v2` t=+9.34/+9.13。

**方法学演进（不要退回去）**：`: 相关性阈值 |rho|<0.9` → 发现不足 → `残差 IC` →
发现会被残差方差衰减、会误杀真因子 → **`Fama-MacBeth 系数 + HAC t + 已入库因子定标`**。

### C. 方向翻转是流程性风险，必须制度化（R3 确立）

**Lead 与执行 Agent 各自独立犯过同一个错**：拿原始尺度的增量数字去和声明尺度的 RankIC 比较，
漏做 `higher_is_better` 翻转，把"方向支持、增量偏弱"误读成"符号反转的代理"。

1. 任何增量类指标在解读前**必须先过** `higher_is_better`：true → `declared = raw`；false → `declared = −raw`。
   **`evaluation.json` 的 `summary[].rankic` 已经是 declared 值，不得当 raw 使用。**
2. 报告里所有增量类指标（FM 系数与 t、残差 IC、正交后残差、分层收益）**必须 raw / declared 双列**；
   只报一列的报告不予审核通过。
3. 判定一律用 declared 列：一致为**正** ≥7/9 年 → 方向得到支持；一致为**负** → 被证伪；正负混杂 → 无稳定信号。
   **禁止**事后反号、禁止改 `higher_is_better`、禁止换新版本把方向扳回来。稳定反向属**样本内发现**，
   只能作为下一轮的独立事前假设（须用 C 节之外的独立确认设计：机制独立陈述 + 时间分块同号 + 期限外推 + 参数化不同 + 正交后同号）。

### D. 已知的伪发现模式（审核时必须主动排除）

1. **高原始 IC、实为既有因子投影**：R2/R3 已抓出 6 例。典型：声明 RankIC +0.0320（9/9）但控制风格后 t=−2.66 符号反向
   （换手波动率代理）；+0.0197 控制动量后 t=+1.48（动量代理）；+0.0121 与股息率 \|rho\|=0.876（股息率代理）。
2. **低两两相关、高联合解释力**：某候选与全库 491 个因子 max\|rho\| 仅 0.183，但每天 34–42% 截面取 0、
   只有约 243 个不同取值；这种**半离散阶梯变量**可被多个连续风格因子的线性组合重建，加入控制后系数归零。
   **只看 max\|rho\| 会漏掉这类重复。**
3. **敏感性变体实为前视变体**：某候选把发布滞后从 15 个交易日缩到 5 个，增量 t 从 +1.02 跳到 +2.52；
   实测供应商发布滞后约 13 个交易日 ⇒ 5 日滞后使用了当时读不到的数据。
   **审核敏感性变体必须检查其可用性假设，而不只是看数字。**
4. **同一 Idea 下两个机制是同一轴的正反写法**：`rv_skewness` 与 `signed_jump` 日截面 rho=−0.9582，
   却被同向登记 ⇒ 必有一错。**机制集合必须在预登记阶段做两两相关性预判**；高度共线时只登记一端。
5. **零填充与 NaN 是两个不同的东西**：某族候选在零填充口径 9/9、NaN 条件口径**符号翻转**。
   稀疏事件因子必须同时报两种口径，符号不稳健者不得准入。

### E. 运行与协作纪律

1. **内存护栏用不可回收量**：`grep '^anon ' /sys/fs/cgroup/memory.stat`。
   **不要用 `memory.current`** —— 它含可回收页缓存（实测 80 GiB 里只有 51.8 GiB 是不可回收的），
   曾导致误杀一条已跑 40 分钟的 run。护栏：anon > 85 GiB 暂停新任务，> 100 GiB 强制降载。
2. **被 kill 的 run 只留下 `begin.json`、没有 `run.json`**：任何"按目录存在判定完成"的工具都会把
   残缺 run 当成已完成并**直接拿半成品去 evaluate**，静默产出错误结论。**只在 `run.json` 存在时才算完成。**
3. **共享交付目录禁止递归删除**：`dsh_scratch/round2|round3` 曾在 2026-10-02 06:53 被本队之外的并行会话
   整棵删除。交付物必须**三处落地**：服务器交付目录（写入前 `mkdir -p`）+ 容器本地 `/tmp/` + 本机镜像。
   任何 Agent 不得对共享交付目录做 `rm`/`mv`/`find -delete`，含"只删自己的"。
4. **inode 是硬资源**：`/autodl-fs/data` 是 AutoFS，**总 inode 仅 200,000**，而每个 research run 会创建
   私有 phase 派生缓存（约 100–140 个 inode）。开工前查 `df -i`，IFree < 3000 停手上报。
   **结构性建议：为本工程产物单列存储，或调大该挂载的 inode 上限。**
5. **不要改共享源码**：`fea/*.py`、`research/*.py` 顶层、`conf/config.yaml`、`conf/production.json`
   参与 `source_identity_hash`；并行期间改动会作废其它 Agent 已完成 run 的 `same_source_identity`。
   （唯一例外：Lead 执行 `research promote` 时会写 `conf/production.json`，这是授权动作，须提前通告。）

### F. 框架已知缺陷（研究期需绕行，待正式修复）

1. `fea/upstream.py::Upstream._audit_columns` 的日期列白名单只认
   `ann_date / f_ann_date / trade_time / trade_date / suspend_date / date`。
   `stock_pledge_stat` 只有 `end_date`（周频快照截止日）⇒ 任何设置 `audit_cutoff` 的 `research run` 直接抛
   `ValueError`。研究期处置：在候选模块进程内**局部声明**该数据集的日期列，并**直接调用 `Upstream._audit_frame`**
   实测证明截断确实生效（截断前后行数、`end_date > cutoff` 全丢、`<= cutoff` 全留）。
   **只比"截断前缀 == 全量前缀"不够** —— 若截断是 no-op，该比较会平凡通过。
   建议修法：在 `_audit_columns` 增加**显式声明**的数据集→日期列映射，不要放宽成任意日期列都接受。
2. `fea/resources.py` 对每个计算进程强制 `RLIMIT_AS = 24 GiB` 且**无环境变量可覆盖**（提高须改
   `conf/config.yaml`）。`research verify` 的三阶段在同一进程内累积虚拟地址空间，
   导致依赖大内存读取的族（如 `stock_cyq_chips` 筹码、分钟线）**verify 无法通过**（实测抛 `ArrayMemoryError`）。
   建议：让 `RLIMIT_AS` 可按进程/按族显式声明。
3. `stock_pledge_stat` 只有 `end_date`、无发布时刻合同；`stock_dragon_tiger` 的买卖列存在**年际整块互换**
   （2018 年约 94% 的行），导致现有正式因子 `dragon_tiger_org_net_20` **在 2018 年被系统性污染**。
   该因子本轮未改动（需按版本/审批流程处理），此处记录为**待处理发现**。

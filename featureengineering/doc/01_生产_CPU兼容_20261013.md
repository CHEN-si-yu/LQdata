# CPU 容器兼容与验证（2026-10-13）

用户本轮授权每日更新、CPU 兼容修改与台账核查。未改变因子公式、数据合同或模型训练配方。

## 修复

R16ML1 v2 已有无 CUDA 自动回退 CPU 的路径，但原 `_single_gpu_lock` 无论设备均争抢全局 `r16ml1_gpu.lock`。多个 CPU 年度 worker 会互相拒绝，甚至被其他 GPU 任务阻塞。

改为先在计算 worker 惰性初始化 Torch 并探测设备，再进入 `_compute_device_lock`：CUDA 保留原全局锁；CPU 以实际派生缓存路径、任务年份和审计截止日组成缓存锁。不同年度或隔离缓存允许并行，同一缓存重复写入仍拒绝。原 GPU 路径仍要求跨年重算 `--jobs 1`；CPU 路径可使用默认自动资源保护。

硬件漂移继续按既有政策告警，缓存训练身份继续严格核对。未改变 SEED、float64、单线程、deterministic、训练期或训练目标。缓存身份中原有 `adapter_sha256` 属记录性字段，设备锁变更不触发重训或全历史重建。

## 已完成的兼容验证

- `tests/test_r16ml1_device.py` 两项测试通过：GPU 互斥、CPU 不争 GPU 锁、CPU 同缓存互斥、不同年/不同缓存可同时取得锁，以及释放后重新取得锁。
- 本轮 CPU 实际训练与预测：PyTorch `2.11.0+cu128`、无 CUDA、计算线程 1、interop 线程 1、确定性开启；在生产 24 GiB 地址空间限制下完成。
- 固定输入重复训练的状态 SHA256 相同；保存权重恢复后的 100 个 float32 预测逐值相同、全部有限。
- 实测证据及每日生产结果：`/autodl-fs/data/check/incremental_20261013/`，重点见 `cpu_smoke_result.json`、`logs/device_lock_tests.log` 和最终 `LEDGER.md`。

验证不承诺 CPU 与历史 GPU 的浮点末位逐位一致；这项边界与 2026-10-09 的设备漂移政策一致。

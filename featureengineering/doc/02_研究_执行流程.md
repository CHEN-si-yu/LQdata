# 股票因子挖掘与入库

本技能面向需要按明确步骤工作的 Agent。目标是产出可解释、可复算、能服务横断面排序/回归的因子，以及能追溯的失败记录。代码跑通、IC 显著、相关性低三者中的任意一项，都不足以证明可以入库。

先确认用户当前任务。用户说暂停或停止时，不启动新方向、不重启旧作业；整理资料不等于恢复研发。用户重新授权研发后再执行以下流程。子 Agent 只在用户授权并行研究时启用，模型与推理配置遵从用户要求和实际可用环境。

## 1. 接手前先读与核验

项目实际根目录为 `/autodl-fs/data/featureengineering`。用户有时省略路径中的 `data`，不要为此另建一份工程。所有研究产物放在项目内，上游与下游只读。

按顺序阅读：

1. [维护约定](AGENTS.md)、[项目手册](01_生产_项目手册.md)、[生产入口](01_生产_命令接口.md)。当前代码与维护合同优先于旧轮次命令。
2. `resources/调研阅读指南.md`、`resources/索引/研究主题导航.md`、字段与证据说明；需要具体主题时再打开相应资源。
3. 正式注册来源 `fea/production.py`、`conf/production.json`、`factors/` 和研究转正实现；用实际注册清单判断现库，不用旧文档中的数量。
4. `research/catalog.py`、`research/runner.py`、`research/evaluation.py`、`research/lifecycle.py`；了解定义、运行、证据和状态的关系。
5. 当前有效准入政策。R14 历史授权下为 [v4](03_准入_政策_v4_20261007.md) 与 [v4.1](03_准入_截面区分度_v4.1_20261007.md)。后续用户或正式新政策可以替换它们，不自行改阈值。

开始计算前核验：数据最新日期、股票轴、已启用股票因子、市场对象和标签数量、内存、磁盘与 inode、存活作业、已有候选版本和结果。日期和数量都注明测量时间。

本轮曾使用 2115 股票、2018-01-02 至 2026-09-30 共 2123 评价日。这是历史冻结样本，不是永远有效的默认值。未授权时不改变股票池来提高覆盖。

接管 R14 时阅读 [交接快照](04_研究记录_R14暂停交接_20261007.md)。排障或设计具体因子时阅读 [方法与失败案例](02_研究_设计方法与案例.md)。

## 2. 选题：先机制、字段和去重，再计算

对每个方向先回答四个问题：

| 问题 | 必须交付的证据 |
|---|---|
| 测量什么经济或会计状态？ | 一段机制说明、适用对象、预期方向或描述用途、可证伪条件 |
| 本地真的能测吗？ | 实际表、列、年份、单位、频率、可得时间、缺失规则；不能只有网上字段名 |
| 与现库有什么不同？ | 最接近的正式因子及失败家族、代数关系、排序关系、信息来源和时间结构 |
| 最小验证是什么？ | 不读收益标签的质量/识别探针及停止条件 |

优先寻找：相同经济变量的创新项、状态转移、条件反应、期限结构、结构份额、同业传播、路径顺序或时间分布。改窗口、反号、乘常数、单调变换、同一机制换名称通常不是新方向。

论文、比赛、GitHub 或平台用于提出假设。取得原始公式及假设，再映射到本地字段；论文用了交易逐笔、报价、期权或基金持仓时，不能用日线代理后仍宣称复现原构念。网上字段文档只能辅助解释，真实供应商字段需要本地样本和官方披露对账。

研究员可以建议方向，主审独立决定：`duplicate`、`source_unavailable`、`construct_invalid`、`design_hold`、`quality_probe`。没有输入或构念不成立，应尽早关闭，不浪费全期回归。

## 3. 固定研究契约

在看到本版本收益结果前写入不可覆盖的定义与 SHA256：

```yaml
direction_id: Fxxx
channel: C或GC
mechanism: 测量对象及经济意义
formula: 精确公式，含排序、平局、边界、分母与缺失处理
parameters: 唯一主版本参数；允许变体及预算须事前写明
expected_direction: 正或负；GC写明确描述含义
target_horizons: [1, 5]  # 以真实定义为准
sources: 表/列/单位/年份/可得日/版本选择
universe_and_dates: 固定轴与评价范围
warmup_days: 自然日，说明为什么足够
neighbors: 最接近的现库对象与代数重构关系
family_controls: 真正进入回归的固定补控及缺失语义
quality_gate: 覆盖、非恒定、识别、最小样本门槛
falsifiable: 哪些结果会否定机制或增量
resources: 内存/磁盘/inode/并行预算
```

方向负相关失败后不能翻号；也不能改窗、选择好年份或临时改成 GC。实现错误可以修复为新版本，但保留旧代码、结果、失败原因、修复前后差异及重新检验记录。同一方向修复不重复计数。

矩阵尚未生成时不能声称它已被冻结。先封存源码、输入与契约；生成后另记矩阵 SHA 与时间，不倒填为事前证据。

## 4. 分级计算与数据时点

依次扩大：公式手算/合成反例 → 4–12 股票源样本 → 50 股票一个年度 → 全股票一个年度 → 全评价期 → 正式 Engine 验证。每层按事前门槛决定是否升级；清楚记录试验目的，质量探针不读取 alpha。

先检查公式能否区别于邻居。例如构造相同收益多重集但顺序不同的路径，检查路径因子是否改变；用已知参数模拟检验估计量恢复；在常数参数的 null 中统计误识别率。优化收敛、正 Hessian 不代表经济参数被识别。

数据规则：

- 财务按实际公告可得日进入，日期级数据保守取下一交易日；报告期用于单季/TTM/同比，不是可用时间。使用声明的报表范围和版本选择，保留供应商历史版本不足的限制。
- 财务最新整份报告变成缺失或无效时，应按契约清空，不能悄悄从更旧版本逐字段拼回。跨表必须符合所声明的报告期/前沿匹配。
- TTM 需要完整、匹配的 YTD/FY 桥接。缺失、未披露、经济真实零值分开；没有依据不填零。
- 股价的前后端点是否实际成交必须显式检查。转填价格的恢复交易收益可能跨多年停牌，不能当作一天收益。
- 未来标签可以用于评价，不能进入因子构造、图构建、标准化、参数或股票筛选。标签合同查当前维护文档。
- 月末只能用已完成且日历确认的月份；不能把未来月末或当前不完整月当历史端点。
- 数据修订时点无法复原时要披露；原始读取截断验证不能制造供应商不存在的历史 vintages。

正式实现声明所有直接输入和父依赖，通过 Context/Upstream 读取。直接读原始 Parquet 的研究扫描可用于初筛，但不能绕过正式的日期可得性截断。每年顺序读取、释放缓存，保留相同公式；先做年度适配器与初筛逐值对拍。

## 5. 质量、方向和增量审核

先 G2/G3，后标签。报告全期有效单元、活跃日、单股日、2–99 股日、至少 100 股日、截面常数、Inf、异常值、最早有效日和年度覆盖。因子长期为零时不能只报有行率。

R14 v4/v4.1 的审核摘要如下，裁决时仍读完整政策：

| 门槛 | C：预测候选 | GC：事前经济描述因子 |
|---|---|---|
| G1 | 正式相同版本原始可得性截断、两阶段增量、完整键轴/value/rank/NaN 精确一致 | 相同 |
| G2 | 全期 ≥20% 日期有 ≥100 有效股票；低于30%标稀疏 | 完整报告覆盖，由主审按描述用途审核；不套用 C 的预测门槛 |
| G3 | ≥100 有效股截面中 ≥90% 非恒定 | 相同分母，≥95% 非恒定 |
| G4 | 原声明方向 h1 或 h5 的日度 RankIC：HAC 双侧80%下界>0，t>1.281552，≥4正年度 | 不要求预测显著；必须有明确可识别的描述用途 |
| G5 | 当前全部正式股票因子平均日度绝对 Spearman ≤.95；>.85解释 | <.98；.95–.98专项审查 |
| G7 | 与 G4 同一期限：BASE8 两核系数和t均正，强t≥1、弱t≥.25，各≥3正年，强核≥4正年 | 不因低 IC 拒绝，但结构去重和经济意义仍须成立 |

BASE8：`momentum_120, short_term_reversal_5, vol_120, idio_vol_60, log_mv, turnover_std_20, bp, roe_ttm`。

两核是项目实际 rank/model 横断面回归，具体变换和 HAC 参数按当前 evaluator，不能凭名称另造算法。h1 的 IC 和 h5 的回归不能拼成通过；不以股票日单元作为独立时间样本。报告逐年与逐年剔除，解释单年驱动。

补充控制必须真的进入联合回归。辅助函数的 `extra_controls` 可能仅写元数据，检查实现。经济最近邻、组成腿、原始事件强度、样本选择和未缩放版本往往比泛化的 BASE8 更能揭穿伪增量。固定家族补控把两核增量都消除/反转时，不能仅凭低相关入库。

控制缺失导致样本变化时，另跑相同 complete-case 样本的 BASE8，区分“筛样改变”和“控制吸收”。不为通过删控制、把未知填零或忽略秩缺陷。日期常数与截距共线，应按事前设计做日期分组，不硬塞横断面 FM。

G5 逐日共同有限样本至少100，处理平局，先求每日日度绝对 Spearman 再汇总。报告最高邻居和接近 ±1 的日期占比。227 个旧缓存只代表历史基线；新入库后必须补比对当前现库。低相关不能替代机制审核。

C 本轮均标 `weak_evidence=true`；仅新门槛通过者标 `relaxed_admission=true` 并报告旧/新双判定。强t<1.65、弱t<.5、补控明显收缩或年度不稳时标 `weak_increment=true`。反复使用历史样本不是独立样本外确认。

## 6. 正式验证、主审、生产

严格区分状态：`初筛通过 → 正式计算完成 → 工程验证通过 → 主审允许入库 → 注册生产 → 实际落盘且对拍通过`。

1. 写纯 family builder 与 idea/family/candidate 定义，用 Catalog 登记。GC 也按登记要求提供诊断期限，不能以空列表规避 schema；这些期限不改变 GC 的经济描述定位。
2. 保存登记工具返回的真实 candidate ID。不要猜 hash、复用旧 ID 或混用 v1/v2 结果。
3. 隔离正式运行。初筛和正式输出核对轴、float32 值与 NaN、标签；差异必须定位到输入/日期/公式，不能用“足够接近”掩盖端点缺陷。
4. 对同一封存 run 执行 evaluate 与真实 raw-read cutoff、两阶段增量 verify。修改共享 `fea/*.py` 或 `research/*.py` 可能改变 computation identity：有待验运行时避免修改共享核心。
5. 主审独立读取证据，写每个门槛、邻居、缺陷、证据等级及拒绝/允许的原因。`lifecycle.promote` 检查工程证据链接，不自动证明统计准入。
6. 允许后顺序走 `qualified → shadow → production`。用实际登记后的 factor 名调用 `main.py`，只计算批准对象及其依赖。不要为研究重加 `main.py research`。
7. 检查生产年度 Parquet 的完整键、列序、dtype、有效值与 rank，并对拍正式封存结果。原始 value 不随 rank 的缩尾而改写；遵循 Store 的实际合同。
8. 更新主审台账和文档，附源码/输入/矩阵/年度文件 SHA、run/evaluation/verification ID、生产对拍、资源峰值和局限。只有此时才能说“已入库且落盘”。

命令入口见下面模板。执行前核对本地 `--help`，尤其旧工具的固定截止日期和9年轴假设，不能照抄到新样本。

```bash
# 在项目根目录；变量值来自登记结果，不能猜测
PY=/autodl-fs/data/miniconda3/bin/python
R14=artifacts/research/round14_20261007
$PY scripts/research_cli.py idea --file "$IDEA_FILE"
$PY scripts/research_cli.py family --file "$FAMILY_FILE"
$PY scripts/research_cli.py candidate --file "$CANDIDATE_FILE"

# JOB_ID 必须新建；估计资源后填写预算。正式任务通过 bounded 调度。
$PY "$R14/bounded.py" --id "$JOB_ID" --reserve-gb 8 --disk-gb 3 -- \
  "$PY" -u scripts/research_cli.py run "$CANDIDATE_ID" --end "$END_DATE" --jobs 1

# 以下均须在 bounded 包装下执行；参数来自真实产物
$PY "$R14/g5_complete.py" "$VALUES_NPY" "$G5_OUTPUT_PREFIX" --workers 8
$PY "$R14/formal_compare.py" "$RUN_ID" "$VALUES_NPY" "$COMPARE_OUTPUT"
$PY "$R14/formal_evidence.py" "$RUN_ID" "$EVIDENCE_OUTPUT" --jobs 1

# 主审允许并完成生命周期登记后，依当前资源约束包装生产命令
$PY main.py run "$REGISTERED_FACTOR_NAME" --end "$END_DATE" --jobs 1
$PY "$R14/production_compare.py" "$RUN_ID" "$PRODUCTION_COMPARE_OUTPUT"
```

`formal_evidence.py` 是 R14 工具，固定 cutoff 为 2025-12-31；`formal_compare.py` 等包含历史轴约束。新研究范围须先检查并另做版本，不覆盖已被历史证据引用的脚本。晋级参数参阅 `scripts/research_cli.py promote --help`；不省略 chief 裁决。

## 7. 资源与协作

用户本轮硬约束：总内存 <60GB；共享磁盘总量200GB、inode总量200000。不能把默认生产90GiB预算当本轮授权，也不能把进程 RSS 当总内存。

- 检查 cgroup `memory.current`、进程组峰值、磁盘可用量与 `df -i`；page cache、共享内存与其他任务也占预算。
- R14 `bounded.py` 当前总预留≤36GB，已计费内存+新预留<52GB；磁盘留25GB加在途预算，inode留20000加每任务1500。55GiB的90% guard约53.15GB，是提前停止线。reserve 是调度估计，不是进程硬限额。
- 数值线程置1。重任务先 jobs1；分钟年度读取曾达到4.68GiB，截断过滤还可能额外复制，不能据一次成功盲开并行。
- 使用 mmap、分块流式和年度 Parquet；避免每股票/每日一个小文件。共享只读缓存需校验轴和 SHA，控制临时副本。
- 任一资源不足先排队或减并发；不为利用率目标挤破硬上限。席位活跃率与 CPU 利用率分别报告，不能混为“超过50%”。
- 用户要求五研究席位时可轮转五个长期角色；实际环境若只允许总共4 Agent，则主审+3子 Agent，同时工作的上限不能伪报为5。完成一个再补一个，有价值且有预算的方向优先。
- 子 Agent 仅交付研究证据，不能自行生产晋级、改共用政策或重构共享核心。暂停时检查进程组，先停止自己创建的作业并保留日志，不杀其他工程。

## 8. 低级 Agent 的任务单与汇报

每次只给一个主方向和一个固定公式，不给“随便找几个有效因子”。可以直接使用：

> 研究方向【ID/机制】。先读现库最近邻【名称】和本地源【表/字段】。不得改变上游/下游或生产注册。先交付精确公式、单位/PIT/缺失规则、去重说明及事前门槛。获准后依次做无标签样本探针、单年覆盖、全期固定方向初筛。家族补控【列表】须真实联合回归且报告共同样本 BASE8。资源【预算】。保留每次失败和 SHA；没有完整证据不得声称入库。数据或识别不成立就停止该方向，说明原因。

每次返回统一字段：

```text
方向ID / 版本 / 通道 / 状态
公式、机制、最接近现库、源与可得日
已执行层级、轴、覆盖、非恒定、异常、参数识别
声明方向 h1/h5 IC、HAC区间、逐年、LOYO
BASE8两核；固定补控两核；秩缺陷与共同样本对照
当前全库G5及最高邻居
正式run/evaluation/verification ID与精确对拍
源码/输入/值/证据路径与SHA
内存/磁盘/inode/耗时；失败原因；下一步
```

统计“完成独立方向”“允许入库”“实际落盘”“失败未入库”“待审”“计算中”时，说明口径。重复提案、修复版、同机制窗口不计新方向；缺源失败不称为回测失败。复审保留旧裁决但不重复计完成数。股票因子计数不含市场和标签。

如果重新启用本轮持续挖掘，历史目标为完成独立方向>128 或正式股票因子>500，或用户明确停止；这条旧目标本身不授予当前自动开工权限。停止时保存交接，不以达到数量为由跳过证据。

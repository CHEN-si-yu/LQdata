## 重构场景与数值合同

首轮 [test_production.py](../tests/test_production.py) 的 19 个测试全部通过，日志见 [production_tests.log](../artifacts/tests/production_tests.log)。覆盖：

- 全量/增量与串行/并行逐值一致，同源重复跳过且分区修改时间不变。
- 新源日期、标签成熟、跨年新增分区与上一年标签回算。
- 新因子注册仅补新增对象，子因子父依赖及预热自动补齐。
- 初次生成中断、已有旧文件的强制重建中断、逐分区断点恢复。
- 缺失/损坏分区、状态丢失恢复、写入独占锁和进程 SIGKILL。
- 按日期刷新保留后续数据，对齐起点前缀，派生缓存复用/更新。
- dry-run 不提交因子覆盖、不调用指纹，名称对齐及失败状态保留。

后续针对终端被数值警告打乱的问题，新增第 20 个测试：在真实计算进程中触发全 NaN 均值及自由度不足，确认两类 RuntimeWarning 被忽略、其他 RuntimeWarning 和同文字 UserWarning 仍保留、输出数值不变。新增后完整生产场景测试 20 项全部通过，耗时 80.322 秒，结果见 [production_warnings_tests.log](../artifacts/tests/production_warnings_tests.log)。

## 规划耗时与边界

重构验证时，全库 279 对象、2511 年任务的空输出计划耗时 0.35 秒；真实重复小样本 2 对象、0 任务耗时 0.25 秒，见[计划日志](../artifacts/tests/production_all_plan.log)和[重复运行日志](../artifacts/tests/production_style.log)。这些是当时的样本结果，实际耗时随输入、覆盖、I/O 和资源改变。

上述验证生成的因子均在项目 `artifacts/tests/` 隔离命名空间，未以正式输出做删分区故障测试。重构验证没有启动正式全库生产，也不证明历史数据已全库验收。用户后续自行启动的生产进度不计作这些测试结果。

## 复现

在项目根目录，使用共享解释器：

```bash
/autodl-fs/data/miniconda3/bin/python -m unittest discover -s tests -p test_production.py -v
/autodl-fs/data/miniconda3/bin/python scripts/verify_production_sample.py --out artifacts/tests/production_parity_rerun
/autodl-fs/data/miniconda3/bin/python scripts/run_tests.py
```

前两个分别执行生产场景和真实样本对拍，第三个执行全工程测试。真实样本脚本会计算并写入指定项目内隔离目录。研究源码稳定性守卫要求测试期间不编辑其监测范围；不能一边修改源码一边把全套守卫结果当作稳定版本验收。

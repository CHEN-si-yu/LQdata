# ★ main.py 全量 / 增量重构接口规范（成熟版）

> **来源**：`main.py` 源码 + 各子命令 `--help` 实测输出（2026-10-05 实测）。
> **用途**：作为模块②（因子工程）的标准操作接口，覆盖首次全量、增量更新、定向重算、断点续跑、
> 审计核验、沙箱试跑、资源管控七类场景。

---

## 〇、一句话总览

```bash
python main.py                      # 日常增量：自动读上游 → 计算 → 检查 → 发布
python main.py rebuild --jobs 1     # 首次全量 / 重算全部（按年，可断点续跑）
python main.py run <factor> ...     # 只跑指定因子
```

**`main.py` 是模块②的唯一入口**；因子是否"在库"由 `conf/production.json` 决定，
`main.py` 经 `fea.release.load_library()` 读取，并由 `fea/catalog.generate()` 生成
`artifacts/catalog/factors.csv` 与 `factors.json`。

## 二、★ `rebuild` —— 全量重建接口（完整参数）

```bash
python main.py rebuild [--jobs N] [--from-year YYYY] [--to-year YYYY]
                       [--factors NAME ...] [--resume] [--dry-run]
                       [--adaptive] [--budget-bytes BYTES] [--streams N]
                       [--sandbox DIR] [--force]
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--jobs` | `0` | 总车道预算（0 = 自动） |
| `--from-year` | 无 | 起始年 |
| `--to-year` | 无 | 结束年 |
| **`--factors`** | 无 | **只重建指定因子**（可多个，空格分隔） |
| **`--resume`** | 关 | **跳过已验收完成的年；默认强制重算** |
| `--dry-run` | 关 | 只出计划不落盘（实测输出"待补/已就绪"逐年清单） |
| **`--adaptive`** | 关 | **逐块反馈自适应并行**：每块按实测计费内存峰值调下一块的 `--jobs`（目标带 **0.50–0.85×** 预算；证据落 `artifacts/rebuild_adaptation/`） |
| `--budget-bytes` | `0`→`60e9` | 自适应目标带的内存预算（默认 **60 GB = 容器上限**） |
| **`--streams`** | `0`=auto | **并行年份流数**；auto 规则：**待算 ≥2 年 且 总车道 ≥6 时取 2，否则 1**；`--jobs` 是**总车道预算**，按流均分 |

### ★ 推荐用法（按场景）

```bash
# 1. 先看计划（不落盘）
python main.py rebuild --dry-run

# 2. 首次全量，稳妥单车道
python main.py rebuild --jobs 1

# 3. 全量 + 自适应内存 + 双年份流（推荐用于 32 核 / 60GB 容器）
python main.py rebuild --adaptive --budget-bytes 60e9 --streams 2

# 4. 断点续跑（跳过已验收完成的年）
python main.py rebuild --resume --jobs 6

# 5. ★ 只重建本次新入库的 3 个因子（实测用法）
python main.py rebuild --factors \
    r9f_breadth_intraday_slope_x_beta_v1_51445f98a0907e8f \
    r9a_sec_own_rv_beta_v2_ef77e079dd4478fe \
    r11u4_flow_intensity_x_surprise_v1_1cec9f0321fe52c1 \
    --jobs 6 --streams 1

# 6. 指定年份区间重算
python main.py rebuild --from-year 2024 --to-year 2026 --jobs 6

# 7. 沙箱试跑（不碰生产 data/ 与 state/）
python main.py rebuild --sandbox /tmp/sbx --jobs 4
```

### 实测行为（2026-10-05 三次真实重建）

```
本次实测：rebuild --factors <3 个新因子> --jobs 6 --streams 1
  年块执行：退出码 0 · 10 块 · 峰值计费内存 40.69 GiB / 60 GiB · 进程组 CPU 345s
  ✔ 事后对账通过：5 个因子的台账覆盖均达 2018-01-02 ~ 2026-09-30
  台账比对：变化 0，恢复/新增 21，消失 0 → 报告 state/runs/<ts>/report.json
  ✔ 上游无历史变化（无被冻结的回填）
  ⚠️ 27 个 (因子,年) 分区内容真的变了（跳过写盘 2 个）→ 明细见 partition_rewrites
  ✔ 「历史不可变」：无任何已覆盖的历史日期被排入计划
  资源账：墙钟 244.9s · CPU 344.8s / 32 核 → 整轮利用率 4.4% · 计算阶段 6.4%
  内存峰值 charged 40.7 GiB（护栏 54.0 / anon 上限 46.0）· anon 9.3 GiB
  任务 29 个 · 6 任务分钟 · 1 流 × 6 车道

随后 daily 全库刷新：180 项 · 墙钟 120.3s · 峰值 charged 38.6 GiB
  发布完成：a26fa3db740edddd · 180 项
```

**★ 关键观察**：`rebuild` 自带**三重安全网**
① **事后对账**（台账覆盖是否达上游截止日）② **台账比对**（变化/恢复/消失计数）
③ **历史不可变校验**（已覆盖的历史日期不得被重排）
⇒ **它不是"暴力重算"，而是带对账的受控重建。**

## 三、`run` —— 增量更新接口

```bash
python main.py                       # 无参数 = 日常增量（推荐）
python main.py run                   # 同上
python main.py run roe_ttm yoy_revenue   # 只跑指定因子
```

`run` 的隐藏参数多为内部编排（`--slice-worker` / `--plan-file` / `--results-file` /
`--no-state-writes` / `--coordinate` / `--run-dir` / `--cutoff` / `--chunk-timeout` /
`--jobs-min` / `--jobs-max` / `--run-mode`），**日常无需直接使用**；
对外可用的只有 `--streams N` 与公共的 `--sandbox` / `--force`。

**增量语义**：`main.py` 无参数运行 = **读上游 → 计算缺失/过期部分 → 检查 → 发布**，
末尾输出与 `rebuild` 相同的会话资源账。

## 四、★ 审计与核验接口（三件套）

### 4.1 `dayhash` —— 历史不变 + 增量==全量
```bash
python main.py dayhash [--date YYYY-MM-DD] [--days N] [--all] [--scope production]
                       [--baseline TSV] [--out DIR] [--jobs N] [--verify]
                       [--sandbox DIR] [--force] [factors ...]
```
| 参数 | 说明 |
|---|---|
| `--date` | 截止日（默认 = 上游最后一天） |
| `--days` | 记录最近几个交易日（默认 **7**） |
| **`--all`** | **全历史模式：每个因子的全部交易日（自对齐起点至截止日），用于重建前后逐格对拍** |
| `--scope production` | 只做正式生产对象 |
| **`--verify`** | **与 `.prev.tsv` 基线台账比对，报出发生变化的 (因子, 日期)** |
| `--jobs` | 并行进程数（默认 1，**最多 2**） |
| `--out` | 输出目录（默认 `artifacts/dayhash/YYYY-MM-DD`） |

**用途**：① 证明"历史不可变"；② 证明"增量结果 == 全量结果"。

### 4.2 `audit-pit` —— 前视 / 滞后审计
```bash
python main.py audit-pit [--group G ...] [--end DATE] [--jobs N] [--sample N]
                         [--tol T] [--static-only] [--sandbox DIR] [--force] [factors ...]
```
| 参数 | 默认 | 说明 |
|---|---|---|
| `--group` | 无 | 按类别过滤 |
| `--end` | 上游基准表最后一天 | 审计到哪一天 |
| `--jobs` | **12** | 复算并行数（**★ 内存敏感，别乱加**） |
| `--sample` | 中点+尾部 | 抽几个交易日做**截断复算** |
| `--tol` | `1e-4` | 复算相对容差 |
| **`--static-only`** | 关 | **只做静态扫描（秒出）** |

### 4.3 `dedup` —— 冗余检测
```bash
python main.py dedup [--years Y0 Y1] [--threshold T] [--out DIR] [--sandbox DIR] [factors ...]
```
输出 **\|ρ\|≥阈值 的重复簇 + 完全重复对**。

### 4.4 其它核验命令
| 命令 | 要点 |
|---|---|
| `check` | 基础体检：universe / 值域 / 格式 |
| `eval` | IC / RankIC / ICIR / 分层 / 覆盖 |
| `monitor` | 数据质量与成熟标签监控 |
| `resources --last N` | 资源台账（默认最近 20 次；`0`=全部） |
| `prune-history` | 清理配置起点之前的产物（**先预览**） |
| `status` / `list` | 已落地统计 / 因子与本地进度 |
| `docs` | 刷新因子字典与 README |

## 五、`library` 与 `research` —— 定义与准入

```bash
python main.py library {bootstrap,list,accept,accept-common,status}
python main.py research {idea|family|candidate|run|evaluate|verify|promote|list|splits|selection|batch}
```

**生命周期（`research/catalog.py`，实测）**：
```
STATES      = ("candidate", "qualified", "shadow", "production", "paused", "retired")
TRANSITIONS = candidate → {qualified, retired}
              qualified → {shadow, paused, retired}
              shadow    → {production, paused, retired}
              production→ {paused, retired}
              paused    → {shadow, production, retired}
              retired   → {}
```
**★ 逐级不可跳级。** `promote --to {qualified,shadow,production}` **强制要求同源 eval + verify**：
```
research/lifecycle.py:62
  ValueError: Qualification requires actual evaluation and full/incremental/causal verification IDs
```
**`--to production` 会写 `conf/production.json`（`approve_candidate`）** —— 这是"入库"的唯一动作。

**★ 完整入库链路（本次实测）**：
```bash
# 1) 三级晋升
python main.py research promote <cid> --to qualified --reason "..." --evaluation <e_...> --verification <v_...>
python main.py research promote <cid> --to shadow    --reason "..." --evaluation <e_...> --verification <v_...>
python main.py research promote <cid> --to production --reason "..." --evaluation <e_...> --verification <v_...>
# 2) 刷新目录
python main.py docs
# 3) 全量生成面板
python main.py rebuild --factors <cid> --jobs 6
```

## 六、★ 标准作业流程（SOP）

### A. 日常增量（每日）
```bash
python main.py                       # 增量计算 + 检查 + 发布
python main.py status                # 确认落地
python main.py dayhash --days 7 --verify   # 确认历史未变
```

### B. 新因子入库
```bash
python main.py research promote <cid> --to qualified  --reason "..." --evaluation <e> --verification <v>
python main.py research promote <cid> --to shadow     --reason "..." --evaluation <e> --verification <v>
python main.py research promote <cid> --to production --reason "..." --evaluation <e> --verification <v>
python main.py docs
python main.py rebuild --factors <cid> --jobs 6
python main.py dayhash --all --scope production --verify   # 逐格对拍
```

### C. 全量重建（换季/上游变更）
```bash
python main.py rebuild --dry-run                      # 先看计划
python main.py rebuild --adaptive --budget-bytes 60e9 --streams 2
python main.py dayhash --all --scope production --baseline <重建前台账> --verify
```

### D. 断点续跑（中断后）
```bash
python main.py rebuild --resume --jobs 6
```

### E. 提交前核验
```bash
python main.py check
python main.py audit-pit --static-only                # 秒出静态扫描
python main.py audit-pit --sample 5 --tol 1e-4        # 抽样截断复算
python main.py dedup --threshold 0.95
```

## 七、资源与护栏（实测口径）

| 项 | 值 |
|---|---|
| CPU | **32 核**（`cpu.max = 3200000/100000`） |
| 内存硬上限 | **60 GiB**（`memory.max`） |
| 内存护栏 | `charged` **54.0 GiB** / `anon` **46.0 GiB**（`rebuild` 自报口径） |
| 用户口径上限 | **55 GB** |
| 实测峰值 | 本会话最高 **59.51 GiB**（99.2% 硬限）—— 由单个 8.78 GB 的"单年"run 造成 |
| 冷却判断 | **`memory.pressure avg10`**（0.00 = 无压力）；**不要看 `memory.current`**（含可回收页缓存） |
| 不可回收量 | **`grep '^anon ' /sys/fs/cgroup/memory.stat`**（`doc/AGENTS.md` §E.1 强制） |

**★ 关于"利用率"**：`rebuild` 自带利用率报表（本次 **整轮 4.4% / 计算阶段 6.4%**），
目标 50%。**单条定向 rebuild 天然低利用率**（作业数少）；全库 rebuild 才会拉高。
**提高利用率的正确方式是"更多独立因子在同一次 rebuild 里"**，而不是调大 `--jobs`（会撞 I/O 争用）。

## 八、已知框架边界（勿"顺手修"）

1. **`stock_pledge_stat` 只有 `end_date`**，而 `Upstream._audit_columns` 白名单不含它
   ⇒ 任何带 `--cutoff` 的 run 会抛 `ValueError`（BRIEF §11.1 有绕行方案）
2. **market 标量不可能产出 RankIC** —— `evaluate_run` 有硬 `is_market` 分支
   ⇒ 市场因子只能作状态，交付物必须是股票形态 `(T,C)`
3. **`var_95_20` 不在 177→180 个因子中** ⇒ `AGENTS.md` §B 的波动率族 G7 三控制规格**不可完整执行**
4. **`research verify` 单条全区间需 20–41 分钟**（实测）⇒ 准入成本 ≈ 两次全区间计算
5. **写 `/autodl-fs/data` 的 SFTP 可能静默丢失** ⇒ 经 `/tmp` 脚本写入并换会话复核

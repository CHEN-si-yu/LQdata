### 需求从哪里来

近期模型全截面IC为正而实际头部仍亏损，实战10-28的Top40明显偏小市值，四大行在池内却排在后部。需要研究的是“什么时候由小盘/高弹性转向大盘/红利/低beta，且何时应持现金”，不能直接把事后银行上涨写成固定买入规则。当前50市场对象主要提供市场状态，已有行业领导持续性和小大盘成交额份额变化；缺少某个明确风格量之前，先检查已有344股票暴露及50市场控制是否已包含相同信息。

现有市场对象入库证据常围绕固定池等权股票h5均值，它与银行相对小盘收益、组合尾部损失不是同一目标。未来应区分市场整体、风格相对和个股暴露三类需求，明确由模型侧如何使用：市场`(T,)`进入条件编码/仓位政策，个股`(T,C)`暴露进入排序，二者交互才能定向改变银行与小盘的相对排名。只增加同日所有股票共同的线性截距，不会改变截面排名。

### 评价设计与交付要求

先冻结目标：整体市场收益、未来可执行端点的风格收益差、组合尾部事件分别定义，不在结果后择优。输入可使用T及以前已发布收盘数据，交易目标与模型的T+1开盘及后续兑现端点对齐；收盘到收盘的历史趋势特征不自动等于开盘交易目标。未来风格收益或下跌分组只能作训练标签/事后诊断，不能生成当日组别。

原市场准入协议不因本备忘自动改变。若风格专用对象需要新增目标，应在打开收益前另行明确批准其专用评审协议，保留原市场均值结果，不能失败后换目标救回。现有50市场全控制及相关股票风格暴露、简单历史风格延续基线必须纳入；按日期作严格向前比较、成熟期purge、依实际重叠期限设置HAC/块检验，完整10族BH及源失败p=1规则继续按届时冻结协议执行。名义控制数、实际秩、有效日数、缺失和源真实起点分别记录，滚动窗口多次统计不算独立样本。

应同时回答两件事：是否提供相对现库的新信息；模型/策略是否真正消费并增加收益稳定性。前者不由后者单个盈利案例替代，后者不由因子统计t值替代。模型侧先用现有信息完成纯市场截距、显式状态×暴露及固定仓位的对照；若消费接口才是瓶颈，不为增加数量开发重复因子。

### 数据与实现技巧：本次真正踩过的坑

| 问题 | 固定做法 |
|---|---|
| 单位与复权混用 | 日amount为元、vol为股；资金流字段可能为万元；融资金额与融券股数分别处理。逐字段核对，股数转金额用原始价，收益按合同使用复权价 |

3. 找最近的已注册实现，先比较经济含义、代数和排序关系。仅改符号、窗口或单调变换通常没有新增信息。
4. 填下一节设计卡，明确唯一主版本和停止条件；在看本版本收益结果前确定方向、期限、缺失规则和控制组。
5. 先写纯计算函数与手算参考，再接入FactorSpec；按第5节从小样本扩大到正式年度引擎。
6. 工程、描述用途或预测证据、库内重叠、下游模型增量分别判断。确认后只物化点名对象及依赖，填写交付卡。

以下是文档模板，不是现有配置文件的schema。按开发任务填写，不把占位项直接加入生产清单。

```yaml

## 3. 可复用的构造套路

| 套路 | 怎么提出问题 | 必须排除的伪差异 |
|---|---|---|
| 自身创新项 | 当前值偏离过去季节性、趋势或常态多少？ | 全样本拟合；仅换尺度；未来参与基线 |
| 结构份额 | 同一经济总额中的权利或现金流如何分配？ | 分母口径不匹配；互补份额重复计数 |
| 条件响应 | 同样冲击在不同状态下的反应是否不同？ | 已知因子乘状态；组成腿解释全部增量 |
| 路径顺序 | 相同累计收益和分布下，发生顺序有何不同？ | 只由收益多重集决定的指标改名 |
| 时间分配 | 成交或信息到达在日内如何偏离历史预期？ | 端点代理冒充逐笔；跨股票日传播状态 |
| 同业传播 | 已公开同业信息对尚未披露对象有何影响？ | 最新映射回填；本公司事件强度解释全部 |
| 期限结构/动态参数 | 短长窗口的差异或参数变化可识别吗？ | 邻窗堆积；弱识别；优化成功冒充识别 |

反例要针对构念：路径因子使用“收益多重集相同、顺序不同”的两条路径；比例检验同比例缩放；估计参数检验已知真值与常参数null；门控先拆组成腿。残差化依赖控制和样本，不是通用的新增信息证明。

    amount = np.asarray(ctx.px_raw("amount"), dtype=np.float64)
    valid = ctx.universe & ctx.traded() & np.isfinite(amount) & (amount > 0)
    x = np.full(amount.shape, np.nan, dtype=np.float64)
    x[valid] = np.log1p(amount[valid])
    baseline = ctx.roll_mean(x, 20, min_count=16)
    result = x - baseline
    return np.where(valid & np.isfinite(result), result, np.nan)


@register(FactorSpec(
    name="dev_example_amount_log_deviation_20",
    group="liquidity",
    desc="教学示例：成交额对数相对自身20槽均值的偏离",
    formula="log1p(amount_t)-mean_20(log1p(amount)); min_count=16",
    deps=("stock_daily",),
    start=None,
    warmup_days=80,
    higher_is_better=True,
    version=1,
    enabled=False,
    note="仅教学；方向元数据不构成预测声明；预热须按实际年度锚点核对",
))
def example_factor(ctx):
    return compute(ctx)
```

开发者决定接入时，在 `factors/__init__.py` 增加 `from . import my_family`；装饰器必须实际作用于函数。`enabled=False` 的规格不会被生产选择，包括按名称的沙箱运行。进入受控沙箱验收前需明确改为 `True`；沙箱仅隔离输出，不隔离启用清单，调试规格启用期间应避免默认日更将它纳入正式输出。未获准的规格验收后恢复禁用。

内部按float64计算，返回与面板一致的 `(T,C)` 数组；市场规格设置 `is_market=True` 并返回 `(T,)`。不自行生成rank、不反转Store输出、不手写Parquet，不缓存 `id(ctx)`。字段 `version` 便于说明变更，当前入口仍需显式重建才能刷新覆盖。

### 按数据类型选入口

| 类型 | 复用入口和必填内容 | 现存实现参考 |
|---|---|---|
| 日频价量 | `ctx.px_raw`、`ctx.hfq`、`ctx.traded`；声明日线、复权等全部源 | [动量](../factors/momentum.py)、[流动性](../factors/liquidity.py) |
| 财务 | `ctx.ttm/point/annual` 或必要的 `ctx.dataset`；列明 `fin_fields`、报表源和PIT | [基本面](../factors/fundamental.py)、[财务构成](../factors/registered/r13gc_financial_composition_v1.py) |
| 分钟/筹码 | `ctx.intraday_field/open5_field/closing30_field/chip`；复用派生层，声明原始源 | [日内](../factors/intraday.py)、[筹码几何](../factors/registered/r17_chip_geo_v1.py) |
| 父因子组合 | `ctx.load_factor(name)`；`deps`列全父名称，以及自己直接读取的原始源 | [耦合](../factors/coupling.py) |
| 不规则事件 | `ctx.dataset` 取源，明确可得日后用 `ctx.asof_daily/event_grid` 对齐 | [事件](../factors/event.py) |

`ctx.ret_clean(1)` 只按当前成交状态屏蔽，不能替代两端成交检查。相邻收益至少再验证前一日成交，例如 `ctx.shift(ctx.traded().astype(float), 1) == 1`；多日收益核查公式所用全部端点，不能照搬单日异常阈值。

财务例：经营现金/收入比可用 `ctx.ttm("n_cashflow_act")` 和 `ctx.ttm("revenue")`，分别依赖 `stock_cashflow`、`stock_income`，并声明相同的 `fin_fields`。这只是已有概念的接线例；具体分母资格、版本前沿、有效起点和报龄必须沿用设计卡，不能由helper默认值代替。

滞后表先查 [frequency.yaml](../conf/frequency.yaml)。`lagged_ok` 仅声明已处理，不能自动移动数据；确需延迟n个交易日时用 `ctx.lag_grid(grid, n)` 或明确日期映射，避免双重延迟。父因子加载的是已落盘float32值，普通父输出不提供2018年前预热；需要私有历史时必须单独设计，不能填零。

参数化家族可复用 `factors/registered/<module>.py` 的 `build(parameters) -> compute(ctx)` 形式，以及 `conf/production.json` 的内嵌 `definition`。新开发优先选择一种登记方式，不同时装饰器登记和清单登记同一名称，避免内置注册优先造成定义被跳过。

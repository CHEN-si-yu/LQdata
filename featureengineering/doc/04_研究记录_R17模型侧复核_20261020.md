## 2. R17 A/B 配对验证（2026-10-19）的核心结果

协议：同一份 `featureengineering/data`、同一截止日，A=260 列基线，B=A+50 列；四个 release
模型（V220/V230/V240/V252）各 16 折，共 128 折；seed 35253；242 日测试窗。

模型级四指标均值（A→B）：

| 指标 | A | B | Δ(B−A) | 相对变化 | B 更好的模型数 |
|---|---:|---:|---:|---:|---:|
| IC_1d | 0.03488 | 0.03198 | **−0.00289** | −8.3% | 0/4 |
| IC_5d | 0.05026 | 0.04646 | **−0.00380** | −7.6% | 0/4 |
| RankIC_1d | 0.04191 | 0.04045 | **−0.00147** | −3.5% | 0/4 |
| RankIC_5d | 0.05934 | 0.05660 | **−0.00275** | −4.6% | 0/4 |
| ICIR | 0.33089 | 0.30066 | **−0.03024** | −9.1% | 0/4 |

- 64 个折级配对 test：ΔRankIC_5d 均值 **−0.00338**（22/64 为正，符号检验 p≈0.008）；
  ΔIC_1d 均值 −0.00299（19/64 为正，p≈0.0008）。
- 季度结构不稳定：2025Q4 四个模型全部改善；2025Q3、2026Q2 四个模型全部变差
  （2026Q2 平均 ΔRankIC_5d −0.00995）。
- 单因子诊断（测试窗，50 个新因子）：平均 RankIC_5d **+0.0031**，29/50 为正；
  chip_geometry 平均 +0.0054 最好；liability_composition −0.0023、chip_event_C −0.0136、
  reopen −0.0014 为负。整批弱且分化，整批加入的净效果被稀释/过拟合抵消。

要点：

1. **整批不涨 IC**：V260 全 50 列 ΔIC −0.00252、ΔRankIC_5d −0.00086，与 R17 B 的方向一致。
2. **子集也没有可验证 IC 增量**：最好的 V257 仅 +0.00073（约 1.5%），V258 基本打平；
   fund12/cross4 为负。
3. **增量信息基本被现有 260 列覆盖**：把 cross2/chip6/stable10 等权 composite 对 A260 做
   逐日横截面 ridge 残差后，2022–2024 RankIC_5d 从 +0.035/+0.047 降到 +0.003/+0.004，
   2025H1 也接近 0；2024 年 A260 对 stable10 composite 的横截面 R² 均值 0.69。
4. **现金改善是父配方相关且不稳健的**：chip 子集改善 p1 本来就弱的 V230/V252，
   但 p1 已强的 V240 反而 −28.34pp；V258/V257 的 2026Q3 前向仍为负；
   50 列置换（V263）与 V258 的 p1 相差约 55pp，说明单复本现金差异很大。
5. **无模型晋级、无 release 修改**：R18 的 9 个完整单元均未同时超过各自父 release 的
   统一指标与现金表现；四模型 R1 集成仍是最强稳定信号。

## 4. 与 R17 生产/准入审计的关系

R17 交付记录表明 50 个因子在生产侧满足：

- 2018–2026 共 9 个年度分区；
- 4,490,145 行生产输出与封存正式 run 逐值/rank 精确对拍；
- NaN 模式一致、增量与截断验证通过；
- GC 因子计算当前库 G5，0.95–0.98 特殊复核带未自动准入。

**这些证明的是“算得对、存得对、覆盖全”，不是“对下游模型有增量价值”。**
原准入政策（v4/v4.1）主要覆盖构念、PIT、覆盖、截面区分度和库内重叠；
本轮暴露的是**模型侧增量价值门槛缺失**：单因子/整批在模型 A/B 中不涨 IC，仍可能通过原准入。
因此建议把模型侧增量价值纳入复审，而不是否定原生产审计。

**优先回档候选 = 30 个财务构成因子（asset 20 + liability 9 + reopen 1）**。
理由：模型侧 IC/现金均无改善、与既有财务因子冗余度高、R17 单因子平均为负；
chip/cross 家族仍有弱信号与现金观察价值，应先做单因子/子集复审，不宜整族回档。

## 6. 复审/回档的安全流程建议

1. **先冻结复审清单，不直接删数据**：由用户确认复审范围（建议先 30 个财务构成因子，
   再 chip_event/单个 chip 因子）；保留 R17 交付证据、生产分区与对拍文件。
2. **按模型侧增量价值复审**，建议最低协议：
   - 同一快照、同一父配方，family 级与单因子级分别 A/B；至少 4 个 release 配方 × 16 折；
   - 配对 ΔIC/ΔRankIC（整窗 + 分季度 + 折级符号检验），至少 3 个随机种子复核；
   - 对 A260 的横截面残差 IC / 增量 R²；G5 重叠与人工复核带；
   - 含费现金的 band/父配方/前向块稳健性（单点最优不算通过）。
   判定建议：多数模型 ΔIC≤0 或残差 IC≈0 → 不通过；不允许用单季度/单模型/单 seed 的现金
   改善翻案。
3. **回档执行（仅在复审不通过且用户批准后）**：
   - 更新 `conf/production.json` / 注册表，明确停用清单与生效日期，记录变更前后
     `registry_sha256`；
   - 保留历史分区与审计证据，先标记 deprecated，不立即物理删除；
   - 通知下游模型侧：`preparingdata.py` 会随上游列集变化，旧权重需重训或用
     `--features-from` 固定清单；不要静默假设列集不变；
   - 回档后重新生成模型快照并记录 `meta.json` SHA、列数与方向；
   - 若未来恢复，按新因子重新走完整准入，不复用旧审批结论。
4. **不建议的做法**：直接删除 R17 生产分区/台账；只改注册表不通知下游；用 R18 的单 seed
   现金改善作为保留理由；用 R17 的生产对拍通过替代模型侧增量复审。

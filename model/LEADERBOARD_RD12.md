## 2. ★★ 为什么不能简单地把打板接到现有引擎上

现有引擎的执行口径（`README/SPEC.md` §7）写的是：

> **开盘价触及按 `pre_close` 算的 10% 主板限价即保守拒单**，停牌拒单；
> **不用 T+1 全天 high/low 去决定"开盘买不买得进"**。

即现引擎**系统性拒绝涨停价位的一切成交**。而**打板买的正是这个价位**。
⇒ **打板不可能复用 `evaluation_core` 现有的入场/拒单路径**，必须**另写一套执行口径**；
且**两套口径的收益不可横比**。旧口径继续服务 RD11 与全部历史版本。

★ 另有一条**容易写错、错了不报错**的约束：

> **打板必须用「T−1 收盘出分 → T 日盘中执行」的错位口径。**

打板要在 **T 日盘中**下单，而现有 `score` 是「**T 日收盘后**」算出来的。
直接套用现有 `score` 等于用「T 日收盘（**含 T 日涨停这个事实本身**）」预测
「T 日盘中的涨停买入」—— 是 `R3`（掩码必须对齐**成交日**而非信号日）的翻版，
**写错了不报错、只让收益虚高**。

## 3. 预登记口径（Agent 2026-09-22 定，见 `README/TODO.md` RD12）

| 项 | 规则 |
|:--|:--|
| 涨停价 | `zt(T) = round(pre_close(T) × 1.10, 2)`，主板 10%；`pre_close` 取自 `prices` 块**逐日算**；**不依赖 `pct_chg`**（避免与复权口径打架） |
| 触板 | `high(T) ≥ zt(T)` |
| 封板近似 | `close(T) == zt(T)` |
| 一字板 | `low(T) == high(T) == zt(T)` ⇒ 全天无成交，**按打不进剔除** |
| **入场** | T 日以 `zt(T)` 成交（假设封板时打进） |
| **出场** | 默认 **T+1 开盘**（隔日打板）；另做 T+1 收盘 / 持 2、3、5 日对照 |
| 选股 | 模型打分排序 TopN ∩ {T 封板 ∩ 非一字板} |
| ★★ **信号时点** | **只能用 T−1 收盘为止的信息**（见 §2 末） |
| 费用 | 同现有：佣金万 2.5（最低 5）+ 过户万 0.1 + 卖出印花万 5 + 单边滑点 3bp |
| 容量 | 单笔 ≤ T 日该股成交额 1%（沿用）；★ **封单规模无法从快照获取**，必须报「**满额成交上限**」 |

### ★ 必须先声明的偏差（不写清就没法读）

1. `prices` 块是**日线** ⇒ **无法知道封板时点**、**无法判断盘中是否开过板** ⇒ "封板时打进"是**乐观假设**
2. 真实打板要**排队**，封单大时打不进 ⇒ 必须报 **0% / 50% / 100%** 三档**成交率敏感性**
3. 一字板剔除是**保守**方向，但反向偏差同样存在（排队靠前能打进一字板）
4. **涨停价比开盘价贵** ⇒ 打板的入场成本**系统性高于** RD11 的 T+1 开盘买入，溢价先被这部分吃掉
5. 综合 1–4：本口径产出的是**上限收益**，**不是**可实现收益

## 4. 已有线索（是线索，不是结论）

- `LESSONS.md` §9：模型 top1 落在"买不到"的格子是基准的 **42×**、落在「T 日收盘涨停」是 **17×**
  ⇒ **模型本身已经在往涨停票上集中**。打板方向等于把这个倾向从"要被掩码剔除的污染"
  改成"被显式建模的目标"。
- `LESSONS.md` **U2**：T 日收盘涨停可用 `consecutive_limit_up` 当日截面 **rank ≥ 0.98** 识别
  （精确率 99.6% / 召回 91.4%、AUC 0.988）⇒ 有**两条独立**的涨停判定路径
  （`pre_close×1.1` 与 `rank≥0.98`）**可以互相对拍**，不必只信一条。

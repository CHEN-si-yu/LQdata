# releases/ 经验手册（2026-10-06 四模型线）

> 本文件汇总现行四模型线（V220 / V252 / V230 / V240）建立过程中换来的全部经验，
> 以及从**旧实战线**（V31/V36/V38，归档于 `history/releases_retired_20261006/`）继承的实战模式要点。
> 数值与产物指针以 `docs/iterations.md`、`dsh_scratch/releases_*` 为准。

## 一、选择与验证链（这四个单元是怎么选出来、怎么验证的）

1. **综合分沿袭归档公式**：0.35·RankIC_5d + 0.25·现金净收益 + 0.20·4块年化 + 0.10·top_return + 0.10·审计；
   套用前先在旧 38 单元上逐行复现归档表（38/38 吻合）再应用。不能跨快照/跨窗合并排名。
2. **相关结构**：综合分前 10 ≈ 4 个独立信号（双分支 / 容量 MLP / 个体户对 / V252），跨簇日秩相关低至 0.45。
   四条线各取一个代表：V220、V252、V230、V240。注意 V214 与 V202 权重逐字节相同（对照单元，非独立方向）。
3. **种子稳定性（第一个测试）**：每单元 4 新种子复本（45253/55253/65253/75253），256 折 97 分钟零失败。
   复本目录（16 个）已按用户指示删除（2026-10-06）；复现按 `dsh_scratch/releases_seed_20261006/protocol.json` 重训（约 97 分钟）。
   结论：模型内种子信号相关 0.88–0.95 ≫ 跨模型 0.45–0.75；**单种子含费现金是噪声点**（sd ±2.9~±13.6pp，
   原种子常有抽样极值）——跨模型现金比较只引用种子均值；4 块（epoch 选轮块）系统性偏高，只作诊断。
4. **代表选择**：候选 = 4 个新种子；主口径 = 信号 medoid（与其余种子交付打分日秩相关均值最高），
   交叉口径 = 指标 z 距离中心。产出：V220→s75253、V252→s45253、V230→s45253、V240→s45253。
5. **集成规则 R1**：各模型先做种子复本打分等权平均（baseline 模型级口径），再对四模型**逐日截面分位秩等权平均**
   （共同有效集 ~99.997%）。6 种输入组合下 p1 现金 6/6 正、p5 5/6 正，回撤全场最低；z-score 与原始分平均均更差。
   独立复核 22 行指标 + 44 个现金块全部 0 差。
6. **小资金策略 A（待前向验证）**：R1_MEAN5 信号 + 10 万 + n5 + 每日检查（period1）+ band40 + **门控 OFF**；
   复检 5/5 正（中位 +47.5%）、三资金档同向（+54.7/+55.6/+54.6）、相位 0–4 天全正、四季全正。

## 二、硬件与调度实测（本机）

- 256 折并发运行：**97 分钟、内存峰值 104.3GB、双卡均值 ~95%**；CPU 均值 ~53%。
- **并发宽度由内存预算决定**（BUDGET=110GB：dual 折 ~22 并发、MLP 折 ~16 并发），不是 parallel_limit（28）；
  GPU 是真正的瓶颈（99%）。内存守卫（SOFT 120GB / HARD 138GB，cgroup 上限 160GiB）全程未触发。
- 折级全局队列 + "**单元 N 折齐 → 立即串行审计**"闸门 + analysis flock/超时：16/16 审计零失败；
  单单元审计中位 2.2 分钟。**调度可能在单元未齐时提前铺后续单元的折**（已记录）；审计闸门不受影响。
- 复本数与调度：4 单元 × 5 实例 = 20 个单元目录并行训练，无需人工干预。

## 三、数据与实现陷阱（踩过的，重犯代价高）

1. **单种子现金不可当水平**：同配方换种子现金 sd 达 ±14pp（见上）；引用前先聚合。
2. **4 块（epoch 选轮块）有系统性选择偏差**：原种子普遍高于其复本全部取值，只作诊断、不入成绩。
3. **锚点对拍要核对参照物**：策略搜索前用官方已落盘值对拍引擎（V220 门控 ON +34.32/−15.53）；初版误填了
   V229 的 42.60 靠数值不符才发现——**对拍失败先查参照物，再查代码**。
4. **pct 分位门控的准入型实现会冻结组合**（band/period 不变、数值重复）= 伪影；正确语义未移植，交付前勿用。
5. **门控列 `absolute_forecast_1d` 跨单元逐位共享**（技术腿确定性拟合），集成信号可直接复用。
6. **门控开关不是常数**：p1 档 gate-off 显著更优、p5 档部分格子 gate-on 更优——必须入网格，无"默认开"。
7. **复本构造的最低验证标准**：源文件 + main 前单条 `RECIPE.update` 覆盖块；须满足「删块后与源逐字节相同、
   生效配方差异恰为白名单键、训练折种子记录全量核验」。
8. **独立对抗性复核是标准流程**：每个研究产出后派独立复核（重算 + 证伪尝试），逐位 0 差才落文档。
   本轮已完成：综合分（PASS）、种子稳定性（PASS）、集成规则（PASS）、小资金策略（PASS，
   另修正非 10 万档季度表 reporting bug；pct 门控冻结在 band40/60 成立、band20 为例外）。
9. **复用评测函数先核对账户规模假设**：`quarter_metrics` 硬编码 `previous=100000`，非 10 万档的季度收益
   必须以实际账户基准自行切分——此类 bug 不影响净值/回撤/笔数，只出现在分档报表里（独立复核发现）。

## 四、实战模式要点（继承旧线 README + 本轮勘察；重训/评分前必读）

1. **一个模型 = 一个季度的四折集成**：四折打分**相加**为交付分，不是单个子模型。
2. **验证块长度是真旋钮**：旧线曾被 95 天验证块毁掉（bagging 选中晚期轮，评估块 RankIC 仅 +0.0039）；
   现四折设计每折验证块 ~470 天，天然规避。
3. **回测窗尾留 3 天**：现金循环会读到 signal+2 日价格，评估窗铺到数据末日会 IndexError。
4. **「MX_LIVE 未设 ⇒ 与 experiments 逐字一致」对拍**：`model.py --split` 输出 diff 必须无输出；
   全部新增代码限 LIVE 分支。
5. **断点续跑判据 = `complete.json`**；改配方重训必须先删对应折目录，否则静默沿用旧产物。
6. **权重装载三件套** `model` / `ridge` / `features` 必须一起恢复（只装 model 会静默错）。
7. **快照列名顺序漂移不报错**：加载旧权重必须钉住 `ck['features']`；列数/顺序变了是静默错位。
8. `patch` 用 `--no-backup-if-mismatch`（`.orig` 会被文件合同拒）；`/autodl-fs/data` 是 `/root/autodl-fs`
   的软链，路径别混写。
9. **2026Q4 伪季度设计（本轮）**：`LIVE_QUARTER='2026Q4'`；cutoff = 季首 − purge − 1 ≈ **2026-08-31**
   （季首前 21 个交易日，`--split` 实测）；test/score 窗 = 2026-10-01 起 → 数据更新前为空，评分待数据到位。
   如需极致推新（把 cutoff 推到数据末 ≈ 2026-09-30）需接受 Q4 首月评分的标签重叠——默认不做，改前必须记录。
10. **★ 因子侧持续新增 ⇒ 实战推演前必须做因子对表/筛选**：上游因子库在持续更新（快照会新增列，列数与列序都会漂）。
   用已训练模型做推演时**不能把新快照整表直接喂给模型**——必须按模型钉住的清单（`ck['features']` / RECIPE 的
   特征清单）**按列名**从新快照取出对应列、**按钉住顺序重排**：新增列一律不进模型；缺列必须**显式报错**
   （不得静默补零或截断）；列序漂移不报错、只会静默错位（见第 7 条）。"对表"应作为评分流程的前置**硬校验**：
   ① 列名包含关系 ② 顺序逐列比对 ③ 对不齐即拒绝评分并列差异。训练侧已有 `--features-from <pinned.json>`
   钉列机制（见 `docs/baseline.md`「特征集变更的可比性」），实战评分流程需实现等价的对表与校验。
   快照 pin（`snapshot_meta_sha256` / `snapshot_cutoff`）的更新是**有意的显式操作**，每次评分必须记录
   "哪一个快照、哪些列、何种顺序"。
11. **方向也是输入合同（2026-10-07 实测修复）**：列名、列序及 `semantics` 相同，仍可能把训练时的
   `−z` 喂成新快照的 `+z`。本次新快照的 227 列全部正向，V220 有 31 个输入方向不匹配，
   V230/V240/V252 各有 52 个；漏校验导致日报排名大幅变化。训练前归档元数据恢复的方向保存在
   `releases/input_contracts.json`，`main.py` 必须按 `训练方向 × 当前快照方向` 转换后才评分；
   缺方向合同或当前方向时必须报错，不得默认正向。仅修复符号就重现 2026-09-30 旧融合 Top10 的代码、
   每模型排名及各模型 Top5，融合分最大差异 `2.22e-16`。使用同一新快照对拍两条读取路径不能证明训练口径兼容。

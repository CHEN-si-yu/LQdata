# releases/ —— 实战单元

本目录存放**经明确确认的实战单元**（`docs/architecture.md`）。当前三个：

| 单元 | 来自 | 说明 |
| --- | --- | --- |
| `V31` | `experiments/V31/` | 理想口径第一名（单因子 `close30_ret`） |
| `V36` | `experiments/V36/` | 理想口径第二名（单因子 `chip_near_overhang_5pct`） |
| `V38` | `experiments/V38/` | 干净块与账户口径第一名（V29 核心 + `close30_crowded_fade`） |

每个单元的三个实现脚本（`run.py` / `model.py` / `analysis.py`）是从对应的实验单元**逐字复制**过来的。

> ★★ **交付物是三个单元的「集成」**：把三个单元各自的四折集成打分**再等权平均** ⇒ 等价于
> **12 个子模型等权**。它降方差是几乎免费的（三个单元打分逐日秩相关 0.92~0.97，本来就是同一个模型），
> 也避免"按最近一段收益挑模型"这个陷阱。
> 实现在本目录的 `ensemble.py`，结果记在 [REPORT.md](REPORT.md) 与 `ensemble.json`。
> **REPORT.md 专门记录这个集成**；三个单模型的结果只在里面作对照。
> 它有两段是**脚本自动生成**的（不要手改）：
> **顶栏「最新一日推演」** —— 只列当下这一天，前 5 名建仓 / 6~10 名顺位替补；
> **文末「历史每日 Top-10」** —— 从 `2026-09-01` 起逐日列出（起始日改 `ensemble.py:HISTORY_START`）。
> 每次跑 `ensemble.py` 两段一起刷新。

## 0. ★★ 最重要的概念：什么叫做「一个模型」

**实战模型 = 一个季度的四折集成，不是单个子模型。**

experiments 里每个单元训 16 个子模型（4 个季度 × 4 折），**每个季度的 4 折打分相加 = 那一季的交付打分**
（`analysis.py` 的 `sum(variants.values())`）。所以平时说的"V27 模型"、"V38 模型"，
指的**就是四折集成后的结果**，而不是某一个子模型。

> 这条在本目录建立过程中被误解过一次（把"只训一个模型"按字面做成了单个子模型），
> 后来由用户澄清。**以后凡是说"一个模型"，都指一整组四折的集成结果。**

### 三层结构

| 层 | 是什么 | 落在哪 |
| --- | --- | --- |
| 子模型 | 一个 (单元, 折) 的训练产物 | `releases/<V>/model_train/2026Q3/fold<k>/best.pt`（共 12 个） |
| 单元集成 | 该单元四个折的打分**平均** | `releases/<V>/model_train/2026Q3/fold*/score_predictions.npy` |
| **交付集成** | **三个单元的打分再平均 = 12 个子模型等权** | `releases/ensemble.py` → `releases/ensemble.json` |

## 1. 实战模式与实验模式的唯一区别

实验单元跑「4 个季度 × 4 折」；**实战单元只跑一个季度**，但**同样是四折**。

开关是环境变量 `MX_LIVE=1`：

```
MX_LIVE 未设（默认）→ 行为与 experiments/<V>/ 逐字一致（可用 --split 验证，见 §5）
MX_LIVE=1          → 只跑伪季度 2026Q3 的四折，产物落在 live 清单里
```

### 伪季度 `2026Q3`

```
LIVE_QUARTER = '2026Q3'
```

它的起点 `2026-07-01` 就是**干净评估窗**的起点。`splits()` 的几何一行没改，
于是自动得到：

| 折 | train | valid（选轮专用） | test = score |
| --- | --- | --- | --- |
| fold1 | 2020-03-12 → 2026-05-29 | 2018-01-02 → 2020-01-03 | 2026-07-01 → 2026-09-24 |
| fold2 | 2018-01-02 → 2020-01-03 ＋ 2022-04-18 → 2026-05-29 | 2020-02-12 → 2022-02-14 | 同上 |
| fold3 | 2018-01-02 → 2022-02-14 ＋ 2024-05-24 → 2026-05-29 | 2022-03-16 → 2024-03-19 | 同上 |
| fold4 | 2018-01-02 → 2024-03-19（**干净**：训练全在 valid 之前） | 2024-04-22 → 2026-04-27 | 同上 |

- 四折共用的 cutoff = 季首 − purge − 1 ≈ **2026-06-01**（训练数据止于此）。
- **`test` = score 窗 = 2026-07-01 → 2026-09-24（62 天），四个折的训练集都不含这段**
  ⇒ 对**集成整体**是干净的样本外。
- 四个折的差别与 experiments 完全一样：第 k 折把第 k 块留作验证，训练集是其余部分。

★ 唯一与 experiments 不同的代码是 `splits()` 里的一行：伪季度不在固定评价窗内，
`test` 取本季度自己的区间（与 `tmp/vlines/wf_unit` 的既有做法一致）。

## 2. 怎么跑

```bash
cd /root/autodl-fs/model/releases/V38          # 或 V31 / V36

# ① 训练四折（= 四个子模型）。run.py 会断点续跑，已完成的折自动跳过
MX_LIVE=1 ./run.py --jobs 4 --device cuda

# ② 验证：四折集成在干净评估窗上的表现
MX_LIVE=1 python -B analysis.py --live

# 只看切分（不训练）
MX_LIVE=1 python -B model.py --split
```

```bash
# ③ ★ 交付物：三个单元的集成（打分等权平均，等价于 12 个子模型等权）
cd /root/autodl-fs/model/releases && MX_LIVE=1 python -B ensemble.py
# → 打印结果 + 写 releases/ensemble.json；人读结果见 releases/REPORT.md
```

产物：

| 路径 | 内容 |
| --- | --- |
| `model_train/2026Q3/fold{1..4}/` | 四个子模型（各 8 个固定文件，含 `best.pt`、`score_predictions.npy`） |
| `model_info/live_validation.json` | 机读验证结果 |
| `model_pred/live_report.md` | 人读报告 |
| `model_logs/2026Q3_{1..4}.log` | 四折各自的训练日志 |

★ **不要 12 个折一起跑**：每折峰值 ~12 GiB，3 个单元 × 4 折 = 144 GiB，
加系统开销会越过 180 GiB 的 90% 上限。**并发 6 是安全的**（≈92 GiB），分两波。

## 3. 验证口径（`analysis.py --live` 报什么）

1. **模型质量**：评估窗上逐标签的 RankIC / Pearson IC —— 与 experiments 的 `RankIC_5d` 同式，
   可直接对照（experiments 近期单元在 242 天窗是 +0.0482 ~ +0.0541）。
2. **账户表现**：评估窗上按交付配置跑 `cash_backtest`（10 万元、含佣金/印花/过户/3bp 滑点、
   整手、T+1、拒单），分列毛收益 / 费用 / 净收益，年化按 242 个交易日折算。
3. **可复现**：现场重载 `fold1/best.pt` 重新前向，与落盘打分逐格对拍（阈值 2e-4）。
4. **判定分两条，不能合并**：
   - **模型质量**（对窗口稳健）**是主判据**；
   - **账户表现**照实报，但**不能**直接和锚比 —— 锚（22 块上激进 +30.4%/年、稳态 +37.5%/年；
     四个近期干净块 V28 +44.7%、V29 +45.4%）是 **2021–2026 的多年年化**，而评估窗只有 62 天。
     必须同时看**同窗的 experiments 参照**（`experiments/<V>` 同一季度的四折集成）。
     对照脚本：`/root/autodl-fs/tmp/vlines/release_vs_exp_lab.py`（在单元之外，不违反目录规则）。

## 4. 技术细节

| 项 | 说明 |
| --- | --- |
| 权重装载三件套 | `best.pt` 的 `model` / `ridge` / `features` **必须一起恢复**。`ridge` 是 20% 的线性分量（`linear_weight=0.2`），只装 `model` 会静默给出错的分。 |
| epoch bagging | 交付权重 = 验证集 `val_wei` 前 `bag_topk`(=5) 名的权重平均，**不是 argmax**。V26 那类单元还会把 `bag_bank`(=10) 份快照一并存进 `best.pt`，所以它的日志打印 `bag 10/5` 是"留 10 份、平均 5 份"，不是 bug。 |
| BN 重标定 | 平均后按 `split['train']` 重估 BN 统计量 —— 所以**训练集变了就必须重训**，不能复用旧权重。 |
| 断点续跑 | 判据是 `model_train/<季>/fold<折>/complete.json` 存在。**改了配方想重训，必须先删掉对应折目录**，否则静默沿用旧产物。 |
| 特征列数会漂 | 快照的特征随上游增删（477 → 484 都发生过）。重训会按当前列数建模型（正常）；**加载旧权重必须钉住 `ck['features']` 的列名与顺序**，顺序变了不报错、只会静默错位。 |
| 打分是纯函数 | `predict(model, panel, prices, days, device)` 对任意日期索引都成立，没有季度/折假设。签名在两层不完全一致（没有 `hot_pool` 的单元是 4 参数），跨单元复用推理代码要 `inspect.signature` 判一下。 |
| 账户口径 | 佣金 `max(名义×0.00025, 5)` + 过户 0.001% + 卖出印花 0.05% + 单边 3bp 滑点；整手、T+1、涨跌停/停牌拒单、现金约束。佣金下限让小账户的低仓档费率显著上升，所以费用要分档看。 |
| 集成的口径 | 三个单元的打分**等权平均**（不是投票、不是按权重）。三个单元的特征列数不同（478 / 478 / 480），但**打分是 `(天数 × 股票数)` 的矩阵，形状一致**，可以直接平均。 |
| 策略口径 `top5_1d` | **持仓 5 只**；`period=1` ⇒ **每个交易日**检查调仓；但 `band=40` 的缓冲区让**只有掉出前 40 名的票才卖** —— 实测 60 个交易日里只有 34 天发生买入、平均每天换 1.5 只，完整持有跨度 1~11 天。名字里的 `1d` 指**调仓锚点周期**与 **1 日头打分**，**不是「持有 1 天」**。 |

## 6. ★ 建这个目录时踩过的坑（写给后来的人）

1. **「一个模型」的歧义**：字面照做会得到单个子模型，而正确含义是"一个季度的四折集成"。
   详见 §0。判据：experiments 的交付打分是四折相加。
2. **验证块长度是个真旋钮，会静默毁掉模型**。先前的 live 设计把验证块紧贴评估窗、只有 95 天
   （实验单元每折的验证块是 473 天）。结果 epoch bagging 选中第 13~20 轮（晚期），
   交付权重在评估块上 `RankIC_5d` 只有 **+0.0039**（比没有信号还差）；把验证块放到中间、
   拉长到 338 天后选中第 1~6 轮，回到 **+0.0506**。**现在的四折设计天然规避了这个问题**
   （每折的验证块都是 488 天左右），但换设计时别忘了这条。
3. **`validate_layout()` 会挡住跨模式运行**。单元里同时存在两种模式的产物时，
   跑另一种模式会被自己的历史产物判为"多余路径"（连 `--split` 都跑不了）。
   解法：`known_files()` = 两模式清单的**并集**判"多余"——仍是封闭枚举，清单外照拒。
   **没有这一条，"原封不动"这条验证就没法复做。**
4. **回测窗尾要留 3 天**。`cash_backtest` 的循环会读到 `signal+2` 日的价格
   （T 日信号、T+1 开盘成交、再往后一天结算）。评估窗若一直铺到**数据末日**，
   会 `IndexError`。做法：IC 用完整评估窗，**回测用去掉末 3 天的前缀**（前缀保证逐日配对仍正确）。
5. **`patch` 会留 `.orig` 备份**，被文件合同拒（`releases/V38` 第一次就因为
   `model.py.orig` / `analysis.py.orig` 报错）。用 `patch --no-backup-if-mismatch`。
6. **写路径要小心符号链接**：`/autodl-fs/data` 是 `→ /root/autodl-fs` 的软链，
   但 `/root/autodl-fs/data` **不存在**。写脚本时两者别混。
7. **快照的 `meta.json` 特征列数会变**，旧权重不能直接装到新面板上（形状不符会响，
   但**列名顺序变了不会响**——那才是真危险）。

## 7. 已知局限（引用本目录任何数字前必读）

- **评估窗只有 62 个交易日，对策略层没有统计功效**（项目实测 top5 边际 t 仅 0.45）。
  只能读"量级对不对"，不能读"比谁好多少"。实证：同一段窗口上 experiments 四个单折
  曾出现 −7.3% ~ −22.3% 的散布，而集成与单模型的打分秩相关高达 0.83。
- **训练数据止于 ~2026-06-01** —— 要留出干净样本外，就必须舍弃最近几个月的训练数据。
- **「9 年」在数据上做不到**：快照最早交易日 **2018-01-02**，全区间 2120 天 ≈ **8.7 年**；
  上游没有 2017 年及以前的数据。无前视样本外最多覆盖 2021→2026（≈5.7 年）。
- **集成不会改变晋级状态**：它降的是方差，不是把一个未晋级的信号变成已晋级的。
  三个单元在 experiments 侧的多种子复核都没通过（见下条）。
- **V38 / V36 在 experiments 侧的多种子复核未通过晋级**：V37 配置的四种子干净块加权净年化
  为 57.93 / 46.23 / 46.68 / 38.16%，三颗新增种子均值 43.69% 低于 V29 的 45.41%。
  它们进 releases 是用户的明确要求（"换成最新的单元"），**不等于项目的研究结论是"已晋级"**。

## 实战模式（2026Q4）

- 四个单元已移植 `MX_LIVE` 实战开关（新增代码全在 LIVE 分支；**未设 MX_LIVE 时与 experiments 逐字一致**，
  `model.py --split` 对拍四单元 diff 全空）。
- 伪季度几何：训练数据止于 **2026-08-31**（季首前 21 个交易日 purge）；fold4 验证块至 2026-07-31；
  test/score 窗 = 2026-10-01 起（数据未覆盖前为空）。
- 用法：`MX_LIVE=1 ./run.py --jobs …` 训练；`MX_LIVE=1 python -B analysis.py --live`
  → `model_info/live_validation.json` + `model_pred/live_report.md`。
- 最终重训（四单元 × 四折）的调度、事件与资源记录：`dsh_scratch/releases_live_2026Q4/`。
- **每日入口：`python releases/main.py`**（在 model 目录执行；也可在 releases 下执行 `python main.py`）。
  自动发现本目录内含 `model.py` 的发布单元，读取各自最新季度的完整四折权重，推演共享
  `trainingdata/` 中最新 **10 个交易日**，每一天列出各模型 Top10 和 R1 融合 Top10。
- 每天按机器本地的执行日期生成 **`DAILY-YYYYMMDD.md`**，例如 `DAILY-20261007.md`；
  日报内的交易日期以快照为准。同一天重复执行更新同名文件，其他日期的日报保留。
  权重与输入未变时复用 `.daily_state.json` 的评分缓存；数据更新后刷新窗口，不重复日期。
  `--force` 强制重新评分，`--days 20` 调整窗口，`--data /path/to/trainingdata` 指定快照。
- 股票列以 `best.pt` 的冻结列名与顺序为准，市场列以同折 `training_info.json` 的 `market_columns`
  为准；新增列不进模型，缺列或四折列顺序不一致时报错。沿用发布模型的 CPU 推理与四折相加，
  再在共同有效股票内逐日截面分位秩等权融合。当前只有各模型已有的一套种子权重，不补造种子复本。
- **方向同样属于训练输入合同**：快照值是 `z × 快照方向`，模型需要 `z × 训练方向`。
  `input_contracts.json` 冻结训练方向，入口逐列乘 `训练方向 × 当前快照方向`；已经同向的列不再次翻转。
  训练或当前方向缺失则拒绝评分。合同是从训练前归档元数据恢复的本地文件，运行时无需上游配置或注册表。
  2026-10-07 查明当前 227 列快照全部正向，而 V220 的 92 列中有 31 列、其余模型的 206 列中有 52 列
  训练时存负 z。修复后，2026-09-30 的融合 Top10 代码、各模型排名及每个模型 Top5 与旧日报完全一致；
  融合分最大差异 `2.22e-16`（加法顺序的浮点误差）。此前只核对列名/顺序生成的当日日报已重新评分。
- 日报是已有权重对最近日期的推演结果，不重新训练，不自动操作持仓。原有
  [`DAILY.md`](DAILY.md) 的持仓/操作记录保留，旧 paper 持仓跟踪仍在
  `dsh_scratch/releases_live_2026Q4/daily_state.json`；新入口不依赖这些临时脚本或修改其状态。

## 每日持仓操作与 CPU 验证（2026-10-13）

日常评分沿用已交付权重，CPU 容器可以完成四模型四折推演。开工先核实实际 CUDA 可用性与 cgroup 内存配额，资源配置按当前容器执行；下节 2026-10-08 重训时的 90 GiB 是历史实例。因子侧的 CPU 缓存锁修复和验证见 [CPU兼容记录](../../featureengineering/doc/01_生产_CPU兼容_20261013.md)。

需要持仓分数与完整排名时，可一次评分同时生成两个输出。先创建证据目录，再把下面的 `<证据目录>`、`<数据末日>`、`<实际持仓>` 换成当前值；持仓使用用户当次确认的代码及交易所后缀。

```bash
PY=/autodl-fs/data/miniconda3/bin/python
cd /autodl-fs/data/model
$PY /autodl-fs/data/dsh_scratch/releases_daily_helpers/capture_scores.py \
    --days 3 --out <证据目录>/scores_<数据末日>.json \
    --ranks-out <证据目录>/ranks_<数据末日>.json
$PY /autodl-fs/data/dsh_scratch/releases_daily_helpers/ops_tomorrow.py \
    --ranks <证据目录>/ranks_<数据末日>.json --held <实际持仓，逗号分隔带后缀>
```

评分前由主入口设置数值线程，保存前检查快照、输入文件、权重及合同是否漂移。核对 `data_end`、`snapshot_sha256`、融合/单模型 Top10 与当日日报一致后，将持仓计划写入日报的 `holdings-analysis:<YYYYMMDD>` 标记块，并保存输入、评分与计划到当日证据目录。

现行策略 A 为 n=5、每日检查、band=40、门控 OFF；前 40 内的已有持仓保留，跌出后才按规则补位。新 ST、停牌与开盘成交条件须按实际交易状态核查。旧 `DAILY.md` 和 paper 状态只作历史追溯；没有实际股数、成本、现金和成交信息时，不补造成交或收益台账。

2026-10-13 已完成 16/16 折 CPU 推演与独立对拍；本轮用户确认的五只持仓在 2026-10-14 全部保留，买入/卖出均无。逐只排名和计划见 [当日日报](DAILY-20261013.md)，数据修订、快照指纹、验收边界与遗留见 [跨层台账](../../check/incremental_20261013/LEDGER.md)。此结果仅属于本次信号日，后续重新计算。

## 1. 修的是什么

`../20260921_new_factors/newfactor_ic.py` 第 27/36 行：

```python
CUTOFF = '2025-06-30'
df = df[df['trade_date'] <= CUTOFF]
```

**只按信号日截断，没有截标签末端。** 标签是前视的：

    label_ret_5d(T) = open(T+1+5) / open(T+1) − 1        （`README/SPEC.md` §2 铁律一）

T = 2025-06-30 的标签要用 **2025-07-08** 的开盘价 —— 落在评价窗（2025-07-01 起）**里面**。

### 正确口径（照抄平台自己的 `splits()`，不另立标准）

`V16/model.py::splits()` 的判据是 `cutoff = first − horizon − 1`、`eligible = ix[:cutoff]`，
再加一条**严格不等式**的断言 `max(train.max(), valid.max()) + horizon + 1 < first`
⇒ 最后一个安全样本的**兑现日 = first − 1**，严格早于评价窗。

    h = 5，评价窗首个交易日 first = 2025-07-01
    first − h − 1 = 2025-06-23 → 兑现日 2025-07-01  ✘ 落进评价窗
    first − h − 2 = 2025-06-20 → 兑现日 2025-06-30  ✔   ← 正确的 CUTOFF

★ **我第一版按 `first − (h+1)` 退，脚本里的自检当场就炸了** ——
这说明"算完再验一次兑现日"这条自检不是装饰，是必需的。
`newfactor_ic_isolated.py::_assert_isolated()` 把它固化成了运行时断言，算错就拒跑。

### 污染面（实测）

受污染的**信号日 6 个**：`2025-06-23 / 06-24 / 06-25 / 06-26 / 06-27 / 06-30`
（占 2018-01-02 ~ 2025-06-30 全部样本日的 **≈0.28%**）。

## 3. 冻结的判据与淘汰规则（S-03 的"冻结证据"部分）

今后任何"某组特征/某个配方更好"的申报，必须同时满足下面全部四条，否则不进提名：

1. **标签隔离**：筛选脚本的 `CUTOFF` 由交易日历算出，且**运行时断言**标签兑现日严格早于评价窗；
2. **多种子配对**：至少三粒互不重叠的基础种子，报**最差情形**（不是均值、更不是最好）；
3. **口径统一**：H2 一律按**信号季度归属**（见 §4），不用现金曲线行中点；
4. **证据不得事后改口径**：被证伪的候选**保留原结果**，只允许**追加标注**，不允许重算替换。

★ 判据 3 是本次新补的：同一张 `arms_summary.csv` 里"top1 后半程"（行中点法）与
"门槛 H2"（信号季度法）**窗口不同** —— 实例 V62 两列为 +9.25% vs +30.77%，差 21.5pp。
两个口径混在一张表里，读数就没有意义。

## 4. `arms_summary_fixed.py` 改了什么

原 `../20260921_new_factors/arms_summary.py:33-34`：

```python
eq = pd.read_csv(curve)['equity'].to_numpy()
H2 = eq[-1] / eq[len(eq) // 2] - 1
```

V63 的现金曲线 243 行、首 2025-07-02、末 2026-07-02 ⇒ `len//2 = 121`，除数是 **2025-12-26**，
分子还含 2026-07-01/02 两天（Q2 信号跨季执行 + 末尾清仓）。
而 REPORT 自己定义的口径是"**按发出交易指令的信号日归属**"，
`market_gate_research.py:73` 也是这么算的（`np.prod([1+q['net'] for q in quarters[2:]])-1`）。

本目录的版本改为与 REPORT 口径一致：**按信号季度归属，H2 = H1 末权益 → H2 末权益的连乘**，
并保留末端结算（跨季执行与末尾清仓顺延仍归入对应信号季度）。

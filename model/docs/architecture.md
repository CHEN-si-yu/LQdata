# 架构与运行

## 探索过程文件的新规则

用户于2026-10-30要求将有价值的探索结论整理进既有 docs 文档，今后不长期保留详细探索过程文件。原先有关永久保留探索归档、探针及原始明细的描述仅代表历史安排，遇到冲突以此规则为准。生产运行所需的文件及现存代码、测试的实际依赖须先核对和迁移，再清理；仅有文档的历史试验不能保证复现。

## 目录与文档纪律

`docs/` 固定维护[索引](README.md)列出的九个文件。规则归 `development.md`/`baseline.md`/本页，当前状态归 `STATUS.md`，结果归 `leaderboard.md` 与 `core_models.json`，过程与收尾归 `iterations.md`，经验归 `lessons.md`。同一结论不另建日期报告、总结副本或状态备份。

每个模型目录继续只保留 `run.py`、`model.py`、`analysis.py` 三个实现入口及 `model_train/`、`model_info/`、`model_pred/`、`model_logs/` 四类产物。所有实际文件仍须满足该版 `fixed_files()`；不能因目录叫 `model_info` 就随意加入未声明文件，也不能为文档整理修改训练配方或裁掉断点。

跨模型材料按轮次归档于 `experiments/_archive/`；最近完成轮为 `20261029_20261030/`，此前轮次为 `20261028_20261029/` 与 `20261024_20261025/`。归档不是模型或公共训练引擎，是否仍有授权任务以该轮会话状态为准。辅助脚本在 `scripts/`，原始设计/审计/机器状态在 `model_info/`，报表/图/账本在 `model_pred/`，运行修复与原件快照在 `model_logs/`，同模型复核在 `replicas/`。后续先确定研究单元及产物清单，不在 `experiments/` 顶层散建日期脚本和策略目录。

归档中的迁移清单（原始归档已清理）连接原路径与实际位置，记录原始指纹及路径引用修复。冻结 JSON 不回写；历史源码原件保存在清单指定的压缩快照。部分辅助/分析脚本的位置引用已经更新，其新源码指纹不能冒称旧冻结指纹。回放原冻结尝试时恢复原源码与历史路径，或另记清楚路径迁移；不能静默跳过验证。V263 的当前三组评估位置已在登记表同步，V287 新增复本仍取消、未训练。

## 基础模块

| 路径 | 职责 |
|---|---|
| `trainingdata/` | 共享只读数据：因子、标签、成交额、市场状态和价格 |
| `preparingdata.py` | 从上游落盘数据构建、更新和校验快照 |
| `releases/` | V322、V259、V282、V335 的实战四折权重、冻结发布清单和每日入口 |
| `experiments/` | 既有六个研究模型与 V253 起的新轮季度训练、评估 |
| `docs/` | 当前模型评估、数据合同和运行说明 |
| `tests/` | 生产清单选择、缺失产物报错，以及发布入口的列对齐、方向转换、融合与写入测试 |

各模型自包含，不导入其他模型的实现。相同配方的一组种子属于一个模型；单元编号只作标识，不能据其大小推断策略或质量。

## 训练快照

```text
trainingdata/
├── meta.json
├── factors/year=YYYY/data.parquet
├── target/year=YYYY/data.parquet
├── amount/year=YYYY/data.parquet
├── fac_sample/year=YYYY/data.parquet
├── market_factors/year=YYYY/data.parquet
├── prices/year=YYYY/data.parquet
├── .source_index.json
└── log/
```

`meta.json` 记录日期、股票轴、列名、方向、标准化语义和分区。股票块按 `trade_date, stock_code` 对齐；市场块按日期对齐。股票特征采用 `zscore_win1_99_v1` 语义，模型按自身规则处理缺失。价格块保存原始行情；复权和交易约束由回测实现处理。

`fac_sample`、索引与台账属于数据构建合同。`preparingdata.py` 默认读取上游 `conf/production.json` 的 `production` 对象，并从对应 Parquet 读取数据，不导入上游 Python 或状态。已退出生产的历史目录不会参与打包，生产对象缺少落盘年分区时直接报错。独立 `--source-data` 没有相邻 `conf/production.json` 时，才按全部落盘目录打包。列集、方向或股票轴变化会自动全量重建，以保持各年份一致。

生产清单与物理目录数量分别解释：上游仍保留 46 个已退出生产的股票因子文件，模型快照按当前生产清单排除这些列。当前生产清单为344个股票因子、50个市场因子和5个标签，共399项，10-28日更日期轴为2018-01-02～2026-10-28（2138日、2115只股票）。历史10-23归档是282/47/5共334项；同轮对照读取各自冻结归档，不静默改变既有权重输入合同。`cl_tail_cost_asym_5_v1` 已按用户指令永久删除，后续禁止使用；其注册、专用实现、年度源数据、状态及完整父秩缓存均已移除，本地快照按新清单重建。日期轴取入选股票产物主键并集，缺测仍保留 NaN。当前核对详情见 [数据状态](STATUS.md#数据)。

```bash
python -B preparingdata.py --check
python -B preparingdata.py --jobs 4 --progress bars
```

构建会更新快照；校验不写数据。`--check` 检查文件结构、日期轴、年度列签名、取值口径及当前生产清单中的股票、标签和市场列集，并提示股票因子源文件落后于全库末日的情况。`--features-from` 显式锁定的股票特征子集允许缺少其他在产列，但不能包含退出生产的列。源文件落后提示不等于本地对齐失败，缺格必须保留 NaN。需要指定输入、输出或列集时，使用 `--source-data`、`--out`、`--features-from`；具体参数以 `--help` 为准。

## 模型文件合同

每个模型有 `run.py`、`model.py`、`analysis.py` 三个实现脚本：分别负责调度、模型与训练、评估与报表。固定文件的真源是该模型的 `fixed_files()`；发布模型还按 `MX_LIVE` 区分模式。

| 路径 | 必要内容 |
|---|---|
| `model_train/<季度>/fold1..4/` | `best.pt`、`last.pt`、`complete.json`、`training_info.json`、`split.json`、训练曲线与预测数组 |
| `model_info/` | 研究模型的 `final_audit.json`、`two_strategy_validation.json`；发布模型的 `live_validation.json` |
| `model_pred/` | 研究模型的逐日分数、现金曲线和 `picks.md`；发布模型的 `live_report.md` |
| `model_logs/` | 与训练、评估对应的日志 |

`best.pt` 用于交付；`last.pt` 用于续训；`complete.json` 和 `training_info.json` 固定完成状态与输入合同。权重里的神经参数、ridge、特征列等组成一个完整交付，恢复时不能只取神经参数。

标准研究评估采用四季度×四折，共 16 折；本轮另加2026Q3四折单列检验，核心折文件增加验证预测、辅助绝对收益预测和市场风险模型，仍以各版fixed_files()为准；发布模型当前使用 2026Q4 的四折。各单元内部保留完整文件合同，不能单独裁掉断点或预测数组后仍声称可完整续训、审计。

## 运行

资源准入除CPU／GPU／内存，还须同时检查磁盘字节与inode余量。当前工作盘inode配额200000；新方向、复本、历史扩展和预检克隆应按预计文件数留足余量。10-30收尾已将119个完成临时探针目录的3139文件逐一SHA校验后压缩保留，见[清理收据](../../check/storage_cleanup_20261030/final_summary.json)与[恢复清单](../../check/storage_cleanup_20261030/completed_probe_evidence_manifest.json.gz)。复跑旧探针前先从该压缩包解到`/autodl-fs/data`，恢复原项目深度；解包不代表获准重新研究。

正式模型目录仍为完整实体文件树，全部权重／断点／预测与账本保留。13702个不可变完成文件的重复字节以原子硬链接共享；原生`save_torch`／`save_npy`用临时文件替换，未来写入必须保持该方式，不能原位修改共享文件。旧inode恢复清单描述当时状态，部分重复tar已移除，不能把其旧路径当作现存唯一原件；完整证据现由正式原文件及新的探针压缩包承接。无引用的本轮派生面板缓存已删除，按保留的输入和源码自动重建；生产必要缓存保留。

研究模型在自己的目录执行：

```bash
python -B run.py --jobs 4 --device cuda
python -B analysis.py --audit
```

旧发布实现的训练调用（现行实战包不再使用此入口重训）：

```bash
MX_LIVE=1 python -B run.py --jobs 4 --device cuda
MX_LIVE=1 python -B analysis.py --live
```

这些命令会训练或改写对应产物。同一版本完成完整季度与折再进入完整排名。CPU策略回测/审计可与下一版本GPU训练并行，按当前容器总资源预算协调。run.py只读共享面板，依据CPU配额、cgroup内存、可见GPU及滚动平均负载逐步增加并行折数，目标使瓶颈计算资源平均利用率超过80%，保留内存/显存余量。最多三个待训练研究方向与并行折数分别控制。

历史研究权重与评估绑定其登记的输入快照；当前共享快照不必与其一致。重训或重载审计前必须核对快照指纹和列集；不应只修改指纹来绕过校验。新配方采用独立产物目录。

最新完整输入归档见[10-28 清单](../input_snapshots/20261028_ec93f702e49f/manifest.json)，在本批模型结果前保存。旧10-27配方继续读取[原清单](../input_snapshots/20261028_2fcbed2d751d/manifest.json)，不被最新数据替代；[10-24 历史清单](../input_snapshots/20261024_d4c3dea169ea/manifest.json)在其当轮结果后保存，只证明保存时一致。归档和元数据指纹不证明上游历史因子的时点可得性。清单的 `replay_environment` 给出 `MX_DATA`、`MX_STOCK_LIST`、`MX_CALENDAR` 覆盖路径；复演使用独立模型产物目录，保留已审阅的分数和报告。

日常发布推演在根目录运行 `python -B releases/main.py`，只读取已有权重，不训练。入口按权重冻结列名、顺序、方向投影当前快照；新增列忽略，缺列或方向合同缺失即拒绝评分。四折分数相加，四模型在共同有效股票内按release_config.json冻结的截尾z分数等权融合。

## 派生面板缓存与两阶段训练

V258起可将当前快照派生的X与覆盖率数组存于`/dev/shm/quant-model-panel-<key>/`，只读mmap供各折共享。键包含元数据指纹、列序、标准化语义与源文件大小/时效，建立时逐块逐值对拍，原子写入清单；内存或共享内存不足则使用原载入路径，`MX_PANEL_CACHE=off`可关闭。它是源快照的派生缓存，不能修改指纹绕过校验。本次规范线程设置下，缓存/原面板推理误差0。

V260研究“严格选择模型＋测试前成熟历史最终重训”：额外保存`selector_best.pt`、`selector_market_risk.pt`、`selector_complete.json`，旧验证分数只由选择模型产生，最终交付用`best.pt`及`market_risk.pt`。两套训练截止与重载误差分别审计。`last.pt`保存固定岭回归前缀充分统计量，恢复交付重训时检查前缀及配方；最终模型不能回跑已见验证集并冒充样本外。确定性四折交付使用相同成熟区间时不算四个独立复本。

时间序列模型可进一步在独立spawn进程中创建一份CUDA输入张量，再通过CUDA IPC提供给从未在父进程初始化CUDA的训练子进程；CPU规范推理路径不变。当前仅在单GPU且有足够显存的容器启用，跨轴9个切片与双进程序列gather探针逐值一致。进程池退出前显式释放子进程的共享张量，再结束生产者，已用真实进程池探针验证无生命周期警告。缓存失效、不可用或预算不足时使用CPU批量搬运。

原生提升树仍使用三个脚本模板：树UBJ字节嵌入registered buffer，CPU重载时调整buffer长度并在内存创建原生预测器，无需额外模型文件；阶段断点保存当前及最优树前缀与库版本，最终重训冻结选择树数。选择损失和原生参数均写入配方，不能将CPU/GPU工作空间变化当成新的模型方向。

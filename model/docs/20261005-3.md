# HQTH × BEST 对照研究结论（2026-10-05）

> **一句话**：在**完全相同的数据**（我们 trainingdata：124 因子 / 2115 只池 / label_ret_1d）与**
> 完全相同的评估口径**（min_test 唯一构造，全部样本外）下，**公司实习项目的 MLP 配方全面胜过
> 我们 experiments 的最佳单元配方（V202 dual_leg_tradable）**——IC 2.1×、top500 2.5×、top5 3.0×；
> 其配方中的"**头部/容量导向**"要素（wpcc 头部加权损失 + val_wei 容量受限组合选轮）是首要嫌疑，
> 但未做消融，不能单独归因。公司自报数字与我们的公平复刻之间还差 ~2.2–2.5×，来自因子库规模
> （124 vs 1400）、股票池（~2115 vs ~5000）、数据源等**尚未拆分的资源段**。

## 一、实验设置（技术细节）

### 1.1 两条流水线

| | **HQTH**（公司配方 × 我们因子） | **BEST**（我们 experiments 配方） |
|---|---|---|
| 代码 | `model/HQTH/`：`hqth_data.py`（数据适配）→ `hqth_train.py`（以公司 `MLP.py` 为准）→ `hqth_min_test.py`（以公司 `min_test.ipynb` 为准） | `model/BEST/`：V202 单元三件套（`run.py`/`model.py`/`analysis.py`，逐字沿用 experiments 合同，仅改评价窗口） |
| 模型 | 4 层 MLP：124 因子→256→128→32→1（BN+Dropout 0.2/0.1，Kaiming） | 双分支 GRU（micro20 ⊕ fund53）+ 拼接秩头 + 绝对值岭回归（19 价 + 47 市情），内部百分位秩融合 |
| 损失 | `wpcc`：按**预测排名指数加权**的截面 Pearson（头部权重最大） | 双支路 WPCC（3/5/10d 标签）+ 技术支路岭回归 |
| 选轮 | `val_wei = 当日 top500 容量受限组合收益×100 + 0.7×IC`（λ=0.7） | 加权 raw-label RankIC（`tradable_topn` 判据） |
| 切分 | `all_train`（回看至 2021-01，4 年上限）+ `shuffle_split`（4 折 = 随机 25% 日期）+ 季前 10 天 purge | 每季度 4 折**连续块**、purge21、fold4 干净块；训练窗 = 快照全历史 |
| 训练跨度 | 每季一个 season，训练数据止于季度前 10 个交易日 | 每季度 4 折，训练数据均止于季度前（purge21） |
| 交付分 | **四折对该季度 test 打分相加**（每日先逐截 z-score） | 同（单元交付口径：四折打分直接相加） |
| 种子 | 3253（公司默认） | 35253（V202，**单复本**） |
| 规模 | 8 季度 × 4 折 = **32 折**（≈1 小时，8 路并行） | 8 季度 × 4 折 = **32 折**（24.5 分钟，8 路并行） |

### 1.2 评估口径（min_test 唯一构造，**不存在其他口径**）

对每个组合口径：读入各折对**对应季度**（全部样本外）的 test 打分 → 每日 z-score → 四折相加 →
按日期拼接八季度（2023-01-03 ~ 2024-12-31）→ 计算：

- **IC** = 日度截面 Pearson（score vs `label_ret_1d`×100）均值；**ICIR** = IC 均值/标准差（不年化）；
- **top_return** = 容量受限组合日收益均值（`topn` 只、名义资金 `money`、单票持仓 ≤ 当日 `amount`、无费用）；
- **stability** = top_return 均值/标准差。

三档组合：`top500/15亿`（公司原口径）、`top5/1000万`（小资金）、`top5/15亿`（大资金×小组合）。

> ★ **防重犯注意**：不要用 "season=2025q1 的四折全跨度产物" 来评估 2023–2024 —— 那样每个日期
> 对 4 个折叠中的 3 个是**训练日**（shuffle 下每日期恰属一折 holdout），IC 会被抬到 ~0.13
> 并误判为"复现了公司数字"。正确构造只有一个：**每季度一个 season、四折全部样本外、四折相加**。

## 二、结论（拆账版）

**公司的优势 = 配方段 × 资源段（两段相乘）：**

| 段 | 对比 | 倍数 | 状态 |
|---|---|---|---|
| **配方段** | 同数据：HQTH(0.0563) ÷ BEST(0.0267) | **2.1×**（IC）；top5/1000万 3.0× | ✅ 本实验已测 |
| **资源段** | 公司自报(0.1225~0.1431) ÷ HQTH(0.0563) | **2.2~2.5×** | ❌ 未拆分（因子 124 vs 1400 / 池 ~2115 vs ~5000 / 数据源；label1 期限仍是未知项） |

**要点：**
1. "公司效果远超"中，**约一半来自配方本身**（这是本实验钉死的）；另一半才轮到因子库/池子/数据，
   且**不能单独归因**（没有消融；label1 若是多日标签，两边 IC 不同尺）。
2. **头部/容量导向是配方段的头号嫌疑**：公司配方的两个核心部件——wpcc（头部加权损失）与
   val_wei（**15 亿/top500 容量受限组合**收益 + 0.7·IC 选轮）——都直接朝"头部 + 装得下资金"优化；
   且其优势在小资金 top5 上同样成立（0.674 vs 0.225）。
3. **"换 Top5 口径"对双方都有大增益，差距未缩小**：BEST top500→top5/1000万 ×4.9（验证了
   "我们为小组合/小资金特化"的直觉）；但公司配方 ×5.9，仍全面领先。
   ⇒ **引申出本阶段主线方向：大盘策略 → 小盘策略的迁移研究（见 §三 主线，含 L1–L5 实验设计与决策点）**。
4. **容量可行性差异**：15 亿下 BEST 的 top5 为负（小票装不下大资金、资金闲置被摊薄），
   公司配方仍正（0.168）——其头部票更"吃得下资金"，与容量感知训练方向一致。
5. **不可过度外推**：单窗口（2023–2024，含微盘崩盘逆风）、单复本、配方差异是**多因素捆绑**
   （模型/损失/选轮/切分/因子子集），尚无消融。

## 三、后续研究思路与方向（按优先级）

### ★ 主线方向：大盘策略 → 小盘策略的迁移研究（Large→Small）

**背景（本实验最重要的引申）**：公司配方的训练目标是"**大盘方向**"的——wpcc 头部加权损失 +
`val_wei = 15 亿/top500 **容量受限组合**收益×100 + 0.7·IC` 选轮，即明确朝"能装下大资金的头部"学。
但把它**直接套到小盘实战口径**（top5/1000 万）后，成绩反而全面超过我们原本就是小盘/可交易导向
的单元配方（0.674 vs 0.225）——**"用大盘目标训练出来的模型，在小盘实战回测里反而更好"这一命题
已初步成立**（单窗口 2023–2024、单复本）。由此引出本阶段的主线研究问题：

1. **是否需要、以及如何针对小盘策略对训练做特化？**
   我们单元的 `tradable_topn` 判据本来就是朴素的小盘/头部导向，却输给了大盘目标——说明"把小盘
   目标简单塞进训练/选轮"未必正确；特化的**正确形式**（损失加权形状？选轮口径？容量约束方向？
   特征侧重？）需要系统探索。
2. **特化能否在小盘实战口径上取得更好的收益？**
   还是"大盘目标"中的容量/流动性约束实际扮演了**正则与防过拟合**的角色（小盘噪声大、
   涨跌停/流动性陷阱多），贸然特化反而会破坏它？
3. **训练目标应锚定哪个口径最优？**
   从"大盘目标（top500/15 亿）"到"小盘目标（top5/小资金）"是一条连续谱系，最优锚点未知，
   不应默认采用任何一端。

**研究设计（全部复用现有 HQTH/BEST 管线；评估用 min_test 统一表达 + 小盘实战档）**：

| # | 实验 | 设计 | 回答什么问题 |
|---|---|---|---|
| L1 | **目标锚点扫描** | `val_wei` 的组合口径连续插值：top500/15亿 → top50/1亿 → top5/1000万 → top5/10万；同一模型族训练，看小盘口径评估下的得失曲线 | 最优锚点在哪 |
| L2 | **双向重训消融** | MLP 配方改小盘目标重训 vs 原大盘目标；V202 改大盘目标重训 vs 原 tradable_topn（即下方方向 A 的 A1/A2 延伸） | 目标错配的量化成本（两个方向） |
| L3 | **容量正则假说检验** | 三组对照：训练加显式流动性/容量约束项 vs 保持大盘目标 vs 都不加，在小盘实战档比较 | 大盘目标的增益是否来自"隐性流动性正则" |
| L4 | **执行层迁移** | 把小盘实战的真实约束（涨跌停、T+1、整手、费用、冲击）纳入评估（单元已有的现金账户口径），重估"训练目标该锚定哪个口径" | 交易摩擦如何改变锚点选择 |
| L5 | **窗口与外推** | L1–L4 的胜者搬回 2025–2026 窗（我们的主场）+ 多种子复本 | 不是 2023–2024 的窗口偶然 |

**交付与决策点（需要用户拍板）**：
- 小盘实战的**资金体量档**（10 万 / 100 万 / 1000 万？）——决定容量约束的松紧与 L1 的锚点范围；
- 是否允许把"**训练目标锚定口径**"作为正式方法论字段写进单元合同（改 `docs/architecture.md` 配置摘要）；
- L1 胜出的锚点若要进交付，仍须过**四道晋级门**（干净对照/多种子/跨季度/fold4 干净块）。

以下方向 A–D 为该主线的支撑工具与配套：

### 方向 A：配方消融五连（第一优先，各 ~25 分钟，复用现有管线）

| # | 实验 | 做法 | 决策含义 |
|---|---|---|---|
| A1 | **选轮消融（正）** | 把 V202/BEST 的 valid 判据从 `tradable_topn` 换成 `val_wei` 式（top500/15亿 组合收益×100+0.7·IC），其余一律不动 | 若 BEST 大幅提升 ⇒ **选轮（容量感知）是主因** |
| A2 | **选轮消融（反）** | 把 HQTH 的 `val_wei` 换成纯加权 RankIC，其余不动 | 若 HQTH 大掉 ⇒ 镜像验证 A1 |
| A3 | **损失消融** | HQTH 的 `wpcc` ↔ 均匀加权 Pearson；观察 top5/top500 谁先掉 | 分离"头部加权"贡献 |
| A4 | **因子集消融** | HQTH 只用 V202 的 92 列（去技术 19 列等）vs 全 124 | 分离"因子子集"贡献 |
| A5 | **架构消融** | 同损失同选轮下：MLP ↔ 双分支 GRU | 分离架构贡献 |

**决策树**：A1≈A2 生效 → 把容量感知目标引入我们单元的训练/选轮（见方向 B）；
  仅 A3 生效 → 改损失加权；A4/A5 显著 → 优先特征/架构，而非训练目标。

### 方向 B：把"容量感知"系统性地引入我们单元（若 A1/A2 成立）

1. **选轮判据改造**：`tradable_topn` → 混合判据（容量受限组合收益 + λ·RankIC）。
   ⚠️ 与我们的纪律冲突点：选轮与评估同折会失真，**必须在我们自己的干净块（fold4/4 块）上复核**，
   并过"四道晋级门"再谈采纳（干净对照/多种子/跨季度/fold4）。
2. **损失层**：头部加权 Pearson（wpcc）与我们现有双支路 WPCC 的差异排查（权重形状、指数底数）。
3. **特征层**：容量类特征是否已在用（`amount`/`amihud_daily_5`/`amount_ratio_20`）——
   检查 BEST 是否把"可容纳资金量"信息喂足。
4. **目标函数口径的哲学**：明确"训练目标对标的组合口径"（top5 可交易 vs top500 容量受限），
   作为单元合同的可选字段记录进 `docs/architecture.md` 的配置摘要。

### 方向 C：补全资源段（需要决策/上游协同）

1. **label1 期限确认**（最高性价比）：向公司/实习资料确认当年 label1 的期限与口径；
   若是多日标签，所有 IC 对比需换到我们对应期限的标签上（我们有 1/3/5/10/20d）。
2. **因子规模**：我们当前 124 因子 vs 公司 1400 —— 短期无法对齐；可先做"因子数量-IC"的
   边际实验（用我们已有因子的随机子集 × {30, 60, 124}）看我们内部是否还在"欠拟合因子数"区间。
3. **股票池**：我们的 2115 只冻结池（含幸存者偏差）vs 全市场 ~5000 —— 扩池涉及上游边界
   （见 `upstream-downstream-boundary`），列为**待用户决策**，不在本轮范围。

### 方向 D：稳健性与外推

1. **换窗口复核**：把 HQTH 与 BEST 的同尺对照搬到我们自己的评价窗（2025–2026）——
   HQTH 侧需把缓存扩到 2025-2026 并加 season=2025q1..2026q2；
   目的：排除"2023–2024 是 BEST 逆风窗"的窗口偏差。
2. **补复本**：BEST 目前单复本；按话术补到 4 复本并做复本波动（预计 4×25 分钟）。
3. **资金档扫描**：top5 的 money ∈ {100万, 1000万, 1亿, 5亿, 15亿} 扫描容量陡降点，
   量化我们模型"可承载资金上限"。

### 三、`trainingdata/log/ledger_YYYY-MM-DD.tsv`（用户要的台账）

一行一个数据文件（四块 × 九年 = 36 行）：`block / year / rows / cols / bytes / sha / mtime / action`，
前 4 行 `#` 注释带运行上下文。**一天一个文件，同日覆盖**（要的是"最新台账"不是运行流水）。

- `mtime` 取自文件本身 ⇒ **一眼看出今天动了哪几个**；
- `action` 由**调用方传本次运行的信息**。★ 有个坑：不能用 `meta["years"][y]["action"]` ——
  实测日常增量跑完 `years.2018.action` 仍写着 `'full'`（那是上午全量留下的旧值），照抄会误导；
- 键必须是 **`(块, 年)`** 不是只按年 —— 否则 `--amount-only` 会把 `amount` 盖到那一年的
  `factors`/`target` 行上，看着像它们也被重写了（**已实测踩到并修掉**）；
- 落点在 `main()` 而不是 `prepare()` —— 台账是**运行记录**，放 `prepare()` 里会让探针/程序化调用
  也写（字节对拍时一天要跑几十次）。

### 一、先量再砍：那 2000 行是什么

用 `ast` 逐函数统计（2049 行 / 67 个函数 / 1650 行在函数体）。**不是注水** ——

### 二、口径改动：增量窗口 22 → 28 天

用户：「增量更新最新 7 个交易日的数据（**冗余覆盖**的逻辑）」。
改成 `lookback = max(h) + 1 + REDUNDANT_DAYS(7)` = **28**（原 `+2`）。
`h + 1` 是硬下限（标签 `T` 用到 `open(T+1+h)`）；`+7` 是用户要的冗余覆盖。
★ 为什么**不**照字面实现"每个标签各自刷最新 7 个有效行"：跨多天没跑时会漏 —— 详见
模块 docstring 与 [DATA.md](DATA.md) §3。

### 五、顺手修的一个日跑误报

增量的"丢弃行"告警会**天天误报**：窗口外的行本来就该被丢弃（由 `keep` 提供），

### 六、★ 日常跑一次，抓出一个**天天会踩**的真 bug（已修）

用户要求「每天执行 `python preparingdata.py`」，于是真的跑了一次 —— 结果发现
**`meta.json` 里 `amount` / `fac_sample` 的记录被这次增量抹掉了**，而且是**两个独立的成因**：

1. `prepare()` 的 `meta` 是**从零重建**的字典，而这两块的记录是事后由 `_record_block`
   单独写进去的 ⇒ 整条被顶掉；
2. `build_year` **只产出 `factors`/`target`**，而 `prepare()` 用 `years_meta[str(y)] = info`
   **整年替换** ⇒ 该年 `files.amount` / `files.fac_sample` 的记录也没了。

两个都**不是本次重构引入的**（原代码同样如此），但后果实打实：
`ensure_block` 随后只补"文件陈旧/缺失"的块 —— 文件好好的，它**一声不吭**，
于是"这块数据是哪一版"的指纹**静默消失**（而 `_block_digest` 存在的全部理由就是回答这个）。
⇒ 已分别修掉（搬旧记录 / 合并 files），实测：跑完日常命令后两块记录**原样健在**，
指纹仍是 `79973f9cddb57c50` / `860cac8991198f88`。

★ 教训与 §11 那条同族：**"静默降级"比报错危险** —— 崩掉你会去修，没声了你以为它在工作。

### 二、★ 三个指纹逐位没变（实测，不是推理）

| 指纹 | 值 |
|:--|:--|
| `panel_digest` | `798ccb32214853a8` |

**为什么改名不动指纹**：`panel_digest()` 的哈希串是 `f"{年}:{行数}:{sha}"` ——
**块名只用来查 key，不进哈希**。所以「常量 + meta key 同步改」⇒ 指纹不变；
**只改一头会静默换掉锚点**（实测漏改得到 `d90b20cf37710f94`）。

⇒ 推论：`meta["columns"]["features"] / ["labels"]` **一个字都不能动**（直接进哈希），
**改 `labels` 的顺序也算变** —— 所以别顺手"整理列序"。

### 三、★ 抓到的两个真坑

1. **脚本自己的字节进上游指纹**。`_fingerprint()` 里有 `h.update(ROOT_SCRIPT.read_bytes())`

   "无新增"零 I/O 快路径随之失效，下次裸跑会误判成上游变了、去重算**当年最后 ~22 个交易日**。

   （15:33 上锁，`meta.frozen.on = True`）。★ 要不要把脚本字节从指纹里拿掉是**设计决定**，留给用户。

**而且变的不只是范围，数值本身也变了。** 拿 2026 年逐格比对（固定同样的 306 列）：

### 七之二、★ 端到端跑通又抓出一个真 bug（D5）

第一次跑 `analysis.py` 时报：

```
⚠️ 拿不到价格层（TypeError: read_price_frame() got an unexpected keyword argument 'years'）
   —— 无摩擦口径将**不套可买掩码**，那些数字不可用于结论
```

根因：`mx/prices.py:130` 一直按 `IO.read_price_frame(self.root, years=years)` 要数据，
而 `mx/panel_io.py::read_price_frame` **从来没有 `years` 这个参数**。

**后果比这个 TypeError 本身严重得多**：`analyze` 用 try/except 把它接住、**降级成
"不套可买掩码"的口径继续跑**（打了一行 ⚠️ 就过去了）。于是
**回测路径自诞生起就没真正跑通过**，而因为降级得很安静，谁也没发现 ——
上一轮的记录把"回测跑不了"归因成"P 块残缺"，其实 P 块补全了它也跑不了。

⇒ **教训（值得记进 [LESSONS.md](LESSONS.md) §11 坑清单）：`except` 兜底必须同时兜住"功能没了"这件事。**
一个把致命错误降级成警告的 `try/except`，比直接崩掉危险得多 —— 崩掉你会去修，
降级了你会以为它在工作。

**修法**：给 `read_price_frame` 补上 `years` 参数并透传给 `read_frame`（一行）。
已修 `V16/mx/panel_io.py`（权威副本）。★ `best/mx/panel_io.py` **有同样的 bug，本轮没动**
（用户裁定 V16 之前的一律不管）—— 下次要用 `best` 的回测时，把这一行照抄过去即可。

## 2026-09-19 · 单元自包含化（上一轮重构）

**问题**：单元只有约 180 行声明式配方，靠 `ROOT = parents[1]` 把模块根塞进 `sys.path`
去 `import mx` —— **引擎在单元外面**，所以单元无法独立拷贝出去。

**做法（五根支柱）**：

| 支柱 | 内容 |
|:--|:--|
| 一 · 引擎随单元走 | `mx/` 与 `main.py` 复制进单元目录。`ROOT = mx/..` 这条规则让"引擎复制到哪，哪里就是根"，所以单元代码一行不用改 |
| 二 · 构建期/运行期分层 | `preparingdata.py` + `mx/prepared.py` + `mx/upstream.py` = 构建期（要上游，不交付）；单元 + 自带引擎 + `trainingdata/` = 运行期（自包含，交付） |
| 三 · 价格层快照化 | 新增 `trainingdata/P` 块。★ 存**原料**不存算好的复权价 —— 上游 `hfq_X = ffill(X) × ffill(adj_factor)` 的 `ffill` 效果取决于作用窗口，烘进数据会让消费端换窗口后首行对不上 |
| 四 · 三层防分叉 | ① `load_unit` 硬闸门（从模块根跑自包含单元 → 拒绝）② `unit_names` 列表过滤 ③ 各单元 README 写明"改引擎请改模块根那份" |
| 五 · 位移共享 | 数据根三候选解析（`$MX_DATA` > `<单元>/trainingdata` > `<单元>/../trainingdata`），**判据是 `meta.json` 存在而不是目录存在** |

**接缝表**（`fea` 的全部引用点）—— 这张表是以后要重新 vendor 时的地图：

| 位置 | 原状 | 现况 | 为什么必须改 |
|:--|:--|:--|:--|
| `mx/data.py:31` | `from . import prepared, store` | → `panel_io` | 只用 8 个 I/O 符号，却拖上整个 `fea` |
| `mx/unit.py:68` | `from . import prepared` | → `panel_io` | `train.sh` 每次都要调它算并发 |
| `mx/unit.py:338` | `upstream.fingerprint(cfg)` | → 从快照 meta 读 | 快照里本来就有，而且**读快照更准**：那是"建快照时的上游" |

### RD12 · 打板策略（涨停板买入）—— 口径由 Agent 定（2026-09-22）

**定义**：在**涨停价**买入当日**封住涨停**的主板股票，赌次日及之后的溢价。

#### ★★ 与现有执行口径的直接冲突（本次最重要的一条）

`SPEC.md` §7 现行写着：「开盘价触及**按 `pre_close` 算的 10% 主板限价**即**保守拒单**，停牌拒单；
**不用 T+1 全天 high/low 去决定"开盘买不买得进"**」——
即现有引擎**系统性拒绝涨停价位的成交**，而打板**买的正是这个价位**。

⇒ **打板不可能复用 `evaluation_core` 现有的入场 / 拒单路径**，必须**另写一套执行口径**；
且**两套口径的收益不可横比**。旧口径（开盘限价拒单）继续服务 RD11 与全部历史版本。

#### 打板执行口径（预登记）

| 项 | 规则 |
|:--|:--|
| 涨停价 | `zt(T) = round(pre_close(T) × 1.10, 2)`，主板 10%；`pre_close` 取自 `prices` 块**逐日算**；**不依赖 `pct_chg`**（避免与复权口径打架） |
| 触板 | `high(T) ≥ zt(T)` |
| 封板近似 | `close(T) == zt(T)` |
| 一字板 | `low(T) == high(T) == zt(T)` ⇒ 全天无成交，**按打不进剔除** |
| **入场** | T 日以 `zt(T)` 成交（假设封板时打进） |
| **出场** | 默认 **T+1 开盘**（隔日打板）；另做 T+1 收盘 / 持 2、3、5 日对照 |
| 选股 | 模型打分排序 TopN ∩ {T 封板 ∩ 非一字板} |
| ★★ **信号时点** | **只能用 T−1 收盘为止的信息**。打板要在 **T 日盘中**下单，而现有 `score` 是「**T 日收盘后**」算出来的 ⇒ 必须用**错位口径**：T−1 收盘出分 → T 日盘中执行 |
| 费用 | 同现有：佣金万 2.5（最低 5）+ 过户万 0.1 + 卖出印花万 5 + 单边滑点 3bp |
| 容量 | 单笔 ≤ T 日该股成交额 1%（沿用）；★ **封单规模无法从快照获取**，必须报「**满额成交上限**」 |

★★ **信号时点这一条最容易写错，而且写错了不报错、只让收益虚高** —— 直接套用现有 `score`
等于用「T 日收盘（**含 T 日涨停这个事实本身**）」去预测「T 日盘中的涨停买入」，
是 `R3`（掩码必须对齐**成交日**而非信号日）在打板方向的翻版。

#### 必须先声明的偏差（不写清就没法读）

1. `prices` 块是**日线** ⇒ **无法知道封板时点**、**无法判断盘中是否开过板** ⇒ "封板时打进"是**乐观假设**
2. 真实打板要**排队**，封单大时打不进 ⇒ 必须报 **0% / 50% / 100%** 三档**成交率敏感性**
3. 一字板剔除是**保守**方向，但反向偏差同样存在（排队靠前能打进一字板）
4. **涨停价比开盘价贵** ⇒ 打板的入场成本**系统性高于** RD11 的 T+1 开盘买入，溢价先被这部分吃掉
5. 综合 1–4：本口径产出的是**上限收益**，**不是**可实现收益

#### 已有线索（是线索，不是结论）

- `LESSONS.md` §9：模型 top1 落在"买不到"的格子是基准的 **42×**、落在「T 日收盘涨停」是 **17×**
  ⇒ **模型本身已经在往涨停票上集中**。打板方向等于把这个倾向从"要被掩码剔除的污染"改成"被显式建模的目标"。
- `LESSONS.md` **U2**：T 日收盘涨停可用 `consecutive_limit_up` 当日截面 **rank ≥ 0.98** 识别
  （精确率 99.6% / 召回 91.4%、AUC 0.988）⇒ 有**两条独立**的涨停判定路径（`pre_close×1.1` 与 `rank≥0.98`）**可以互相对拍**，不必只信一条。

#### 判据

沿用 `S-03` §3 四条：标签隔离（运行时断言兑现日严格早于评价窗）·
**至少三粒互不重叠种子、报最差情形** · H2 按**信号季度归属** · 证据只加标注不改口径。

### ★★★ 先记住这条方法论（本轮最贵的一课）

**两折的差值不构成结论。** 本库的**折间跨度就有 ±0.03~0.09**（同引擎、同窗、同种子、
只换验证窗位置与模型种子），任何小于它的"改动前后差异"都必须等**四折跑齐**再说。
本轮 V5 就是这么翻的车：折 1/2 时读数像"明确有效"（10d +0.032→+0.070），

### ★ 研究方向 RD1 · 停牌样本：模型输入端删掉那一行（2026-09-20 立案）

**现状（实测，样本 = 601198.SH 停牌 20 天）**：停牌日那一行**不会被剔除**。`Panel.mask()` 只筛覆盖率
（`coverage ≥ 0.2`），而停牌日实测覆盖率中位 **0.61**（最低 0.45）—— 远高于门槛，于是停牌票照常进
前向计算、照常输出分数，输入张量形状**仍是 `(2115, 337)`**（不是 `2114`）。
它带进来的向量是「约 60% 真值 + 40% 被填成中性 0」，而价格类因子是在**前填的平线**上重算出来的伪值
（实测 `adx_14` 的 rank 冲到 **0.96**、`aroon_down_25` **0.97**，在截面上排到最极端）；
标签侧同样是伪的（`label_ret_5d` 在停牌中段恰为 0 —— 前填价之比恒等 1）。
实测停牌日样本 **98% 以上进训练集**（2024: 401/408、2025: 589/597、2026: 324/346）。
回测侧不受影响（`Prices.entry` 拒单 + `amount=NaN`），**所以问题只在模型侧**。

**提议**：模型输入端把停牌那一行删掉 —— 让"不可交易的票不参与打分"，与回测拒单口径对齐。

**★ 动手前必须知道的前置证据（`LESSONS.md` §10 死胡同详录）**：2026-09-18 本模块测过**几乎同一件事** ——
把「T 日停牌 / T 日收盘涨停」的行从**训练/验证样本**里切掉（测试集不动）。
**V8 的同折同种子干净对照显示：方向一致为负 ⇒ 在长期限上明确有害**
（Δ：1d **+0.021**、3d −0.006、5d −0.010、10d −0.014、20d **−0.018**；V5/LightGBM 那轮 Δ 全在折间跨度内 = 未观察到效应）。
机制推测：**训练时看不见 ⇒ 模型对这批票的打分变成"没学过的外推值"，而测试集是全截面的，
它们照样被打分、照样可能排到前面** ⇒ "训练时看不见、打分时乱给分"，比让它看着学更糟。

**但那条死胡同自己留了一条活路，正是 RD1**：「要在训练侧剔，就**必须在打分侧也剔**」——
本提案（删输入行）在效果上就是**两侧都剔**，所以它是**未测过的活路**，不是重试死胡同。

⚠️ 附带一条同节原文的警告：**执行层的 `Prices.entry` 已经在用 T+1 的「真实」一字板状态过滤候选**
（比"T 日收盘涨停"这个代理**信息更准**），所以"打分侧再剔一次"的增量价值可能很小 ——
**真要做得先算清楚：它比 `Prices.entry` 多拦了什么？**
换句话说，RD1 的价值不在"拦住买不进的票"（回测已经拦了），而在**改变模型学到什么**
（训练样本集 + 当天批统计）—— 这也正是上面 V8 那次"有害"的成因（只剔训练侧、不剔打分侧，制造了外推）。

**动手前四条**（缺一条就会得出错误结论）：

1. **删「行」影响的是「那一整天」、不只是那一只**：`PredictModel` 有 `BatchNorm1d`，而每个日截面在
   `train_fold` 里是**独立一次 forward**（一个 batch = 4 个日截面，但不是拼成一个张量），
   所以训练模式下归一化统计量按**当天那 ~2110 只股票**算 —— 删掉一只会改变当天**所有股票**的归一化，
   但**不影响同一 batch 里另外 3 天**（4 天不共享批统计）。推理用滑动统计量、各样本独立，
   所以推理侧只需改 mask 即可。
2. **WPCC 是截面 rank 加权损失**：删行会改变当日截面 ⇒ loss 的权重分布跟着变，影响同样外溢。
3. **判据要选**：用 `prices.entry`（开盘可买）还是 `traded`（当日有成交）？前者更贴回测口径，但会把
   "开盘涨停买不进"的正常票一起删掉（实测 2025-11-19 一天就有 7 只）—— 要区分「停牌」与「开盘涨停」
   就得接上游 `stock_suspension` 表（**该表从未被任何因子读过**，停牌目前只靠"缺行"隐式表达）。
4. **产物口径会变**：删行 ⇒ `ensemble/year=*/*.parquet` 里那些票没有 value 也没有 rank，而现在是满格产物。
   另：**改输入必须重训 16 折**（约 25 分钟训练 + 评价）。评估时注意差异主要来自「它对**别的**股票的
   影响」（BatchNorm 批统计 + WPCC 截面），而不是它自己的分数 —— 需要一个能分离这两种效应的对照实验。

**更小的替代方案**：① 不动行数，给停牌行加一个**显式停牌标记特征**让模型自己学；
② 在 `mask()` 里加"停牌日不采样"（停牌期不进训练，但仍参与推理打分）。

**立案时的取证记录**（可复现）：上游缺失数据的口径见 [SPEC.md](SPEC.md) §3（`fea/context.py` 的
`px`/`hfq`/`ret`/`ret_clean`/`traded` 五套语义：流量类 NaN、价格类**前填**、`ret` 停牌日恰为 **0**）；
模型侧取数与 mask 见 `V16/model.py` 的 `Panel` / `predict` / `train_fold`。

#### 边界规则：只有「test 窗那条」是硬约束

**判据（用户 2026-09-20）**：只要不是**原则上的数据泄露 / 透视未来数据**，都可接受 ——
切分口径最多让训练过程过拟合，而这**会被 test 集惩罚**，所以不需要固定限制死。
按这条判据过筛，五个方案里只有**两种重叠**需要区分：

| 重叠 | 后果 | 定性 |
|:--|:--|:--|
| **train ↔ valid** | 验证指标偏乐观 ⇒ 早停/选轮不可信 ⇒ 模型选得差 | ✅ **可接受**（会被 test 惩罚）⇒ **可自由实验，包括完全不隔离** |
| **train / valid → test** | **测量工具本身被污染** ⇒ "被 test 惩罚"的机制失效，版本比较失去意义 | ❌ **唯一的硬约束**，必须隔离 |

落到具体做法：

1. **train 与 valid 之间要不要留隔离带 —— 是选择，不是必须**。B / E 里两者紧贴 ⇒ 训练日 `X−1` 的
   5 日标签覆盖到 `X+5`（伸进 valid 池）⇒ 验证指标偏乐观。但这**只影响早停质量**，实验照做，
   代价看 test 窗数字即可。★ **值得专门设一组「有隔离 vs 无隔离」来量化它到底值多少。**
2. **`delta`（守 test 边界）必须以「测试窗第一个交易日」为基准、按【交易日】算** ← **硬要求**。
   实测反例：26Q1 测试窗首日 `2026-01-05`，若按 `2025-12-31 − 6 日历天 = 2025-12-25`，
   该日 T+6 = `2026-01-06` **落在测试窗内**（跨元旦假期使日历天 ≠ 交易日）⇒ 直接透视 test。
3. **`delta` 按实际用到的标签的 `max(h)+1` 取** ← **硬要求**。现在只训 `label_ret_5d`（h=5 ⇒ 6），
   但数据里有 1d/3d/5d/10d/20d 五个标签；若启用 20d 需 ≥ **21** 个交易日
   （参考 `preparingdata.py` 用 `max(h)+1+7 = 28`）。★ 注意 `delta` 也属于"隔离带长度"，
   但它守的是 test 边界 ⇒ **只能加长、不能短于 `h+1`**。

#### ★ 待研究的维度（**不止"选哪个方案"** —— 用户 2026-09-20 追加：验证集长度这类也要研究）

上面五个方案的差别其实落在 **4 个可独立调的旋钮**上，每个都应该单独做实验：

| 旋钮 | 各方案现状 | 权衡 |
|:--|:--|:--|
| **① 单折验证集长度** | **30**（`tmp/model.py`：`VALID_DAYS=120` 交易日 ÷ 4）· **61 / 91**（用户提的 365 天，日历/交易日两种解释）· **~120**（`model2.py` 分支2 与 E 的 180 日历天块）· **446~492**（V16 现行） | ★ **跨度 16 倍**。长了早停决策稳，但吃掉训练数据；短了训练数据多、验证贴测试窗，但"选第几轮"的噪声大。**没有任何一个是被验证过的** |
| **② 验证集位置** | 紧邻测试窗（B/E）↔ 轮换覆盖全历史（A） | 贴测试窗 ⇒ 分布最接近部署；离得远 ⇒ 早停依据与测试集分布脱节（A 的验证块最早离测试窗 7.5 年） |
| **③ 验证集形状** | 连续块（A/D/E）↔ 尾部池内随机散点（B/C） | 连续块对齐"一段市场状态"；随机散点对"多种状态的平均"，且四折并集 = 整个池 |
| **④ purge 冗余量** | V16 用 `h+1`（=6 确定性最小）；参考 `preparingdata.py` 用 `max(h)+1+**7**`（=28，留冗余） | 隔离带越长越安全，但越浪费数据。这个 **"+7 冗余"到底该不该有、该多大，没测过** |

补充两个可一并量化的点：

- **折间关系**：四折的验证集是"不相交的 1/4"（B/D/E）还是"整段轮换"（A）—— 决定折间差异该怎么解读
  （见上文 ★ 若选 B 的说明）。
- **验证集长度 → 早停轮数波动**：可直接测「同一份训练数据、4 折选出的最佳轮数标准差」，
  作为"验证集多长才够"的定量依据。这是个**便宜且不依赖测试集**的实验，建议先做。

#### 实验怎么做（机器空闲时）

- **控制变量**：同配方、同种子、同测试窗，**只换切分口径**；比测试集上的 5d RankIC / Σtop1 / 现金净收益，
  外加四折离散度。
- ⚠️ **必须分离「数据量效应」与「切分效应」**：A 与 B/E 的训练交易日数本来就不同（1446 vs 1570/1692），
  直接比会混淆。需要一个「训练量对齐、只有验证集位置不同」的对照组。
- **量化早停噪声**：B/E 的单折验证只有 61~91 天 vs A 的 478 天 ⇒ 可测「4 折选出的最佳轮数的波动」。
- **务必同时报验证集与测试集指标**：A 的验证集离测试窗 8 年远，完全可能出现「验证选得好、测试并不好」——
  这本身就是最有价值的结论。

### ★ 研究方向 RD3 · `val_wei` 的系数与构成（模型选择信号）（2026-09-20 立案，待实验）

用户 2026-09-20：**公式的形式可以，但相关的系数也需要探索和尝试。**

**现状**：`V16/model.py::validation()` 里

    val_wei = 100 × (可执行 top5 的 5d 标签收益均值)  +  0.7 × (Pearson IC)

实测（全 16 折的 `history.json`）：**收益项占 `val_wei` 的中位 93.1%**（区间 71%~135%）——
也就是说 `0.7 × IC` 实质只是个次要项，早停/选轮**几乎完全由"可执行 top5 的 5 日收益"决定**。

**为什么可疑**：`100` 这个放大系数是从参考脚本继承的（原脚本乘的是"15 亿元容量代理"）。
V16 把收益代理换成了 top5 等权 5 日标签均值（量级 ~0.01），**但系数没有跟着重标定**；
而 IC 项（0.7 × 0.11 ≈ 0.077）只有收益项（≈1.0）的 **7%**。若本意是两项均衡，权重要重调。

**可试的方向**：

| # | 方向 | 要点 |
|--:|:--|:--|
| a | **系数重标定** | 两项各自按**验证窗内的标准差**或 rank 归一后再加权 ⇒ 权重才有可解释的"相对重要性" |
| b | **去掉 IC 项**（0.7 → 0） | 检验"只看收益"够不够 —— 现在实质上已经是这样，可作对照确认 |
| c | **只用 IC**（100 → 0） | IC 是**日间平均的截面相关**，比"5 日收益的日间均值"稳定得多，可能让早停更稳 |
| d | **改用 `RankIC`** | 现在只被记录、不参与判据；rank 口径对极端值更稳健 |
| e | **收益代理的口径** | topN 的 N（现 5）、分母是否恒为 N、是否改成**超额收益**（减 universe）、horizon 用 1d 还是 5d |
| f | **多目标** | 收益 + IC + 折间稳定性 的组合，而不是两项线性相加 |

★ **方向 e（收益代理的期限）有个已实测的硬约束** —— `LESSONS.md` §10 的修正条：
**成本是决定性的**。一次往返约 **0.15%** ⇒ **持有 1 天的策略一年要付 ~35% 的成本，持有 10~20 天降到 1/10~1/20**。
本模块据此**推翻过**"长周期标签无用"的旧结论（那次错在纯 IC 视角、没算换手成本）。
⇒ 把 `val_wei` 的收益代理在 1d / 5d 之间调时，**必须同时看成本**，否则会重复那个错误。
这也直接连着主判据：**隔日换手 = 持有 1 天 = 成本最重的那一端**，而现在的 `val_wei` 用的是 5 日 ——
两边口径本来就不一致（用户 2026-09-20 指出：训练与交易策略是耦合的）。

**★ 动它之前必须知道的两件事**：

1. **改系数不会改 `run_id`** —— `100`/`.7` 是**硬编码在 `validation()` 里**的（`provenance()` 只哈希
   `recipe` + 数据；而 `recipe['valid_metric']` 只是一句**代码从不读**的说明字符串）。
   已实测：配方一字未动 ⇒ run_id 不变 ⇒ **已有 16 折会被判"指纹一致"而静默跳过**，
   产物停留在旧语义、代码却已经变了。⇒ **改系数时必须同时改 `recipe['valid_metric']` 字符串**
   （强制重训）**或先归档旧产物**。
   （这是**去掉源码字节哈希之后的副作用**：代码层面的改动不再自动触发失效，只能靠这条手动纪律。）
2. **`val_wei` 是「模型选择信号」，不是评价口径** —— 它只用 valid 窗数据、不碰 test 窗，
   所以**不违反"不许透视 test"那条硬约束**。但它**正是 RD2 所有实验的因变量**
   （切分实验测的就是"用 `val_wei` 选出的模型在 test 上表现如何"）⇒ **RD2 与 RD3 有耦合**：
   建议**先固定一个再扫另一个**，否则分不清是切分变了还是选择信号变了。

**★ 一个能把扫描成本降到几乎为零的做法（建议先做）**：
现在每折只落盘 `best.pt` / `last.pt`，**每轮的验证预测没有存** ⇒ 想换系数就得整折重训。
若在训练时把**每轮的逐日验证预测** dump 下来（每个 epoch ≈ 4 MB/折，16 折合计约 0.6 GB），
之后**所有系数组合都能离线重算"最佳轮是第几轮"**，不必重训 —— 一次性投入，换来整个系数网格的自由扫描。

### ★ 研究方向 RD4 · 逐季度因子筛选（每季度进模型的因子可以不同）（2026-09-20 立案，待实验）

### ★ 研究方向 RD5 · 时空耦合 / 图卷积（固定 `Code_num` 是前提）（2026-09-20 立案，待实验）

用户 2026-09-20：**「如果不考虑删除停牌股票，那么 `Code_num` 就是固定的，可以尝试时空耦合、图卷积方向的网络结构。
如果是考虑停牌删除股票，那么需要固定 `Code_num`，建议用 0 直接填充 NAN。」**

#### 前提（已核对代码，成立）

- `Panel.X` 的形状是 `(T 交易日, C 股票, F 特征)`，`C = 2115` 来自 `meta.axis.codes` —— 是**冻结池**、
  **不随日期变**（`model.py::axis()`）。⇒ **只要不删停牌行，天然就满足"固定节点集"这个图卷积的前提。**
- `X` 的预处理是 `(nan_to_num(x, nan=.5) − .5) × 2`：上游已是当日截面 rank∈[0,1]，
  缺失填 0.5 后中心化 ⇒ **缺失值 = 0 = 当日中位数 = 中性**。所以用户说的「用 0 填」在现有口径下
  **数值上正好落在中性点**，不会引入方向性偏移。

#### 为什么图卷积必须要固定 `Code_num`

图算子（GCN/GAT）要在**固定节点集**上定义邻接矩阵 `A ∈ R^{C×C}`，每层传播是 `A·X`；
时空耦合（ST-GCN / 时空 Transformer 一类）还要求**每个时间步的图结构一致**，才能沿时间维共享权重。
如果删停牌导致 C 逐日变化 ⇒ `A` 每天重建、**同一只票在不同日期拿到不同的列索引** ⇒ 权重无法复用、
时序维也做不了。这就是"固定 `Code_num`"的硬理由。

#### 两个分支

| 分支 | 做法 | 代价 / 风险 |
|:--|:--|:--|
| **A. 不删停牌（现状）** | `X` 已经是固定 `(T, 2115, F)`，**直接可上** | ★ **停牌日的伪值会被图传播扩散给邻居** —— 比 MLP 严重得多：MLP 里停牌票只影响自己那一行，图卷积会把它（约 60% 真值 + 40% 中性、价格类还是前填平线上的伪值）**传给它所有的图邻居**。所以 RD1 的结论在这里被放大 |
| **B. 删但保形** | 被删的票**整行填 0**（而不是从张量里真删），`C` 保持 2115、索引稳定 | ⚠️「整行 0」的节点是**全中性**，但它**仍会参与 `A·X` 的传播与 `BatchNorm` 的批统计**。⇒ 必须**显式排除**：要么给图算子一个节点掩码（`A` 的对应行/列置 0、或度矩阵里剔除），要么在传播后按掩码丢弃。**光填 0 不够。** |

★ **「用 0 填 NAN」有两种读法**，落地前要定清：
- ① 把**被删股票的整行**填 0（保形状）—— 上面 B 分支的做法；
- ② 把**特征缺失值**从现在的 `0.5` 改成 `0`（即改预处理口径）。
两者数值上都落在中性点，但语义不同（整行中性 vs 单格中性），而且 ① 还多一个"节点仍参与传播"的问题。

#### ★ 图的构造：价量算协方差/相关（用户 2026-09-20 追加）

用户：「图的来源可以尝试用**成交量**或者**收益**，计算**协方差**等方式，但都需要注意**时间范围不能泄露**。」

**候选来源**（都是"用价量算一个 `C×C` 的关系矩阵当 `A`"这一族）：

| 来源 | 具体做法 | 注意 |
|:--|:--|:--|
| **收益** | 过去 `W` 日的日收益 → 相关 / 协方差矩阵 | 最常用；收益为 0 的停牌日会稀释相关（同 RD1 的口径问题） |
| **成交量** | `vol` 或 `amount` 的相关 / 协方差（量能同步性） | ★ 停牌日**流量类是 NaN**（上游口径，见 [SPEC.md](SPEC.md) §3 `fea/context.py`）⇒ 窗口里遇到停牌要跳过或填中性，不能当 0 成交量 |
| **量价组合** | 收益相关 × 量能相关（逐元素相乘 / 加权） | 两个矩阵各自的窗口与归一化要分别处理 |
| **行业 / 板块** | 静态分组矩阵 | ⚠️ **必须先做 PIT 核查** —— 见下 |
| **全样本相关矩阵** | —— | ❌ **禁止**（见下） |

★ **`协方差` 与 `相关` 不是一回事**：协方差受量纲与波动率影响，直接当 `A` 会让**高波动票的边权整体压过别人**
（等于按波动率加权传播）。通常要对协方差做**行归一化**（或直接用相关矩阵 = 标准化后的协方差），
这一步要在实验里明确写清是哪种。

#### ★★ 时间范围：本方向最容易踩的泄露，两条硬规则

**规则一：`A` 必须逐样本日滚动构造，右端就是样本日本身 —— `A_t` 只用 `[t−W, t]`。**

| 做法 | 判定 |
|:--|:--|
| ✅ `A_t` 用 `[t−W, t]` 逐日算（`A` 逐日变，或按季度/月刷新但刷新点 ≤ 该样本日） | **安全** —— 训练日 `t < test 首日`，窗口右端自然碰不到 test 窗 |
| ❌ **算一个 `A` 给所有天用**（例如"用最后 60 天算一次相关矩阵"），而那个窗口的右端落在 test 窗内 | **透视 test** —— 训练时就用到了 test 期的收益/成交量。**这不是"会被 test 惩罚"那类，是直接污染** |
| ❌ **全样本**相关矩阵 | 同上，`SPEC.md` 铁律二（一切统计量只用当日截面） |

**规则二：窗口长度 `W` 要避开标签 horizon。** 标签 `T` 用到 `open(T+1+h)`，所以构造 `A_t` 时**不要**让窗口
跨过"样本日 + h"这条线；按 RD2 的口径，凡是要与标签对齐的窗口都用**交易日**算，不用日历天。

**规则三（二阶，可接受但要写明）：** 训练日 `t` 的窗口 `[t−W, t]` 若跨进了**验证块**，则训练样本的图
用到了验证期的价量 ⇒ 属 RD2 说的 train↔valid 那类"会被 test 惩罚"的效应，**可接受**但要在实验记录里标明。

**行业 / 供应链类静态图的 PIT 核查**：★ **上游有"回填改写历史"的前科** —— `stock_daily.stock_name`
被厂商**整段历史**改写成当前名（见 featureengineering/README.md）。行业表若同样被回填 ⇒
**用今天的行业分类去解释两年前的关系 = 透视**。用之前必须先查：这张表的历史值是不是"当时就知道的"，
有没有事后补录/修订。

#### 成本与约束
